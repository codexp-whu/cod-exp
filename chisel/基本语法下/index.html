    基本语法（下）：Bundle、Vec 与 Module¶

    这一章介绍 Bundle、Vec 和 Module，分别用于组织相关信号、表示同类硬件数组和建立模块层次。

    Bundle¶

    流水线级之间通常要同时传递多个信号。IF 级交给 ID 级的有 valid、PC 和指令；ID 级交给 EX 级时，还会多出操作数、立即数、目的寄存器和控制信号。

    每根线都单独声明时，增加或删除字段容易漏改某处连接。Bundle 可以把这些信号组织成一个整体。

    定义流水线数据¶

    下面的 Bundle 表示 IF/ID 级间的一笔数据：

    class IF2ID extends Bundle {
  val valid = Bool()
  val pc = UInt(32.W)
  val inst = UInt(32.W)
}

    new IF2ID 只给出了字段结构。把它交给 Wire 或 Reg 后，才得到实际硬件：

    val if2idNext = Wire(new IF2ID)
val if2id = RegInit(0.U.asTypeOf(new IF2ID))

    给组合输入填字段，再整包写入流水线寄存器：

    if2idNext.valid := fetchValid
if2idNext.pc := fetchPC
if2idNext.inst := fetchInst

when(!stall) {
  if2id := if2idNext
}

    生成的 RTL 中仍然有各字段对应的寄存器和连接。Bundle 改变的是代码组织方式，不会减少这些硬件信号。

    用 valid 表示气泡¶

    插入气泡时，关键动作是把 valid 置为假：

    val bubble = WireDefault(0.U.asTypeOf(new IF2ID))
bubble.valid := false.B

    后连接会覆盖前面的整包零值。后续逻辑应保证 valid 为假时不产生寄存器写入、存储器写入等副作用。

    仅把指令字段写成 NOP 编码，不能保证其他控制信号同时失效。显式 valid 可以统一控制暂停、冲刷和外部副作用。

    Bundle 可以嵌套¶

    当一组控制信号会在多个流水线级中重复出现，可以再定义一个小 Bundle：

    class DecodeControl extends Bundle {
  val regWrite = Bool()
  val memRead = Bool()
  val memWrite = Bool()
  val aluOp = UInt(4.W)
}

    然后把它放进 ID/EX 数据：

    class ID2EX extends Bundle {
  val valid = Bool()
  val pc = UInt(32.W)
  val rd = UInt(5.W)
  val operandA = UInt(32.W)
  val operandB = UInt(32.W)
  val ctrl = new DecodeControl
}

    访问嵌套字段仍然使用点号：

    id2exNext.ctrl.regWrite := decoder.io.ctrl.regWrite
id2exNext.ctrl.aluOp := decoder.io.ctrl.aluOp

    结构和方向兼容时，也可以整包连接：

    id2exNext.ctrl := decoder.io.ctrl

    嵌套层次不宜过深。控制信号、数据通路信号属于同一组时可以嵌套；关系不紧密的字段仍应分开组织。

    Vec¶

    Bundle 的字段有不同名字和含义，Vec 的元素则具有相同类型，通过下标访问。

    先分清 Seq 与 Vec：

    类型 下标是什么 发生在什么时候
    Scala Seq Scala Int 生成阶段选择某一项
    Chisel Vec 可以是硬件 UInt 运行时生成选择电路

    modules(2) 只是 Scala 在生成阶段取序列的第 2 项。registers(rs1) 中的 rs1 是硬件信号，会生成一个由寄存器编号控制的读选择网络。

    用 Vec 写寄存器堆¶

    下面是一个简单的 32 项寄存器堆：

    val registers = RegInit(
  VecInit(Seq.fill(32)(0.U(32.W)))
)

val rdata1 = Mux(rs1 === 0.U, 0.U, registers(rs1))
val rdata2 = Mux(rs2 === 0.U, 0.U, registers(rs2))

    写端口在时钟沿更新，并保护 x0：

    when(writeEnable && rd =/= 0.U) {
  registers(rd) := writeData
}

    VecInit 与 Vec¶

    VecInit 从已有硬件元素构造一个 Vec：

    val sizes = VecInit(Seq(
  1.U(3.W), 2.U(3.W), 4.U(3.W)
))

val selectedSize = sizes(sizeCode)

    常见写法可以这样理解：

    写法 生成的东西 常见用途
    VecInit(Seq(...)) 一组组合表达式 小型常量表、译码选择
    Wire(Vec(n, T)) n 个同类型 Wire 同类组合信号
    Reg(Vec(n, T)) n 个同类型 Reg 寄存器阵列
    RegInit(VecInit(...)) 带初值的寄存器阵列 教学寄存器堆

    log2Ceil 与 log2Floor¶

    参数化模块常要根据元素数量计算地址位宽。log2Ceil 和 log2Floor 都是生成阶段运行的 Scala 函数，不会生成对数计算电路。

    import chisel3.util.{log2Ceil, log2Floor}

val ceil32 = log2Ceil(32)   // 5
val ceil31 = log2Ceil(31)   // 5
val floor32 = log2Floor(32) // 5
val floor31 = log2Floor(31) // 4

    寄存器数量为参数时，地址位宽通常使用 log2Ceil：

    class RegisterFile(val count: Int) extends Module {
  val addrWidth = log2Ceil(count)
  val io = IO(new Bundle {
    val rs1 = Input(UInt(addrWidth.W))
    val rs2 = Input(UInt(addrWidth.W))
  })
}

    count 是 Scala Int，生成模块时已经确定。不能把运行时变化的 Chisel UInt 传给 log2Ceil 或 log2Floor。

    count = 1 的情况

    log2Ceil(1) 的数学结果是 0。若参数化接口允许只有一个元素，通常要用 math.max(1, log2Ceil(count)) 避免得到零位宽地址。固定 32 项寄存器堆不受这个问题影响。

    Module¶

    Chisel 的 Module 对应 Verilog 的 module。一个模块有自己的端口和内部逻辑，顶层通过实例化与连线把它们接起来。

    定义一个 ALU 模块¶

    先集中定义控制编码：

    object AluOp {
  val ADD = 0.U(4.W)
  val SUB = 1.U(4.W)
  val AND = 2.U(4.W)
  val OR  = 3.U(4.W)
}

    ALU 模块只负责根据操作码计算结果：

    class Alu extends Module {
  val io = IO(new Bundle {
    val a = Input(UInt(32.W))
    val b = Input(UInt(32.W))
    val op = Input(UInt(4.W))
    val out = Output(UInt(32.W))
    val zero = Output(Bool())
  })

  val result = MuxLookup(io.op, 0.U)(Seq(
    AluOp.ADD -> (io.a + io.b),
    AluOp.SUB -> (io.a - io.b),
    AluOp.AND -> (io.a & io.b),
    AluOp.OR  -> (io.a | io.b)
  ))
  io.out := result
  io.zero := result === 0.U
}

    io 是常用命名习惯，不是固定关键字。端口 Bundle 负责说明方向，模块内部再通过 io.xxx 读写端口。

    实例化和连线¶

    在EX级中创建 ALU：

    val alu = Module(new Alu)

alu.io.a := forwardedRs1
alu.io.b := operandB
alu.io.op := id2ex.ctrl.aluOp

val executeResult = alu.io.out

    new Alu 创建 Scala 对象，外层的 Module(...) 告诉 Chisel：这是一个硬件子模块实例。漏掉 Module(...) 会得到错误的层次或直接报错。

    Scala 也可以批量实例化模块：

    val adders = Seq.tabulate(4) { _ =>
  Module(new Adder(32))
}

    这会生成四个加法器，而不是让一个加法器分四次计算。生成器减少了重复源码，但硬件资源仍按实例数量生成。

    Mem 与 SyncReadMem¶

    使用存储器时，先确认读数据在哪一拍可用，再选择对应的存储器版本。

    Mem：异步读¶

    val mem = Mem(4096, UInt(32.W))
val readData = mem.read(readAddr)

    地址变化后，读数据走组合路径变化。写入仍发生在时钟沿：

    when(writeEnable) {
  mem.write(writeAddr, writeData)
}

    SyncReadMem：同步读¶

    val mem = SyncReadMem(4096, UInt(32.W))
val readData = mem.read(readAddr, readEnable)

    当 readEnable 为真时，本拍提交地址，下一拍才能使用 readData。对应的目的寄存器号、写回控制和 valid 也必须一起延迟，不能只把数据晚一拍。

    特性 Mem SyncReadMem
    读数据时间 地址变化后当拍 发起读取后的下一拍
    读路径 组合 同步
    是否一定推断成块 RAM 不一定 也不一定，取决于写法和工具

    存储器延迟会改变流水线

    如果当前五级流水线假设指令和数据存储器当拍返回，就不能把它直接换成 SyncReadMem 后期待时序自动对齐。存储器接口变了，流水线寄存器、暂停条件和控制信号对齐也要一起改。

    printf 与 assert¶

    printf 和 assert 可以直接放进硬件模块，在仿真运行到某个周期时观察或检查内部状态。

    条件打印¶

    when(wbValid && wbRegWrite && wbRd =/= 0.U) {
  printf(p"pc=0x${Hexadecimal(wbPC)} ")
  printf(p"x${wbRd}<-0x${Hexadecimal(wbData)}\n")
}

    流水线调试时，可以先查看写回级日志。每条提交的指令只打印一次，输出量比每一级每拍都打印小。

    检查必须成立的性质¶

    assert(pc(1, 0) === 0.U, "PC must be aligned")
assert(registers(0) === 0.U, "x0 must remain zero")

when(memWriteEnable) {
  assert(exmem.valid, "invalid stage wrote memory")
}

    断言适合检查“任何时候都不该发生”的情况，例如 PC 未对齐、两个互斥控制信号同时为真、无效流水线级产生存储器写入。

    调试时可以先用测试找到第一次失败，再围绕对应流水线级打印 PC、指令、valid 和写使能。无需默认打印所有内部信号。

    本节小结¶

    • Bundle 按字段组织一笔流水线数据，valid 决定这笔数据是否有效。
    • Vec 按下标组织同类硬件；硬件下标访问会生成选择电路。
    • log2Ceil 和 log2Floor 在生成阶段计算，寄存器地址位宽通常使用前者。
    • Module(new Xxx) 创建真实的硬件层次，Scala 批量实例化会复制硬件资源。
    • 使用存储器前先确认读延迟，控制信号必须与数据按周期对齐。
