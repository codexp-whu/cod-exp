    从Verilog到Chisel

    同学们已经使用Verilog完成了一个简单的单周期CPU设计。

    在这个过程中，你可能已经体验过：

    • 一个模块需要写大量重复的 assign
    • 数据通路中几十根甚至上百根信号需要手动连接
    • 修改一次数据位宽，需要检查大量代码
    • 增加流水线寄存器，需要复制大量类似代码
    • 参数变化时，需要使用复杂的 generate 语句

    对于一个简单的单周期CPU来说，这些问题还可以接受。

    但是，如果设计一个现代处理器，例如：

    • 五级流水线CPU
    • 双发射CPU
    • 带Cache、TLB、分支预测的处理器
    • 多核处理器

    Verilog代码会迅速膨胀，模块之间的连接关系也会变得越来越复杂。

    因此，现代CPU设计逐渐开始使用硬件构建语言（Hardware Construction Language, HCL），通过更强大的抽象能力帮助设计复杂硬件。

    其中最具有代表性的就是：

    Chisel（Constructing Hardware in Scala Embedded Language）

    Chisel简介¶

    Chisel（Constructing Hardware in a Scala Embedded Language）是由加州大学伯克利分校开发的开源硬件构建语言。 本质是 Scala 语言的一个库，并非独立的新语言。

    你可以使用 Scala 的全部特性（面向对象、函数式编程、元编程）来描述电路。其设计流程为：Chisel 源码 —— FIRRTL（中间表示） —— Verilog（用于综合、仿真），兼容所有现有的EDA工具。

    Note

    使用Chisel设计的CPU，最终仍然会转换成Verilog，并通过Vivado、Verilator等传统EDA工具完成综合、仿真和实现。

    Chisel并不是替代Verilog，而是在Verilog之上提供了一种更加现代、更适合构建复杂硬件的开发方式。

    著名的开源处理器 Rocket Chip（RISC-V）和 OpenXiangShan（香山开源高性能RISC-V处理器）正是用 Chisel 完成的，证明了它在复杂 CPU 设计中的能力。

    为什么要学习Chisel¶

    同学们已经使用Verilog完成了一个单周期CPU，相信大家已经感受到了使用Verilog开发处理器的不便之处。

    现代CPU设计充满大量重复逻辑、复杂连线、高度参数化。传统Verilog开发面临以下问题：

    1. 连线非常多，重复代码极多（如每级流水线寄存器需要重复定义），在开发过程中容易出错
    2. 位宽不匹配的隐式截断、未连接的端口等类型不安全问题，在大型CPU中排查困难
    3. 模块复用更多靠复制粘贴，不能像软件开发一样抽象复用
    4. generate / 宏方案参数化能力有限，难以生成高度灵活的流水线结构

    Chisel与Verilog的直观对比¶

    同学们先不必懂Chisel的语法细节，先对照Verilog和Chisel，直观感受Chisel的“敏捷”

    4选1多路选择器¶

    verilog版本： 

    module mux4 (
    input  [31:0] a, b, c, d,
    input  [1:0]  sel,
    output reg [31:0] out
);
    always @(*) begin
        case(sel)
            2'b00: out = a;
            2'b01: out = b;
            2'b10: out = c;
            2'b11: out = d;
            default: out = 32'b0;
        endcase
    end
endmodule
    Chisel版本： 
    val out = MuxLookup(sel, 0.U(32.W))(Seq(
    0.U -> a,
    1.U -> b,
    2.U -> c,
    3.U -> d
))

    寄存器堆¶

    Verilog版本： 

    module regfile (
    input         clk, wen,
    input  [4:0]  rs1, rs2, rd,
    input  [31:0] wdata,
    output [31:0] rdata1, rdata2
);
    reg [31:0] rf [0:31];
    assign rdata1 = (rs1 == 0) ? 32'b0 : rf[rs1];  // x0 硬件连线
    assign rdata2 = (rs2 == 0) ? 32'b0 : rf[rs2];
    always @(posedge clk)
        if (wen && rd != 0) rf[rd] <= wdata;
endmodule
    Chisel版本： 
    val rf = RegInit(VecInit(Seq.fill(32)(0.U(32.W)))) // 32 个 0 初始化的寄存器
val rdata1 = Mux(rs1 === 0.U, 0.U, rf(rs1))       // x0 的判断依然优雅
val rdata2 = Mux(rs2 === 0.U, 0.U, rf(rs2))
when(wen && rd =/= 0.U) { rf(rd) := wdata }

    ALU¶

    Verilog版本： 

    always @(*) begin
    case(aluOp)
        4'b0000: result = a + b;
        4'b0001: result = a - b;
        4'b0100: result = ($signed(a) < $signed(b)) ? 32'd1 : 32'd0; // SLT 判断
        default: result = 32'b0;
    endcase
end
    Chisel版本： 
    val result = MuxCase(0.U, Seq(
    (aluOp === ALU_ADD)  -> (io.a + io.b),
    (aluOp === ALU_SUB)  -> (io.a - io.b),
    (aluOp === ALU_SLT)  -> (io.a.asSInt < io.b.asSInt).asUInt
))

    顶层连线¶

    Verilog版本：需要手动定义和连接大量信号，且增删信号繁琐 

    wire [31:0] pc, inst;
wire regWrite;
wire [3:0] aluOp;

decoder u_dec(
    .inst(inst),
    .regWrite(regWrite),
    .aluOp(aluOp)
);
    Chisel版本：Bundle处一次定义所有信号，后续增删信号容易 
    // 定义
class DecodeInfo extends Bundle {
    val pc   = UInt(32.W)
    val inst = UInt(32.W)
}
// 实例化
val if2id = Wire(new DecodeInfo)

// 连线
if2id.pc   := pc
if2id.inst := inst

decoder.io.in := if2id

    Note

    Verilog 在单周期 CPU 阶段还能忍受，但一旦流水线级数增加、旁路逻辑复杂，你会深陷重复连线之中，且修改和维护过程繁琐。

    让我们从Chisel重新出发¶

    上述所有优势在流水线处理器开发过程中会被急剧放大：

    • 参数化和复用能够让你轻松创建N级相同流水结构
    • Bundle打包让流水线寄存器例化从几十条信号名缩短为一行
    • 译码表可以动态配置，增删指令只需要修改一处即可
    • 类型安全 保证流水线各级的信号位宽严格匹配，消除级间截断问题

    从单周期CPU过渡到流水线CPU，Chisel 能将你的主要精力从“如何连线”解放出来，聚焦在旁路、冒险等真正的架构设计上。

    让我们从Chisel重新出发，从Chisel最基础的语法知识开始讲起。
