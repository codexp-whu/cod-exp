    Basic Syntax (Part 2): Combinational and Sequential Logic¶

    To tell whether a piece of Chisel is combinational or sequential, look at whether the data passes through a Reg:

    • With no Reg, the output depends only on the current inputs, so it is combinational logic.
    • Passing through a Reg, the value is saved across a clock edge, so it is sequential logic.

    when and switch are only conditional-connection syntax; on their own they are not a register.

    Combinational Expressions¶

    Arithmetic and Bit Width¶

    val sum  = a + b
val diff = a - b
val prod = a * b

    Chisel arithmetic has definite rules for the result bit width. Take UInt addition as an example:

    • a + b and a +% b keep the width of the wider operand, and the carry out of the most significant bit is dropped.
    • a +& b is one bit wider than the wider operand, so it can keep the carry.
    val a = Wire(UInt(8.W))
val b = Wire(UInt(8.W))

val wrapped = a + b   // 8 位
val full    = a +& b  // 9 位

    A 32-bit addition in a CPU usually wants to wrap around naturally, so plain + is enough. When you compute a checksum or an address boundary, or when you need a carry flag, think about +&.

    Check the bit width of the addition result

    Two operands with different bit widths can usually be combined, and the compiler does not necessarily report an error. When you design, check that the result width is what you expect, and write tests for ALU overflow, maximum value plus one, and similar cases.

    Comparison¶

    val eq  = a === b
val neq = a =/= b
val lt  = a < b
val ge  = a >= b

    Order comparisons on UInt are interpreted as unsigned, and on SInt as signed. This is how you tell RISC-V's SLT and SLTU apart:

    val slt  = a.asSInt < b.asSInt
val sltu = a < b

    Hardware equality and inequality use === and =/=.

    Scala's == returns a Scala Boolean and is no substitute for Chisel's hardware comparison result, a Bool.

    when(a === b) {
  equalCount := equalCount + 1.U
}

    Bitwise and Logical Operations¶

    val andResult = a & b
val orResult  = a | b
val xorResult = a ^ b
val inverted  = ~a

    Several Bool conditions are usually combined with &&, || and !:

    val canWrite = wen && (rd =/= 0.U)
val mustStop = loadHazard || cacheBusy

    Shifts¶

    val sll = a << shamt
val srl = a >> shamt
val sra = (a.asSInt >> shamt).asUInt

    For RV32, a register shift uses only the low 5 bits of the shift amount:

    val shamt = b(4, 0)

    The result width of a dynamic left shift can grow with the width of the shift amount. If the ALU output must stay 32 bits wide, the 32-bit output port should constrain it; check what gets generated.

    Bit Extraction, Concatenation and Filling¶

    val opcode = inst(6, 0)
val rs1    = inst(19, 15)
val sign   = inst(31)

    Cat concatenates from left to right, most significant bits first:

    val immS = Cat(inst(31, 25), inst(11, 7))
val addr = Cat(wordAddr, 0.U(2.W))

    Fill repeats a run of bits and is often used for sign extension:

    val immI = Cat(Fill(20, inst(31)), inst(31, 20))

    Selection Logic¶

    Mux¶

    Mux(cond, whenTrue, whenFalse) corresponds to Verilog's ternary operator:

    val nextPC = Mux(taken, target, pc + 4.U)

    MuxLookup¶

    When the selection is driven by one encoded signal, you can use MuxLookup:

    val result = MuxLookup(aluOp, 0.U(32.W))(Seq(
  AluOp.ADD -> (a + b),
  AluOp.SUB -> (a - b),
  AluOp.AND -> (a & b)
))

    The first argument is the select signal and the second is the default value used when nothing matches. Both the keys and the values of the mapping entries are hardware expressions.

    MuxCase¶

    MuxCase takes a list of independent conditions, and the earlier conditions win:

    val fwdData = MuxCase(rsData, Seq(
  hitEx  -> exData,
  hitMem -> memData
))

    This suits cases such as forwarding selection, where the priority is explicit. If the conditions are really just comparisons against the same encoded value, MuxLookup is usually clearer.

    Mux1H¶

    Mux1H selects data with a set of one-hot conditions:

    val result = Mux1H(Seq(
  isAdd -> (a + b),
  isSub -> (a - b),
  isAnd -> (a & b)
))

    It works by masking each candidate bitwise and then OR-ing the results together. So:

    • When no condition is true, the result is usually all zeros.
    • When several conditions are true at once, the candidate values are OR-ed together bitwise, and the result is usually not what you wanted.
    Need Suggested idiom
    Two-way select Mux
    Lookup on one encoded signal MuxLookup
    Several conditions matched in order MuxCase
    One-hot conditions already available Mux1H

    when Is a Conditional Connection¶

    when / elsewhen / otherwise can drive Wires, output ports, or Regs. What hardware gets generated depends on the target.

    Describing Combinational Logic with when¶

    Give the Wire a default value first, then override it when the condition holds:

    val selected = WireDefault(normalData)

when(forwardFromEx) {
  selected := exData
}.elsewhen(forwardFromMem) {
  selected := memData
}

    This generates combinational selection logic with priority. The default value covers the path where no condition holds, so no connection is left undriven.

    The following version is incomplete:

    val selected = Wire(UInt(32.W))
when(cond) {
  selected := data
}

    selected is not a register, and when cond is false it cannot "keep its old value" either. Chisel will point out during its checks that it is not driven on every path.

    Controlling Register Updates with when¶

    When the assignment target is a Reg, the register keeps its value if the condition does not hold:

    val pc = RegInit(0.U(32.W))

when(!stall) {
  pc := nextPC
}

    This generates a register with an enable. Keeping the old value does not require writing pc := pc explicitly.

    Connection Order and Priority¶

    When the same target is driven several times in one scope, the last connection written wins. The usual idiom is a default connection first, then the special cases:

    pc := pc + 4.U

when(redirect) {
  pc := target
}

    This reads as "normally add 4; on a redirect, jump to target". The default-plus-override structure works for both Wires and Regs.

    switch / is¶

    When several branches all test different values of the same signal, switch is easier to read than a long chain of comparisons:

    switch(state) {
  is(State.IDLE) { nextState := State.RUN }
  is(State.RUN)  { nextState := State.DONE }
  is(State.DONE) { nextState := State.IDLE }
}

    switch is not a dedicated sequential statement either. If nextState in the example above is a Wire, it generates combinational next-state logic; if it drives the state Reg directly, it controls a register update.

    A state machine is usually written as "a state register plus a next-state Wire":

    val state = RegInit(State.IDLE)
val nextState = WireDefault(state)

switch(state) {
  is(State.IDLE) { when(start) { nextState := State.RUN } }
  is(State.RUN)  { when(done)  { nextState := State.DONE } }
}

state := nextState

    = vs. :=¶

    The two symbols live at different levels:

    Form Meaning Generates a hardware connection
    val x = expr Defines the Scala name x expr itself may construct hardware
    var x = expr Defines a Scala name that can be rebound Rebinding is not a hardware update
    sink := source Connects a hardware source to a hardware target Yes 
    val sum = a + b
io.out := sum

    The first line names a hardware expression, and the second establishes the connection from sum to the output port. There is no rule that "= is a combinational assignment and := is a sequential one".

    Common Register Idioms¶

    RegNext¶

    RegNext(in) delays the input by one cycle, but carries no reset value:

    val delayed = RegNext(io.in)

    Use the second argument when you need a reset value:

    val delayed = RegNext(io.in, 0.U)

    RegEnable¶

    RegEnable samples the input only when the enable is true:

    val pc = RegEnable(nextPC, 0.U(32.W), !stall)

    The equivalent expanded form is:

    val pc = RegInit(0.U(32.W))
when(!stall) {
  pc := nextPC
}

    Counters¶

    val count = RegInit(0.U(8.W))

when(enable) {
  count := count + 1.U
}

    Default Update, Overridden in Special Cases¶

    val pc = RegInit(0.U(32.W))

when(redirect) {
  pc := target
}.elsewhen(!stall) {
  pc := pc + 4.U
}

    If a stall and a redirect can happen in the same cycle, you must decide explicitly which one wins. The example above tests redirect first, so the redirect wins; only when there is neither a redirect nor a stall does the PC add 4. During a stall there is no connection, so the register naturally holds its value.

    Section Summary¶

    • When you see when, first check whether the assignment target is a Wire or a Reg.
    • Give a combinational Wire a default value, then override it conditionally.
    • = is a Scala definition or rebinding; := is a hardware connection.
    • Check the bit width of every addition, shift, and type conversion.
