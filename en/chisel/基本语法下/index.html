    Basic Syntax (Part 3): Bundle, Vec and Module¶

    This chapter introduces Bundle, Vec and Module, which are used to organize related signals, to represent arrays of similar hardware, and to build up a module hierarchy.

    Bundle¶

    Pipeline stages usually have to pass several signals along at the same time. What IF hands to ID is valid, the PC and the instruction; when ID hands over to EX there are also operands, immediates, the destination register and control signals.

    If every wire is declared on its own, adding or removing a field easily leaves a connection somewhere that nobody updated. A Bundle lets you organize these signals into one unit.

    Defining Pipeline Data¶

    The Bundle below represents one piece of data passed between the IF and ID stages:

    class IF2ID extends Bundle {
  val valid = Bool()
  val pc = UInt(32.W)
  val inst = UInt(32.W)
}

    new IF2ID only gives the field structure. You get actual hardware once you hand it to a Wire or a Reg:

    val if2idNext = Wire(new IF2ID)
val if2id = RegInit(0.U.asTypeOf(new IF2ID))

    Fill in the fields of the combinational version, then write the whole bundle into the pipeline register:

    if2idNext.valid := fetchValid
if2idNext.pc := fetchPC
if2idNext.inst := fetchInst

when(!stall) {
  if2id := if2idNext
}

    The generated RTL still has a register and the corresponding connections for each field. A Bundle changes how the code is organized; it does not reduce these hardware signals.

    Using valid to Mark a Bubble¶

    When you insert a bubble, the key move is to set valid to false:

    val bubble = WireDefault(0.U.asTypeOf(new IF2ID))
bubble.valid := false.B

    The later connection overrides the all-zero bundle written before it. Downstream logic must guarantee that a false valid produces no side effects such as register writes or memory writes.

    Writing only the instruction field as a NOP encoding does not guarantee that the other control signals are neutralized at the same time. An explicit valid lets you control stalls, flushes and external side effects in one place.

    Bundles Can Nest¶

    When a group of control signals recurs in several pipeline stages, you can define a small Bundle for it:

    class DecodeControl extends Bundle {
  val regWrite = Bool()
  val memRead = Bool()
  val memWrite = Bool()
  val aluOp = UInt(4.W)
}

    Then put it inside the ID/EX data:

    class ID2EX extends Bundle {
  val valid = Bool()
  val pc = UInt(32.W)
  val rd = UInt(5.W)
  val operandA = UInt(32.W)
  val operandB = UInt(32.W)
  val ctrl = new DecodeControl
}

    Nested fields are still accessed with dots:

    id2exNext.ctrl.regWrite := decoder.io.ctrl.regWrite
id2exNext.ctrl.aluOp := decoder.io.ctrl.aluOp

    When the structure and the directions are compatible, you can also connect a whole bundle at once:

    id2exNext.ctrl := decoder.io.ctrl

    Do not nest too deeply. Control signals and datapath signals that belong to the same group can be nested; fields that are not closely related should still be organized separately.

    Vec¶

    The fields of a Bundle have different names and meanings, whereas the elements of a Vec all have the same type and are accessed by index.

    First, keep Seq and Vec apart:

    Type What the index is When it happens
    Scala Seq a Scala Int one item is selected at generation time
    Chisel Vec can be a hardware UInt a selection circuit is generated and used at run time

    modules(2) is just Scala taking item 2 of the sequence at generation time. In registers(rs1), rs1 is a hardware signal, so a read selection network controlled by the register number is generated.

    Writing a Register File with Vec¶

    Here is a simple 32-entry register file:

    val registers = RegInit(
  VecInit(Seq.fill(32)(0.U(32.W)))
)

val rdata1 = Mux(rs1 === 0.U, 0.U, registers(rs1))
val rdata2 = Mux(rs2 === 0.U, 0.U, registers(rs2))

    The write port updates on the clock edge and protects x0:

    when(writeEnable && rd =/= 0.U) {
  registers(rd) := writeData
}

    VecInit and Vec¶

    VecInit builds a Vec from existing hardware elements:

    val sizes = VecInit(Seq(
  1.U(3.W), 2.U(3.W), 4.U(3.W)
))

val selectedSize = sizes(sizeCode)

    These common idioms can be read like this:

    Form What it generates Typical use
    VecInit(Seq(...)) a group of combinational expressions small constant tables, decode selection
    Wire(Vec(n, T)) n Wires of the same type similar combinational signals
    Reg(Vec(n, T)) n Regs of the same type register arrays
    RegInit(VecInit(...)) a register array with initial values a teaching register file

    log2Ceil and log2Floor¶

    Parameterized modules often need to compute an address width from the number of elements. Both log2Ceil and log2Floor are Scala functions that run at generation time; they do not generate a logarithm circuit.

    import chisel3.util.{log2Ceil, log2Floor}

val ceil32 = log2Ceil(32)   // 5
val ceil31 = log2Ceil(31)   // 5
val floor32 = log2Floor(32) // 5
val floor31 = log2Floor(31) // 4

    When the number of registers is a parameter, the address width usually uses log2Ceil:

    class RegisterFile(val count: Int) extends Module {
  val addrWidth = log2Ceil(count)
  val io = IO(new Bundle {
    val rs1 = Input(UInt(addrWidth.W))
    val rs2 = Input(UInt(addrWidth.W))
  })
}

    count is a Scala Int and is already fixed when the module is generated. You cannot pass a Chisel UInt that changes at run time to log2Ceil or log2Floor.

    The count = 1 case

    The mathematical result of log2Ceil(1) is 0. If a parameterized interface allows a single element, you usually need math.max(1, log2Ceil(count)) to avoid a zero-width address. A fixed 32-entry register file is not affected by this.

    Module¶

    Chisel's Module corresponds to Verilog's module. A module has its own ports and internal logic, and the top level connects them up by instantiating and wiring them.

    Defining an ALU Module¶

    First define the control encodings in one place:

    object AluOp {
  val ADD = 0.U(4.W)
  val SUB = 1.U(4.W)
  val AND = 2.U(4.W)
  val OR  = 3.U(4.W)
}

    The ALU module is responsible only for computing a result from the operation code:

    class Alu extends Module {
  val io = IO(new Bundle {
    val a = Input(UInt(32.W))
    val b = Input(UInt(32.W))
    val op = Input(UInt(4.W))
    val out = Output(UInt(32.W))
    val zero = Output(Bool())
  })

  val result = MuxLookup(io.op, 0.U)(Seq(
    AluOp.ADD -> (io.a + io.b),
    AluOp.SUB -> (io.a - io.b),
    AluOp.AND -> (io.a & io.b),
    AluOp.OR  -> (io.a | io.b)
  ))
  io.out := result
  io.zero := result === 0.U
}

    io is a common naming convention, not a reserved keyword. The port Bundle states the directions, and inside the module you read and write the ports through io.xxx.

    Instantiation and Wiring¶

    Create the ALU in the EX stage:

    val alu = Module(new Alu)

alu.io.a := forwardedRs1
alu.io.b := operandB
alu.io.op := id2ex.ctrl.aluOp

val executeResult = alu.io.out

    new Alu creates a Scala object, and the enclosing Module(...) tells Chisel that this is a hardware submodule instance. Leaving out Module(...) gives you the wrong hierarchy or fails outright.

    Scala can also instantiate modules in bulk:

    val adders = Seq.tabulate(4) { _ =>
  Module(new Adder(32))
}

    This generates four adders; it does not make one adder compute four times over. Generators reduce duplicated source code, but the hardware resources are still generated per instance.

    Mem and SyncReadMem¶

    Before you use a memory, first establish in which cycle the read data becomes available, then choose the matching memory variant.

    Mem: Asynchronous Read¶

    val mem = Mem(4096, UInt(32.W))
val readData = mem.read(readAddr)

    Once the address changes, the read data changes along a combinational path. Writes still happen on the clock edge:

    when(writeEnable) {
  mem.write(writeAddr, writeData)
}

    SyncReadMem: Synchronous Read¶

    val mem = SyncReadMem(4096, UInt(32.W))
val readData = mem.read(readAddr, readEnable)

    When readEnable is true, the address is submitted in this cycle and readData is only usable in the next cycle. The corresponding destination register number, write-back control and valid must be delayed along with it; delaying only the data by a cycle is not enough.

    Property Mem SyncReadMem
    When read data is available in the same cycle the address changes in the cycle after the read is issued
    Read path combinational synchronous
    Always inferred as block RAM? Not necessarily Also not necessarily; it depends on how you write it and on the tool

    Memory latency changes the pipeline

    If your current five-stage pipeline assumes that the instruction memory and the data memory return in the same cycle, you cannot simply swap in SyncReadMem and expect the timing to line up on its own. Once the memory interface changes, the pipeline registers, the stall conditions and the control-signal alignment have to change with it.

    printf and assert¶

    printf and assert can go straight into a hardware module to observe or check internal state in simulation when a particular cycle is reached.

    Conditional Printing¶

    when(wbValid && wbRegWrite && wbRd =/= 0.U) {
  printf(p"pc=0x${Hexadecimal(wbPC)} ")
  printf(p"x${wbRd}<-0x${Hexadecimal(wbData)}\n")
}

    When debugging a pipeline, start with a write-back stage log. Each committed instruction is printed once, so the output is smaller than printing from every stage every cycle.

    Checking Properties That Must Hold¶

    assert(pc(1, 0) === 0.U, "PC must be aligned")
assert(registers(0) === 0.U, "x0 must remain zero")

when(memWriteEnable) {
  assert(exmem.valid, "invalid stage wrote memory")
}

    Assertions suit conditions that should never happen, such as a misaligned PC, two mutually exclusive control signals being true at the same time, or an invalid pipeline stage producing a memory write.

    When debugging, first use a test to find the first failure, then print the PC, the instruction, valid and the write enables around that pipeline stage. There is no need to print every internal signal by default.

    Section Summary¶

    • A Bundle organizes one piece of pipeline data by field, and valid decides whether that piece of data counts.
    • A Vec organizes similar hardware by index; indexing with a hardware signal generates a selection circuit.
    • log2Ceil and log2Floor are computed at generation time, and a register address width usually uses the former.
    • Module(new Xxx) creates a real hardware hierarchy, and instantiating in bulk from Scala replicates the hardware resources.
    • Confirm the read latency before you use a memory, and keep the control signals aligned cycle by cycle with the data.
