本页介绍如何从 GitHub 获取实验基础模板，以及各目录的结构与用法。开始实验前，请先通读本页。

## 获取实验模板

本课程实验基于龙芯官方教学实验环境 `cdp_ede_local`，对龙芯官方实验环境进行了修改，能够在DIGILENT NEXYS 100T开发板上正常运行，修改后的实验环境仓库：[cdp_ede_loca](https://github.com/zihaojf/cdp_ede_local)

首先clone到本地，**建议放在windows下**，不要放在WSL2中。

```bash
git clone git@github.com:zihaojf/cdp_ede_local.git
```

!!! tip

    建议自己在开发过程中做好版本管理！

克隆完成后，仓库根目录结构如下：

```text
cdp_ede_local/
├── README.md          # 说明文档：实验安排与对应环境
├── dc_env/            # 实验 1~4：数字逻辑电路基础
├── minicpu_env/       # 实验 5：5条指令单周期CPU
└── mycpu_env/         # 实验 6~23：20条指令CPU起的全部实验
```

三个环境**对应课程的三段实验**，彼此独立，按实验进度依次使用。

## dc_env（实验 1~4）

```text
dc_env/
├── exp1/    跑马灯实验
├── exp2/    寄存器堆仿真
├── exp3/    同步/异步 RAM
└── exp4/    数字逻辑电路设计与调试
```

每个 `expN` 目录自带源文件骨架、testbench 和约束文件（`.xdc`），用 Vivado 直接打开或新建工程添加源文件即可。**你需要做的是补全/修正源文件，跑通仿真，再综合上板。**

## minicpu_env（实验 5）

```text
minicpu_env/
├── func/           # 测试程序：汇编 → 指令存储器初始化文件
│   ├── start.S         # 斐波那契程序（5条指令即可运行）
│   ├── Makefile        # 交叉编译，产出 inst_ram.coe / inst_ram.txt
│   └── inst_ram.coe    # 编译好的指令镜像（仿真用）
├── miniCPU/        # CPU 的 RTL
│   ├── minicpu_top.v   # 单周期 CPU 顶层
│   ├── regfile.v       # 寄存器堆
│   └── tools.v         # 辅助部件
└── soc_verify/     # SoC 验证环境
    ├── rtl/            # soc_mini_top.v + CONFREG + xilinx_ip
    └── testbench/      # mycpu_tb.v：仿真顶层
```

已提供一个可运行五条指令的minicpu，在 `soc_verify` 的 Vivado 工程中运行仿真，CPU 从 `inst_ram` 取指执行 `func` 里的斐波那契程序，结果通过 CONFREG（仿真中观察）或数码管（上板）验证。

## mycpu_env（实验 6~23）

这是课程使用时间最长的环境，后续所有实验都在它上面**增量开发**。

```text
mycpu_env/
├── myCPU/              # 你的 CPU RTL
│   ├── mycpu_top.v     # CPU 顶层
│   ├── alu.v、regfile.v、decoder_*.v ...
├── func/               # func 功能测试程序集
│   └── inst/           # n1~n79 分项测试汇编（每文件聚焦若干指令）
├── gettrace/           # 参考轨迹生成工具（trace 比对调试用）
├── module_verify/      # 独立模块验证（实验 17 TLB、实验 20 Cache）
│   ├── tlb_verify/     # 实验 17：TLB模块验证
│   ├── cache_verify/   # 实验 20：Cache模块验证
│   ├── mul_verify/     # 乘法器验证
|   ├── div_verify/     # 除法器验证
└── soc_verify/         # SoC 验证环境，按总线接口分四个目录
    ├── soc_dram/       # 实验 6：分布式 RAM 接口（单周期）
    ├── soc_bram/       # 实验 7~13：块 RAM 接口（流水线/异常）
    ├── soc_hs_bram/    # 实验 14：带握手 BRAM 接口
    └── soc_axi/        # 实验 15~23：AXI 总线接口
```

!!! warning "两点特别注意"

    1. `myCPU/` 初始代码**含有功能错误**，这是实验设计的一部分（找错并修正），不是仓库 bug；
    2. 每个实验对应 `soc_verify` 下**不同的 SoC 目录**——实验时注意仿真/上板工程用的是哪个目录。


!!! note "工具链"

    `func/` 的 Makefile 依赖 `loongarch32r-linux-gnusf-*` 交叉编译工具链（自行编译测试程序时需要）。仿真验证通常只需仓库自带的 `inst_ram.coe` 镜像，直接跑即可。

- [ ] LoongArch32 交叉编译工具链安装并加入 `PATH`；
- [ ] 建立自己的代码仓库
