# Lab 4: Digital Logic Design and Debugging

!!! info "Reference in the Book"

    [*CPU Design in Practice: LoongArch Edition*, 3.1.3 Practical Task 4: Design and Debugging of Digital Logic Circuits](https://bookdown.org/loongson/_book3/chapter-digital-logic.html#subsec-exp4)

## Objectives

- Complete the whole flow of a full digital system on your own: "design → simulate → synthesize → program → debug".
- Learn the basic techniques for debugging on the board.

## Tasks

The lab environment is in the `dc_env/exp4/` directory, with the following structure:
```
|--show_sw.v             Source file for the digital circuit design.
|--show_sw.xdc           Constraints file for the design, used for synthesis and implementation.
|--tb.v                  Simulation file for the design, used for simulation.
```
The design in show_sw.v contains **five bugs**. Its correct behavior is:

1. Read the state of the four rightmost DIP switches on the board (taken as "up = 1, down = 0"; on the actual board, a switch that is up is low and one that is down is high), giving 16 states (numbered 0~15).
2. The leftmost seven-segment display shows the state of the four DIP switches in real time. The display can only show 0~9, so if the switch state is 10~15 the display does not change (it keeps showing the previous value).
3. The four rightmost single-color LEDs show the previous state of the DIP switches, covering 0~15 (a switch that is up means the corresponding LED is lit).

For example: in the initial state, with all four DIP switches down, press reset and the display shows 0 with all LEDs off; set the DIP switches to 1 and the display shows 1, with the LEDs still all off; set the DIP switches to 3 and the display shows 3 while the LEDs show 1.

The design source provided contains five bugs. Four of them produce the first four kinds of waveform anomaly: the waveform being "Z", the waveform being "X", the waveform stopping, and sampling across a clock edge; the fifth bug is a functional bug.

The top-level interface of the example design provided for this task is as follows:

| Name | Width | Direction | Description |
|------|------|------|------|
| clk | 1 | input | Clock signal |
| resetn | 1 | input | Reset signal |
| switch | 4 | input | Corresponds to the four rightmost DIP switches on the board |
| num_csn | 8 | output | Chip-select signals for the seven-segment display |
| num_a_g | 7 | output | Seven-segment signals for the seven-segment display |
| led | 4 | output | Corresponds to the four rightmost single-color LEDs on the board |

## Steps

1. Create a new project in Vivado.
2. Click "Add Sources", choose design sources, and add show_sw.v.
3. Click "Add Sources", choose constraints, and add show_sw.xdc.
4. Click "Add Sources", choose simulation sources, and add tb.v.
5. Work out what the example design is supposed to do, examine the simulation top level tb.v, and understand what the simulation does.
6. Run the simulation, and make good use of the waveform viewer's aids (splitting, grouping, color changes, markers and so on) to debug it and find all the bugs.
7. Once the simulation is correct, synthesize and implement the design and generate the bitstream.
8. After the bitstream has been generated, connect the board and verify the design on hardware.


## Acceptance Criteria

- [ ] In simulation the LED value is 0, 7, 6, 1, d, f in that order.
- [ ] The behavior described above is reproduced correctly on the board.
