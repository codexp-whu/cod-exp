# 实验23：CPU中添加CACOP指令

!!! info "原书参考"

    [《CPU设计实战：LoongArch版》10.2.4 实践任务23：CPU中添加CACOP指令](https://bookdown.org/loongson/_book3/chapter-cache-design.html)

## 实验目标

- 实现 CACHE 指令（`cacop`，编码 `0x06` 类）：按操作码对指定地址的 Cache 行执行**查询、置无效、写回、冲刷**等维护操作。
- 理解软件维护 Cache 的场景：DMA 一致性、内核换页、自修改代码。
- （如安排）打通带完整 Cache 的 CPU 在内核下的稳定运行。

## 知识背景

### 为什么需要 CACHE 指令

DMA 外设直接读写内存，不经过 CPU 的 Cache——双方各自持有数据副本，一致性出现裂痕：

```text
CPU 写 DCache（数据停在缓存）→ DMA 从内存读（拿到旧值）
DMA 写内存（新值落地）      → CPU 读 DCache（命中旧值）
```

内核在 DMA 前后必须用 CACHE 指令主动**清洗（写回脏行）**或**置无效**相关地址的行。同样，换页时作废旧映射、自修改代码时刷新 ICache，都靠它。

### cacop 的操作与语义

`cacop` 带一个 5 位操作码 + 地址操作数，常见子操作（具体集合以课程/手册为准）：

| 操作 | 语义 |
| ---- | ---- |
| 读 Tag 并查询 | 把命中信息写入 `CSR.TLBIDX` 类似的查询结果（LoongArch 上写入 TagLo/TagHi 类 CSR） |
| 置无效（Invalidate） | 命中行清 V，**丢弃**数据 |
| 写回（Writeback） | 脏行写回内存，V 保留 |
| 冲刷（Flush） | 写回 + 置无效一步到位 |

实现上它是"一条走 MEM 级的特殊访存指令"：按地址算 Index/Tag 查行，命中则执行对应操作，状态机与未命中写回路径复用实验 20 的设计。

### 特权与粒度

`cacop` 是**特权指令**（PLV0 才能执行，否则触发特权指令例外）；操作粒度是**一条 Cache 行**，软件需自行按行大小对齐循环。
