# 实验21：在CPU中集成ICache

!!! info "原书参考"

    [《CPU设计实战：LoongArch版》10.2.2 实践任务21：在CPU中集成ICache](https://bookdown.org/loongson/_book3/chapter-cache-design.html)

## 实验目标

- 把实验 20 的 Cache 模块接入 IF 级取指通路，成为 ICache。
- 处理取指粒度问题：一行 16B 有 4 条指令，未命中的代价如何摊薄。
- 在随机总线延迟下验证功能与性能提升。

## 知识背景

### 取指通路的变化

此前 IF 直接向总线发取指请求；接入 ICache 后：

```text
IF → ICache（命中：当拍返回指令 / 未命中：状态机取行，IF 冻结等待）
```

- 等待期间 PC、IF/ID 冻结——与实验 14 的总线等待逻辑同构，可复用；
- **跳转的代价变了**：跳到未命中行要付整行取回的时间；命中则近乎零开销。

### 指令预取的自然收益

一行 4 条指令顺序执行时，只需第一次付未命中代价，后 3 条全部命中——空间局部性直接转化为性能。运行测试程序对比接入前后的周期数，你会第一次亲手量出 Cache 的价值。

### 与流水线冲刷的交互

分支冲刷发生在取指之后：被冲刷的取指请求若已进入 ICache 状态机，需要**作废**其应答（结果丢弃但状态机要走完），否则下一个有效请求会撞上未完成的旧请求。请求编号/作废标志是常见解法。

## 任务要求

1. 将 Cache 模块接入 IF 级，实现等待冻结与冲刷作废逻辑；
2. 功能测试全部通过（含随机总线延迟回归）；
3. 量化对比：接入 ICache 前后，典型测试程序的执行周期数。
