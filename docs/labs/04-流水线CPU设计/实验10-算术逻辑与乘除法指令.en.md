# Lab 10: Adding Arithmetic, Logic, Multiply and Divide Instructions

!!! info "Reference in the Book"

    [*CPU Design in Practice: LoongArch Edition* 6.1.1 Practical Task 10: Adding Arithmetic, Logic, Multiply and Divide Instructions](https://bookdown.org/loongson/_book3/chapter-add-more-user-instr.html#subsec-exp10)

## Objectives

- Add arithmetic and logic instructions and multiply/divide instructions to the pipelined CPU you already have.

## Tasks

This practical task asks you to build on the CPU you implemented in Lab 9 and do the following:

Add the arithmetic and logic instructions: **slti, sltui, andi, ori, xori, sll, srl, sra, pcaddu12i**.

Add the multiply and divide instructions: **mul.w, mulh.w, mulh.wu, div.w, mod.w, div.wu, mod.wu**.

!!! warning "Multiply and divide are multi-cycle operations"

    32-bit multiply and divide cannot complete in a single pipeline cycle, so you need a separate multi-cycle multiply/divide unit and must freeze the pipeline while it operates. Pay attention to how it interacts with the stall and forwarding logic: multiply/divide results must also feed into the forwarding network.

!!! info "Select EXP10 as the test program"

## Steps

1. Copy the code of the CPU you implemented into the `mycpu_env/myCPU/` directory.
2. Edit the func configuration file, `mycpu_env/func/include/test_config.h`, to select the exp10 configuration, then compile it. (`make EXP=10`)
3. Open the `gettrace` project, `mycpu_env/gettrace/gettrace.xpr`. Run the `gettrace` project's simulation (once the simulation window is open, just click run all and wait for the simulation to finish) to generate a new reference trace file `golden_trace.txt` (`mycpu_env/gettrace/golden_trace.txt`). The simulation has to run to completion before `golden_trace.txt` holds its full contents.
4. Go into the `mycpu_env/soc_verify/soc_bram/run_vivado/` directory and start the project that verifies myCPU. If no project has been created in that directory yet, use the `create_project.tcl` file there to create one. If a project created for the previous practical task already exists there, you can open it and then refresh the list of CPU implementation files in the project.
5. Re-customize the `inst_ram` IP in the project.
6. Run the simulation in the myCPU verification project (once the simulation window is open, just click run all), and verify and debug the design until the simulation test passes.
7. Synthesize and implement the design in the myCPU verification project, generate the bitstream, and verify it on the board.

## Acceptance Criteria

- [ ] The Lab 10 test program (n1~n36, 36 feature points in total) passes simulation.
- [ ] On the board, both bicolor LEDs are green and the seven-segment display shows "2400 0024".

!!! tip "Implementation Hints"

    - Check the encoding and semantics of each instruction one by one against the [LoongArch32R instruction set manual](https://www.loongson.cn/uploads/images/2023041918122813624.%E9%BE%99%E8%8A%AF%E6%9E%B6%E6%9E%8432%E4%BD%8D%E7%B2%BE%E7%AE%80%E7%89%88%E5%8F%82%E8%80%83%E6%89%8B%E5%86%8C_r1p03.pdf);
    - For signed division, note that the quotient is truncated toward zero; implement the divide-by-zero and overflow cases (such as `0x80000000 / -1`) as the manual specifies;
    - While the multiply/divide unit is operating, the stall control in the pipeline can reuse the logic from Lab 8.
