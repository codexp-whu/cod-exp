# 实验7：不考虑相关冲突处理的简单流水线CPU

!!! info "原书参考"

    [《CPU设计实战：LoongArch版》5.1.1 实践任务7：不考虑相关冲突处理的简单流水线CPU](https://bookdown.org/loongson/_book3/chapter-simple-pipeline-cpu.html)

## 实验目标

- 将单周期 CPU 的数据通路切分为 IF / ID / EX / MEM / WB 五级，插入流水级寄存器。
- 理解流水线对吞吐率的提升及其代价（冲突）。
- 本实验**故意不处理**相关冲突，直观感受错误现象，为后续两个实验埋下伏笔。

## 知识背景

### 切分数据通路

把实验 6 的单周期通路按功能切五段：

```text
IF  取指    ：PC、指令存储器访问
ID  译码    ：指令域提取、控制信号生成、寄存器堆读
EX  执行    ：ALU 运算、下一 PC 决策（分支目标计算）
MEM 访存    ：数据存储器读写
WB  写回    ：写回寄存器堆
```

每级之间插入流水级寄存器，保存该级向下游传递的全部数据与控制信号。时钟沿一到，各级同时把结果推向下一级。

### 为什么"不处理冲突"

三条指令：

```asm
addi.w r1, r0, 1     # r1 在 WB 级才写回
add.w  r2, r1, r0    # 却在 ID 级就要读 r1
```

流水化后，读发生在写之前——读到的必然是旧值。本实验**明知故犯**：不检测、不处理，让 func 测试在流水线 CPU 上跑飞，观察错误现场。只有亲手见过冲突导致的错乱，实验 8、9 的阻塞与前递才不是纸上谈兵。

## 任务要求

1. 用 Chisel 实现五级流水线数据通路（各流水级寄存器携带的信号集合由你设计）；
2. **不做**任何相关冲突检测与处理；
3. 跑 func 测试，记录出错的第一条指令及现象；
4. 分析出错的直接原因（哪条指令读了还没写回的寄存器）。

## 验收标准

- [ ] 五级流水线结构正确，无冲突指令序列能正确执行；
- [ ] func 测试跑飞的现场被清晰记录（trace 比对输出 + 波形分析）；
- [ ] 提交源码与实验报告。
