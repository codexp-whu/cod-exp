# Lab 9: Resolving Hazards with Forwarding

!!! info "Reference in the Book"

    [*CPU Design in Practice: LoongArch Edition* 5.1.3 Practical Task 9: Resolving Hazards with Forwarding](https://bookdown.org/loongson/_book3/chapter-simple-pipeline-cpu.html#subsec-exp9)

## Objectives

- Use **forwarding (forward)** to improve how data dependencies are handled, reducing stalls and raising pipeline efficiency.

## Tasks

This practical task asks you to build on the CPU you implemented in Lab 8 and do the following:

Add appropriate data forwarding paths to reduce stalling.

!!! note "load-use dependency"

    The data of a `load` instruction does not arrive until the end of the MEM stage, while the instruction right behind it needs that data in the EX stage — forwarding cannot cover this one-cycle gap, so **a load-use dependency still requires a one-cycle stall**. Almost all other results produced by the ALU can be resolved by forwarding.

!!! info "Select EXP9 as the test program"

## Steps

1. Copy the code of the CPU you implemented into the `mycpu_env/myCPU/` directory.
2. Edit the func configuration file, `mycpu_env/func/include/test_config.h`, to select the exp9 configuration, then compile it. (`make EXP=9`)
3. Open the `gettrace` project, `mycpu_env/gettrace/gettrace.xpr`. (The IP cores in this Vivado project were created with Vivado 2019.2; if you open it with a newer version of Vivado, please refer to the Lab 5 environment section to upgrade the IP cores.) Run the `gettrace` project's simulation (once the simulation window is open, just click run all and wait for the simulation to finish) to generate a new reference trace file `golden_trace.txt` (`mycpu_env/gettrace/golden_trace.txt`). The simulation has to run to completion before `golden_trace.txt` holds its full contents.
4. Go into the `mycpu_env/soc_verify/soc_bram/run_vivado/` directory and start the project that verifies myCPU. If no project has been created in that directory yet, use the `create_project.tcl` file there to create one. If a project created for the previous practical task already exists there, you can open it and then refresh the list of CPU implementation files in the project.
5. Re-customize the `inst_ram` IP in the project.
6. Run the simulation in the myCPU verification project (once the simulation window is open, just click run all), and verify and debug the design until the simulation test passes.
7. Synthesize and implement the design in the myCPU verification project, generate the bitstream, and verify it on the board.

## Acceptance Criteria

- [ ] The Lab 9 test program passes simulation.
- [ ] On the board, both bicolor LEDs are green and the seven-segment display shows `1400 0014`.
