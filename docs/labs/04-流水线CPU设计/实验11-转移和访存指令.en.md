# Lab 11: Adding Branch and Memory Access Instructions

!!! info "Reference in the Book"

    [*CPU Design in Practice: LoongArch Edition* 6.1.2 Practical Task 11: Adding Branch and Memory Access Instructions](https://bookdown.org/loongson/_book3/chapter-add-more-user-instr.html#subsec-exp11)

## Objectives

- Add branch instructions and memory access instructions to the pipelined CPU you already have.

## Tasks

This practical task asks you to build on the CPU you implemented in Lab 10 and do the following:

Add the branch instructions: **blt, bge, bltu, bgeu**.

Add the memory access instructions: **ld.b, ld.h, ld.bu, ld.hu, st.b, st.h**.

!!! warning "Byte enables"
    - `ld.b`/`ld.bu`/`ld.h`/`ld.hu` must be **sign/zero extended** after the read; `st.b`/`st.h` must generate the correct **byte write enable** on `data_sram_we` and must not disturb the other bytes of the same word.

!!! info "Select EXP11 as the test program"

## Steps

1. Copy the code of the CPU you implemented into the `mycpu_env/myCPU/` directory.
2. Edit the func configuration file, `mycpu_env/func/include/test_config.h`, to select the exp11 configuration, then compile it. (`make EXP=11`)
3. Open the `gettrace` project, `mycpu_env/gettrace/gettrace.xpr`. Run the `gettrace` project's simulation (once the simulation window is open, just click run all and wait for the simulation to finish) to generate a new reference trace file `golden_trace.txt` (`mycpu_env/gettrace/golden_trace.txt`). The simulation has to run to completion before `golden_trace.txt` holds its full contents.
4. Go into the `mycpu_env/soc_verify/soc_bram/run_vivado/` directory and start the project that verifies myCPU. If no project has been created in that directory yet, use the `create_project.tcl` file there to create one. If a project created for the previous practical task already exists there, you can open it and then refresh the list of CPU implementation files in the project.
5. Re-customize the `inst_ram` IP in the project.
6. Run the simulation in the myCPU verification project (once the simulation window is open, just click run all), and verify and debug the design until the simulation test passes.
7. Synthesize and implement the design in the myCPU verification project, generate the bitstream, and verify it on the board.

## Acceptance Criteria

- [ ] The Lab 11 test program (n1~n46, 46 feature points in total) passes simulation.
- [ ] On the board, both bicolor LEDs are green and the seven-segment display shows "2E00 002E".

!!! tip "Implementation Hints"

    At this point the CPU supports 46 user-mode instructions in total. Once you are done, we suggest you go through the decode table and confirm that every instruction's control signals (write-back enable, ALU operation, immediate type, memory access enable, branch decision) are complete and free of conflicts.
