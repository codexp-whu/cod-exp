# 实验9：前递技术解决相关引发的冲突

!!! info "原书参考"

    [《CPU设计实战：LoongArch版》5.1.3 实践任务9：前递技术解决相关引发的冲突](https://bookdown.org/loongson/_book3/chapter-simple-pipeline-cpu.html)

## 实验目标

- 实现**前递（forwarding / bypass）网络**：把流水线中尚未写回的结果直接送回需要它的级。
- 缩小阻塞范围：多数数据相关不再需要阻塞，性能显著提升。
- func 测试保持全部通过，并对比实验 8 的阻塞次数。

## 知识背景

### 前递的原理

相关指令的运算结果其实**早已算出**——在 EX 级末尾，它只是还没走到 WB 级写回寄存器堆。前递网络搭一条"抄近路"：

```text
EX/MEM 级的结果 ──┐
MEM/WB 级的结果 ──┼── 多路选择 ──→ EX 级的 ALU 输入
寄存器堆读出    ──┘
```

ID 级读出的操作数只是默认来源；检测到 EX 级输入与流水线中流转的目的寄存器匹配时，多路选择器切换到前递来源。

### 仍然需要阻塞的场合

前递不是万能的：

- **load-use 相关**：load 的数据 MEM 级末才可用，紧跟其后要用它的指令在 EX 级就需要——差一拍，前递够不着，仍需阻塞一拍；
- 其余 ALU 相关基本都能被前递化解。

因此实验 9 的完整方案 = **前递网络 + 精简后的阻塞**（只处理 load-use）。

### 检测与前递的配合

前递条件与实验 8 的阻塞条件同源，但粒度更细：要区分结果来自哪一级（EX/MEM 还是 MEM/WB），离得近的优先级高（最新结果）。多路选择信号的优先级设计是本实验的易错点。

## 任务要求

1. 实现 EX 级输入的前递多路选择与匹配检测；
2. 将阻塞条件精简为仅覆盖前递无法化解的相关（load-use）；
3. func 测试全部通过；
4. 对比实验 8：统计阻塞次数的下降，估算性能提升。

## 验收标准

- [ ] func 测试全部通过；
- [ ] 前递优先级正确（ newest result wins ），无错误前递；
- [ ] 提交源码与实验报告，含实验 8/9 阻塞次数对比表。
