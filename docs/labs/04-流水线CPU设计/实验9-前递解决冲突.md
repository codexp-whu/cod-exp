# 实验9：前递技术解决相关引发的冲突

!!! info "原书参考"

    [《CPU设计实战：LoongArch版》5.1.3 实践任务9：前递技术解决相关引发的冲突](https://bookdown.org/loongson/_book3/chapter-simple-pipeline-cpu.html#subsec-exp9)

## 实验目标

- 用**前递（forward）**技术优化数据相关的处理，减少阻塞，提升流水线效率。

## 实验内容

本实践任务要求在实验八实现的CPU基础上完成以下工作：

加入适当的数据前递通路来减少阻塞。

!!! note "load-use 相关"

    load 指令的数据要到 MEM 级末才能得到，紧随其后使用其结果的指令在 EX 级就需要该数据——这一拍差距是前递补不上的，**load-use 相关仍需保留一拍阻塞**。其余由 ALU 产生的结果基本都能通过前递化解。

!!! info "测试程序请选择EXP9"

## 实验步骤

1. 将所实现CPU的代码更新至`mycpu_env/myCPU/`目录中。
2. 修改func配置文件——`mycpu_env/func/include/test_config.h`，选择exp9的配置，编译。（`make EXP=9`）
3. 打开`gettrace` 工程——`mycpu_env/gettrace/gettrace.xpr`。（该Vivado工程中的IP核是使用Vivado2019.2创建的，如果使用更高版本的Vivado打开，请参考实验五实验环境介绍进行IP核升级。）运行`gettrace` 工程的仿真（进入仿真界面后，直接点击run all等待仿真运行完成），生成新的参考trace文件`golden_trace.txt`（`mycpu_env/gettrace/golden_trace.txt`）。要等仿真运行完成，`golden_trace.txt`才有完整的内容。
4. 进入 `mycpu_env/soc_verify/soc_bram/run_vivado/` 目录下启动验证myCPU的工程。如果该目录下尚未创建工程，请利用该目录下的 `create_project.tcl` 文件创建工程。如果该目录下已有前一实践任务创建过的工程，可以在打开工程后，更新项目中CPU实现文件的列表。
5. 对工程中的`inst_ram`重新定制。
6. 在验证myCPU的工程中运行仿真（进入仿真界面后，直接点击run all），进行功能验证与调试，直至仿真测试通过。
7. 在验证myCPU的工程中综合实现后生成bit流文件，进行上板验证。

## 验收标准

- [ ] 实验9 测试程序仿真PASS。
- [ ] 上板两个双色LED全为绿色，数码管显示`1400 0014`。
