# 实验11：转移指令和访存指令添加

!!! info "原书参考"

    [《CPU设计实战：LoongArch版》6.1.2 实践任务11：转移指令和访存指令添加](https://bookdown.org/loongson/_book3/chapter-add-more-user-instr.html)

## 实验目标

- 扩展转移指令族：条件分支（`beq`/`bne`/`blt`/`bge`…）、无条件跳转（`b`/`bl`/`jirl`），理解 LoongArch 的 **延迟槽**。
- 扩展访存指令族：`ld.b/h/w`、`ld.bu/hu`、`st.b/h/w`，处理**非对齐粒度访存**与符号扩展。
- 补全用户态指令集，通过全量 func 测试。

## 知识背景

### 延迟槽：LoongArch 最重要的"坑"

LoongArch 规定：**分支跳转指令之后的那一条指令，无论跳不跳，都会先执行**——它就是延迟槽。这源自 MIPS 时代早期的流水线设计，如今成了软件可见的架构约定：

- 汇编器和编译器会自动填充延迟槽（复制有效指令或填 `nop`）；
- 你的 CPU **必须**实现它：分支在 EX 级判定跳转时，IF 已经取了下一条——恰好就是延迟槽指令，顺势执行即可；
- 但**再**下一条才切换到目标地址。控制冒险的冲刷逻辑必须精确区分"延迟槽指令（保留）"与"错取的指令（冲刷）"。

### 非对齐粒度访存

`ld.b` 只读 1 字节，`ld.h` 读 2 字节且地址应半字对齐：

- 写回前需要按地址低位**字节对齐/符号扩展**；
- store 侧同理，需要**字节使能**：`st.b` 只写 1 字节，不能波及同字的其他字节；
- 大端小端、`ld.bu` 零扩展与 `ld.b` 符号扩展的差别，都是 func 测试的重点。

## 任务要求

1. 实现全部转移指令，正确处理延迟槽与分支冲刷；
2. 实现全部访存指令，处理字节/半字粒度与符号扩展；
3. 全量 func 测试通过；
4. 检查前递网络覆盖新指令：分支的比较源、访存的地址与数据都可能来自近期结果。

## 验收标准

- [ ] 全量 func 测试通过；
- [ ] 延迟槽行为正确（错取指令的冲刷不误伤延迟槽指令）；
- [ ] 字节/半字访存的符号扩展与字节使能正确；
- [ ] 提交源码与实验报告。
