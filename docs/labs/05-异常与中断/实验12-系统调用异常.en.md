# Lab 12: Adding System Call Exception Support

!!! info "Reference in the Book"

    [*CPU Design in Practice: LoongArch Edition*, 7.1.1 Practical Task 12: Adding System Call Exception Support](https://bookdown.org/loongson/_book3/chapter-support-exception.html#subsec-exp12)

## Objectives

- Add CSR registers and CSR access instructions to the CPU, implement the syscall system call exception and the ertn return from exception, and support the complete trap—handle—return loop.

## Tasks

In this practical task you build on the CPU you completed in Lab 11 and do the following:

- Add the CSR access instructions to the CPU: **csrrd, csrwr, csrxchg, ertn**.
- Add the control status registers to the CPU: **CRMD, PRMD, ESTAT, ERA, EENTRY, SAVE0~3**.
- Add the **syscall** instruction to the CPU, implementing support for the system call exception.

!!! warning "Precise Exceptions"

    Exception response requirements: when an exception occurs, ERA records the PC of the instruction that triggered it, ESTAT records the exception code (Ecode 0x0B for syscall), the privilege level switches to PLV0, and the PC jumps to EENTRY; `ertn` restores the PC from ERA and returns. Several instructions in the pipeline may carry an exception flag at the same time, so you must guarantee that "the effects of instructions before the exception take effect and the effects of instructions after it do not".

!!! info "Select EXP12 as the test program"

## Steps

1. Update the code of your CPU implementation into the `mycpu_env/myCPU/` directory.
2. Edit the func configuration file, `mycpu_env/func/include/test_config.h`: select the exp12 configuration and compile. (`make EXP=12`)
3. Open the `gettrace` project, `mycpu_env/gettrace/gettrace.xpr`. Run the simulation of the `gettrace` project (once the simulation window opens, just click run all and wait for it to finish) to generate a new reference trace file, `golden_trace.txt` (`mycpu_env/gettrace/golden_trace.txt`). The simulation has to run to completion before `golden_trace.txt` holds its full contents.
4. Go to the `mycpu_env/soc_verify/soc_bram/run_vivado/` directory and launch the project that verifies myCPU. If no project has been created in that directory yet, use the `create_project.tcl` file there to create one. If a project from the previous practical task already exists there, you can open it and update the list of CPU implementation files in the project.
5. Re-customize `inst_ram` in the project.
6. Run the simulation in the myCPU verification project (once the simulation window opens, just click run all) and verify and debug the design until the simulation passes.
7. Run synthesis and implementation in the myCPU verification project, generate the bitstream file, and verify on the board.

## Acceptance Criteria

- [ ] The Lab 12 test program (n1~n47, 47 feature points in total) passes in simulation.
- [ ] On the board both bicolor LEDs are green, and the seven-segment display shows "2F00 002F".

!!! tip "Implementation Hints"

    - The address of each CSR and the meaning of each field are as given in the [LoongArch32R instruction set manual](https://www.loongson.cn/uploads/images/2023041918122813624.%E9%BE%99%E8%8A%AF%E6%9E%B6%E6%9E%8432%E4%BD%8D%E7%B2%BE%E7%AE%80%E7%89%88%E5%8F%82%E8%80%83%E6%89%8B%E5%86%8C_r1p03.pdf);
    - `csrwr` must return the **old value** to rd at the same time as it writes the new value; `csrxchg` exchanges bits one by one according to the mask in rj;
    - A CSR write and a later `csrrd` that reads the same register number are dependent on each other, so make sure this works together with the forwarding and stalling logic.
