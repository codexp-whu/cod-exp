# Lab 13: Adding Support for Other Exceptions

!!! info "Reference in the Book"

    [*CPU Design in Practice: LoongArch Edition*, 7.1.2 Practical Task 13: Adding Support for Other Exceptions](https://bookdown.org/loongson/_book3/chapter-support-exception.html#subsec-exp13)

## Objectives

- Add support for more exceptions and interrupts to the CPU, completing the precise-exception framework.

## Tasks

In this practical task you build on the CPU you completed in Lab 12 and do the following:

- Add exception support to the CPU: **instruction fetch address error (ADEF), address misalignment (ALE), breakpoint (BRK), instruction not found (INE)**.
- Add interrupt support to the CPU: **2 software interrupts, 8 hardware interrupts and the timer interrupt**.
- Add the control status registers to the CPU: **ECFG, BADV, TID, TCFG, TVAL, TICLR**.
- Add the counter read instructions to the CPU: **rdcntvl.w, rdcntvh.w, rdcntid**.

!!! warning "When to Take an Interrupt"

    Interrupts are asynchronous events, but they must be taken at an **instruction boundary**, without interrupting an instruction that has already entered the pipeline. A common approach is to tag the instruction with a "carries an interrupt" flag as it is fetched; if the interrupt is still pending when that instruction commits, the CPU responds to it as it would to an exception, and the instructions behind it are flushed. Whether an interrupt is enabled or masked is decided jointly by CRMD.IE, ECFG.LIE and ESTAT.IS.

## Steps

1. Update the code of your CPU implementation into the `mycpu_env/myCPU/` directory.
2. Edit the func configuration file, `mycpu_env/func/include/test_config.h`: select the exp13 configuration and compile. (`make EXP=13`)
3. Open the `gettrace` project, `mycpu_env/gettrace/gettrace.xpr`. Run the simulation of the `gettrace` project (once the simulation window opens, just click run all and wait for it to finish) to generate a new reference trace file, `golden_trace.txt` (`mycpu_env/gettrace/golden_trace.txt`). The simulation has to run to completion before `golden_trace.txt` holds its full contents.
4. Go to the `mycpu_env/soc_verify/soc_bram/run_vivado/` directory and launch the project that verifies myCPU. If no project has been created in that directory yet, use the `create_project.tcl` file there to create one. If a project from the previous practical task already exists there, you can open it and update the list of CPU implementation files in the project.
5. Re-customize `inst_ram` in the project.
6. Run the simulation in the myCPU verification project (once the simulation window opens, just click run all) and verify and debug the design until the simulation passes.
7. Run synthesis and implementation in the myCPU verification project, generate the bitstream file, and verify on the board.

## Acceptance Criteria

- [ ] The Lab 13 test program (n1~n58, 58 feature points in total) passes in simulation.
- [ ] On the board both bicolor LEDs are green, and the seven-segment display shows "3A00 003A".

!!! tip "Implementation Hints"

    - Each exception is detected at a different point: ADEF during instruction fetch, INE/BRK during decode, and ALE during memory access (ALE must also record the offending address in BADV). The exception flags need to travel along with the pipeline stages and be arbitrated in instruction order at the commit point;
    - Timer: TCFG configures the timer and selects its period, TVAL reflects the current count, and TICLR is used to clear the timer interrupt.
