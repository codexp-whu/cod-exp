# 实验12：添加系统调用异常支持

!!! info "原书参考"

    [《CPU设计实战：LoongArch版》7.1.1 实践任务12：添加系统调用异常支持](https://bookdown.org/loongson/_book3/chapter-support-exception.html#subsec-exp12)

## 实验目标

- 为 CPU 添加 CSR 寄存器和 CSR 访问指令，实现 syscall 系统调用异常与 ertn 返回，支持"陷入—处理—返回"的完整闭环。

## 实验内容

本实践任务要求在实验十一实现的CPU基础上完成以下工作：

- 为CPU增加CSR访问指令：**csrrd、csrwr、csrxchg、ertn**。
- 为CPU增加控制状态寄存器：**CRMD、PRMD、ESTAT、ERA、EENTRY、SAVE0~3**。
- 为CPU增加**syscall**指令，实现系统调用异常支持。

!!! warning "精确异常"

    异常响应要求：异常发生时，ERA 记录触发指令的 PC，ESTAT 记录异常编码（syscall 为 Ecode 0x0B），特权级切换到 PLV0，PC 跳转到 EENTRY；`ertn` 从 ERA 恢复返回。流水线中可能同时有多条指令带异常标志，必须保证"异常前的指令效果生效、异常后的指令不生效"。

!!! info "测试程序请选择EXP12"

## 实验步骤

1. 将所实现CPU的代码更新至`mycpu_env/myCPU/`目录中。
2. 修改func配置文件——`mycpu_env/func/include/test_config.h`，选择exp12的配置，编译。（`make EXP=12`）
3. 打开`gettrace` 工程——`mycpu_env/gettrace/gettrace.xpr`。运行`gettrace` 工程的仿真（进入仿真界面后，直接点击run all等待仿真运行完成），生成新的参考trace文件`golden_trace.txt`（`mycpu_env/gettrace/golden_trace.txt`）。要等仿真运行完成，`golden_trace.txt`才有完整的内容。
4. 进入 `mycpu_env/soc_verify/soc_bram/run_vivado/` 目录下启动验证myCPU的工程。如果该目录下尚未创建工程，请利用该目录下的 `create_project.tcl` 文件创建工程。如果该目录下已有前一实践任务创建过的工程，可以在打开工程后，更新项目中CPU实现文件的列表。
5. 对工程中的`inst_ram`重新定制。
6. 在验证myCPU的工程中运行仿真（进入仿真界面后，直接点击run all），进行功能验证与调试，直至仿真测试通过。
7. 在验证myCPU的工程中综合实现后生成bit流文件，进行上板验证。

!!! tip "实现提示"

    - 各 CSR 的地址与各域的含义以[LoongArch32R指令集手册](https://www.loongson.cn/uploads/images/2023041918122813624.%E9%BE%99%E8%8A%AF%E6%9E%B6%E6%9E%8432%E4%BD%8D%E7%B2%BE%E7%AE%80%E7%89%88%E5%8F%82%E8%80%83%E6%89%8B%E5%86%8C_r1p03.pdf)为准；
    - `csrwr` 写入新值的同时要把**旧值**返回给 rd；`csrxchg` 按 rj 的掩码逐位交换；
    - CSR 写与后续 `csrrd` 读同号寄存器之间存在相关，注意与前递/阻塞逻辑的配合。
