# 实验12：添加系统调用异常支持

!!! info "原书参考"

    [《CPU设计实战：LoongArch版》7.1.1 实践任务12：添加系统调用异常支持](https://bookdown.org/loongson/_book3/chapter-support-exception.html)

## 实验目标

- 理解异常响应的标准动作：记录现场 → 跳转异常入口。
- 引入 CSR（控制状态寄存器），实现 `csrrd`/`csrwr`/`csrxchg` 访问指令。
- 实现 `syscall` 触发的异常与 `ertn` 返回，跑通"用户态陷入—处理—返回"的完整闭环。

## 知识背景

### 异常响应要做什么

以 `syscall` 为例，异常发生时 CPU 必须原子地完成：

1. **记录现场**：触发异常的指令地址写入 `CSR.CRMD` 相关字段（PC 保存）；
2. **标记来源**：异常编号写入 `CSR.ESTAT` 的 Ecode 子域（syscall 为 `0x0B`）；
3. **切换状态**：CRMD 的 PLV（特权级）切到 0，DA/PG 切换为直接地址翻译；
4. **跳转**：PC ← `CSR.EENTRY`（异常入口地址）。

`ertn` 则做逆操作：从 `ERA` 恢复 PC、恢复特权级，回到断点继续执行。

### 精确异常：流水线的难点

异常指令可能出现在任何一级；同拍还可能多条指令都触发异常。精确异常要求：**异常前的指令效果全部生效，异常后的指令不得生效**。你需要一套异常"汇总—排序—提交"逻辑，以指令的流水位置决定优先级，并配合冲刷，把异常后的流水线清空。

### CSR 引入的冲突

CSR 写在 EX/WB 级生效，而后续异常判定要读它——CSR 与异常通路之间同样存在相关，需要类似前递/阻塞的处理，这是常见的隐藏 bug 点。

## 任务要求

1. 实现 CSR 寄存器（本实验至少：CRMD、PRMD、ECFG、ESTAT、ERA、EENTRY）及 `csrrd`/`csrwr`/`csrxchg` 指令；
2. 实现 `syscall` 异常的检测、记录与响应，以及 `ertn` 返回；
3. 编写/使用含"陷入—修改 CSR—返回"的测试程序验证闭环；
4. 前递网络覆盖 CSR 写→读的相关。

## 验收标准

- [ ] 系统调用闭环测试通过：`syscall` 进入处理程序、`ertn` 精确回到断点；
- [ ] 异常时刻的流水线状态干净（异常后指令无副作用）；
- [ ] 提交源码与实验报告。
