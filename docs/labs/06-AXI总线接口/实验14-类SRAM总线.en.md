# Lab 14: Adding SRAM-Like Bus Support

!!! info "Reference in the Book"

    [*CPU Design in Practice: LoongArch Edition*, 8.1.1 Practical Task 14: Adding SRAM-Like Bus Support](https://bookdown.org/loongson/_book3/chapter-axi-bus.html#subsec-exp14)

## Objectives

- Convert the CPU's external SRAM interface into an **SRAM-like bus interface** with a handshake mechanism, so that the CPU can tolerate memory-access waits.

## Environment

!!! warning

    The verification environment for this lab **no longer uses the `soc_bram/` subdirectory — use the `soc_hs_bram/` subdirectory instead**!

Now that the instruction RAM and data RAM the CPU accesses have changed from ordinary block RAM to **block RAM with a handshake mechanism**, the verification environment has been adjusted accordingly: the `gettrace/`, `func/`, and `myCPU/` subdirectories keep their locations and purposes unchanged; the only difference is that under `soc_verify/` you now use the `soc_hs_bram/` subdirectory, whose files are organized along the same lines as those in `soc_bram/`:

```
|--mycpu_env/                Root directory of the lab environment.
|--gettrace/                 The part that generates the reference trace.
|--func/                     Functional verification test programs used by the lab tasks.
|--myCPU/                    The RTL code of your own CPU.
|--soc_verify/               The SoC system verification environment for your own CPU
   |--soc_hs_bram/           The verification environment for when the CPU's external interface connects to handshaking block RAM.
      |--rtl/                SoC_Lite design source directory.
      |  |--soc_lite_top.v   Top-level file of SoC_Lite.
      |  |--CONFREG/         The confreg module, used to access the CPU and board peripherals such as the seven-segment display and the DIP switches.
      |  |--BRIDGE/          A 1×2 bridge module: the CPU's data sram interface accesses confreg and data_ram at the same time.
      |  |--ram_wrap/        The RAM module wrapped in an SRAM-like interface.
      |  |--xilinx_ip/       Customized Xilinx IP, including clk_pll, inst_ram, and data_ram.
      |--testbench/          Functional simulation verification platform.
      |  |--mycpu_tb.v       Functional simulation top level; this module captures debug information and compares it against golden_trace.txt.
      |--run_vivado/         The run directory of the Vivado project.
         |--constraints/     Design constraints for the Vivado project.
         |--mycpu_hs_bram_prj/ Directory holding the Vivado project files.
```

## Tasks

In this practical task you build on the CPU you completed in Lab 13 and do the following:

- Change the CPU's external interface to an **SRAM-like bus interface**: on top of the existing sram interface signals, add the handshake signals `inst_sram_addr_ok`, `inst_sram_data_ok`, `data_sram_addr_ok`, and `data_sram_data_ok`. Once a request has been issued, it may take several cycles for a response to arrive, and the CPU pipeline must be able to freeze correctly while it waits.
- Complete the **random-delay functional verification of the func program for exp14** in the SoC verification environment built on handshaking block RAM.

!!! warning "Random delay"

    The RAM access delay in the verification environment is **random** (generated by a pseudo-random number generator in `confreg.v`). In simulation the initial random seed is specified by the `RANDOM_SEED` macro in `confreg.v`; on the board it is specified by the DIP switch state sampled during reset. Make sure your CPU works correctly under any delay.

!!! info "Select EXP14 as the test program"

## Steps

1. Update the code of your CPU implementation into the `mycpu_env/myCPU/` directory.
2. Edit the func configuration file, `mycpu_env/func/include/test_config.h`: select the exp14 configuration and compile. (`make EXP=14`)
3. Open the `gettrace` project, `mycpu_env/gettrace/gettrace.xpr`. Run the simulation of the `gettrace` project (once the simulation window opens, just click run all and wait for it to finish) to generate a new reference trace file, `golden_trace.txt` (`mycpu_env/gettrace/golden_trace.txt`). The simulation has to run to completion before `golden_trace.txt` holds its full contents.
4. Go to the `mycpu_env/soc_verify/soc_hs_bram/run_vivado/` directory and launch the project that verifies myCPU. If no project has been created in that directory yet, use the `create_project.tcl` file there to create one.
5. Re-customize `inst_ram` in the project.
6. Run the simulation in the myCPU verification project (once the simulation window opens, just click run all) and verify and debug the design until the simulation passes.
7. Run synthesis and implementation in the myCPU verification project, generate the bitstream file, and verify on the board.

??? tips "Board verification requirements"

    On the board you should **"toggle the DIP switches at random and then press reset"**, and the CPU must pass the 58 feature points of the func program for exp14.

    The DIP switch state during reset serves as the initial random seed and determines the number of random delay cycles for instruction fetch and memory access. The CPU's execution state differs greatly from seed to seed, and hitting an error under some particular seed is very common. If you find that "the simulation passes but the board does not", set `RANDOM_SEED` in `confreg.v` to the failing seed value and reproduce the failure in simulation to debug it. When running on the board you should cover all three delay types as far as possible — **long delay, short delay and no delay** (for the mapping between seeds and delay types, see Figure 8.1 in the book).

    After reset the DIP switches serve a second purpose: controlling the rate at which the seven-segment display accumulates, so that you can adjust the pace at which you observe the test.

## Acceptance Criteria

- [ ] The Lab 14 test program (n1~n58, 58 feature points in total) passes in simulation.
- [ ] On the board both bicolor LEDs are green, and the seven-segment display shows "3A00 003A"; the design also passes for several different random seeds (toggling the DIP switches and pressing reset repeatedly).
