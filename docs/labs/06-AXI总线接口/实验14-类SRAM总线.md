# 实验14：添加类SRAM总线支持

!!! info "原书参考"

    [《CPU设计实战：LoongArch版》8.1.1 实践任务14：添加类SRAM总线支持](https://bookdown.org/loongson/_book3/chapter-axi-bus.html)

## 实验目标

- 把 CPU 对指令/数据存储器的直接访问，改造成**请求—应答握手**的总线形式（类 SRAM 接口）。
- 理解握手协议下 CPU 必须能**容忍等待**：请求不保证当拍应答。

## 知识背景

### 从"直接连线"到"总线请求"

此前 CPU 的取指、访存如同直接连线：给地址、当拍拿数据。真实系统的存储器有自己的时序——总线协议用**握手**描述这一不确定性：

```text
CPU → 请求：addr、we、wdata、（valid=1）
CPU ← 应答：rdata、（ready=1）
```

- `valid` 表示 CPU 已发出有效请求；
- `ready` 表示从端已应答，本拍请求-应答同时成立，事务完成；
- 两次事务之间，请求方**可能等待任意拍**。

### 对 CPU 的影响

流水线各级的存储访问（IF 取指、MEM 访存）一旦改为总线：

- 等待应答期间，对应流水级必须**冻结**（想想实验 8 的阻塞逻辑，本质相同）；
- 译码出的访存请求信号要经过状态机管理：发请求 → 等应答 → 收数据 → 放行。

类 SRAM 总线是通往 AXI 的过渡台阶：它有握手而无通道划分，先把"CPU 能等"这件事做对，AXI 的复杂度才好驾驭。

## 任务要求

1. 设计类 SRAM 总线接口信号（请求/应答、读写、掩码等）；
2. 将 IF 级取指与 MEM 级访存改造为经总线访问，实现等待状态下的流水线冻结；
3. 功能测试（如总线恒当拍应答）行为与改造前一致。

## 验收标准

- [ ] 握手逻辑正确：无请求丢失、无重复应答、应答数据正确采样；
- [ ] 等待期间流水线冻结行为正确（无指令丢失或重复执行）；
- [ ] 提交源码与实验报告。
