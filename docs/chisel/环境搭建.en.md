# Environment Setup

In this section you will use the Mill build tool bundled with the course template to compile a Chisel module under Linux and generate SystemVerilog.

## Development Environment

We strongly recommend doing Chisel development under **WSL2 or a physical Linux machine**. The instructions below use WSL2 + Ubuntu as the example.


!!! tip "Choosing a hardware development environment"
    Write your Chisel code under Linux.
    

## Installing WSL2 / a Linux VM / a physical Linux machine
  Look up the installation instructions for your own setup.

## Installing the Basic Tools

All of the commands below are run in an Ubuntu/Linux terminal. Start by updating the package index:

```bash
sudo apt update
```

Install the JDK, Git, and the local build tools:

```bash
sudo apt install -y openjdk-17-jdk git curl
sudo apt install -y build-essential
```

Then install the RTL simulation and waveform tools this course uses:

```bash
sudo apt install -y verilator gtkwave
```

What each of these tools does for the course is fairly simple:

| Tool | Role in the course |
|------|----------------|
| JDK 17 | Run Scala and Chisel |
| Git | Version control for your code |
| `g++`, `make` | Compile the C++ simulation model that Verilator generates |
| Verilator | Simulate the generated SystemVerilog |
| GTKWave | Open VCD waveform files |

Check the installation with the version commands:

``` bash
java -version
git --version
g++ --version
verilator --version
```

If all of these commands print version information, the system tools are installed. GTKWave usually opens directly on Windows 11 with WSLg; if you cannot open a graphical window inside a virtual machine, first check that the VM desktop and graphics support are working properly.

## A Minimal Chisel Project

For the labs we use the Chisel template provided by **OSCPU**, which already includes test and generation scripts and works out of the box.


1. Clone the project
``` bash
git clone https://github.com/OSCPU/chisel-playground.git

```
2. Install Mill
``` bash
cd chisel-playground

 curl -L https://repo1.maven.org/maven2/com/lihaoyi/mill-dist/1.1.8/mill-dist-1.1.8-mill.sh -o mill
 chmod +x mill
 ./mill version
```
Running this downloads the dependencies automatically. When you see the version number printed, the environment is set up correctly.
3. Test and generate Verilog
``` bash
// 测试
make test

// 生成verilog
make verilog

```
The generated Verilog files end up in the **build** folder.

## Project Structure
```
chisel-playground/
├── .github/workflows/     # GitHub Actions CI configuration
├── src/                   # Source code directory
│   ├── GCD.scala          # GCD module implementation
│   ├── DecoupledGCD.scala # GCD module with a Decoupled interface
│   └── Elaborate.scala    # Top-level wrapper used to generate Verilog
├── test/
│   └── src/
│       └── GCDSpec.scala  # Test code for the GCD module
├── .gitignore             # Git ignore configuration
├── .scalafmt.conf         # Scala code formatting configuration
├── Makefile               # Wraps the common Mill commands
├── build.mill             # Mill build definition file
└── README.md              # Project documentation
```

!!! tip
    If you need to replace the GCD module, open src/Elaborate.scala, which is the entry point for generating Verilog. **You need to replace the new GCD() in it with new MyALU() (or your own module name)**!
    Any new Chisel files you add can simply go in the src folder.
