# From Verilog to Chisel

These notes are built around the five-stage pipeline CPU, and cover only the Scala and Chisel you will use along the way.

We suggest working through them in this order:

1. Get the environment working first, and confirm that you can generate Verilog.
2. Learn the basic syntax, so that you can write small modules.
3. Learn module testing and timing tests, and keep verifying as you go.
4. Then move on to pipeline registers, forwarding, stalling, and flushing.

The examples that follow are set side by side with Verilog wherever possible.

## What Chisel Is

Chisel stands for **Constructing Hardware in a Scala Embedded Language**. It is a hardware construction library built on top of Scala, not a separate language unrelated to Scala.

The Chisel code you write first runs as a Scala program and constructs a circuit; the toolchain then generates **Verilog or SystemVerilog** from it. The result can still be handed to Verilator for RTL simulation, or to Vivado for simulation, synthesis, and implementation on an FPGA.

```text
Scala / Chisel source
        ↓
Run Scala, construct the circuit
        ↓
Generate Verilog / SystemVerilog
        ↓
Simulation, synthesis, running on the board
```

Two layers need to be kept apart here:

- Scala syntax such as `for`, `if`, classes, and functions usually executes **while the circuit is being generated**.
- Chisel constructs such as `Mux`, `when`, `Reg`, and `:=` describe the **hardware that gets generated**.

Mix the two stages up and your code may well compile, yet still generate a different circuit from the one you intended. The syntax chapters that follow return to this point.

## Why Use Chisel

A single-cycle CPU is small enough that wiring everything by hand is usually manageable. With a pipelined CPU, the problems grow quickly:

- Every pipeline register has to carry a batch of data and control signals.
- Adding one control signal often means editing several modules and inter-stage registers at the same time.
- Forwarding, stalling, and flushing make the top-level wiring complicated fast.
- Parameters such as bit width, number of stages, and queue depth tend to get scattered all over the code.

!!! tip 
    Chisel will not solve pipeline hazards for you, and it cannot guarantee that your microarchitecture is correct. What it mainly does is **generate repeated structures, organize related signals, and catch some connection and type problems at generation time**.


## A Few Comparisons First

You are not expected to follow the code below yet; just get a feel for how concise Chisel is.

### Multiplexer

Verilog usually reaches for `case`:

```verilog
always @(*) begin
    case (sel)
        2'd0: out = a;
        2'd1: out = b;
        2'd2: out = c;
        default: out = d;
    endcase
end
```

Chisel can write the selection as a table:

```scala
val out = MuxLookup(sel, d)(Seq(
  0.U -> a,
  1.U -> b,
  2.U -> c
))
```

Both snippets generate combinational selection logic. `MuxLookup` is not a software table lookup, and it does not search item by item at run time.

### Register File

Chisel's `Vec` can be indexed by a hardware signal, which makes it a good fit for describing a small register array:

```scala
val regs = RegInit(VecInit(Seq.fill(32)(0.U(32.W))))

val rdata1 = Mux(rs1 === 0.U, 0.U, regs(rs1))
val rdata2 = Mux(rs2 === 0.U, 0.U, regs(rs2))
```

The write port is still sequential logic:

```scala
when(wen && rd =/= 0.U) {
  regs(rd) := wdata
}
```

Here `when` is not a "sequential statement". A register write is generated because the assignment target `regs(rd)` comes from a `Reg`. The same `when` can also drive a `Wire`, and then it generates combinational logic.

### Passing Signals as a Group

Between pipeline stages you often need to carry the PC, the instruction, and a valid bit along together. Put them in a `Bundle` first:

```scala
class IfId extends Bundle {
  val valid = Bool()
  val pc    = UInt(32.W)
  val inst  = UInt(32.W)
}
```

Then save the whole group in a single register:

```scala
val ifId = RegInit(0.U.asTypeOf(new IfId))
val ifIdNext = WireDefault(ifId)

ifId := ifIdNext
```

To add a field, add it to the Bundle definition. The logic that produces this group of signals still needs the corresponding connection, and the compiler will flag any field you leave undriven.

## Design Problems You Still Have to Solve Yourself

Beginners tend to mistake "short code" for "simple hardware", but the two are not the same thing: short Chisel code still generates the same hardware structure.

- One line of multiplication still generates a multiplier.
- A `Vec` indexed by a hardware signal can still generate a very large multiplexer.
- A long combinational expression can still become a critical path.
- A `for` loop unrolls into hardware; it does not make one copy of that hardware automatically reused over several cycles.

!!! tip
    When you write Chisel you still have to care about bit width, timing, parallelism, and resources. Chisel mainly **changes how the code is organized and generated; it does not change these hardware constraints**.

!!! warning
    Always keep in mind that **different ways of writing Chisel generate different hardware structures!!!**
