    这一节中，你将接触到 Chisel 在 CPU 开发中的常用语法。刚开始觉得陌生、困难是正常的，按照讲义的内容将 Chisel 写法与 Verilog 写法对应起来，你会理解得更快！

!!! warning "抽象是为了更好地描述硬件，而非掩盖硬件"
    可能有同学认为 Chisel 抽象程度高，就可以完全用写软件的心态来编程。**请时刻谨记：Chisel 生成的依然是硬件电路！**
    适当的抽象（如封装 Bundle、使用生成器）能提升代码复用性，但绝不能违背硬件设计的底层逻辑（如时序、并行性、资源消耗）。
    写 Chisel 时，脑子里必须有一张电路图，避免写出综合出意外 Latch 或超长组合逻辑路径的"软件式代码"。

!!! warning "区分Scala数据类型和Chisel数据类型"
    虽然Chisel是Scala语言的一个库，但是**两者的数据类型不可混用**。

## Scala 速览

Chisel 是 Scala 的一个库，而不是一门独立语言——在你写 Chisel 之前，需要先了解几个最基础的 Scala 语法。

### `val` 与 `var`

```scala
val a = UInt(32.W)       // val：不可变引用——Chisel 硬件信号一律用 val
var sum = 0.U            // var：可变变量——仅用于 Scala 软件逻辑，不直接生成硬件
```

!!! warning "Chisel 中请避免使用var"
    **描述硬件的信号用 `val`，仅用于 Scala 元编程的临时变量才用 `var`。**
    
    如果把硬件信号声明为 `var` 并在后面重新赋值（`a = somethingElse`），你只是把 Scala 引用指向了另一个对象，**不会生成任何硬件更新逻辑**。想让硬件信号的值发生变化，必须用 `:=` 配合 `Reg`。


    **在Chisel中建议全部使用`val`**

### `class` 与 `new`
`class`可以创建多个类，且可以通过实例化被复用。
`new`不仅可以实例化类，也可以实例化Module（后文将仔细介绍Module）。
```scala
class MyBundle extends Bundle {     // 定义一个类
    val a = UInt(32.W)
}
val b = new MyBundle                // new 创建一个实例
val m = Module(new MyModule)        // 模块实例化也用 new
```

### `object`

`object` 在 Scala 中是**单例对象**——全局只有一份，非常适合放常量和配置参数：

```scala
object Config {
    val XLEN = 32
}
val a = UInt(Config.XLEN.W)   // 通过 Config.XLEN 引用
```

### `Seq`
`Seq`用于生成一个序列，而`Seq.fill`非常适合生成重复的序列，`Seq.tabulate`则适合根据索引生成同一模式的序列。
```scala
Seq(1.U, 2.U, 3.U)           // 创建一个序列
Seq.fill(32)(0.U(32.W))      // 生成 32 个 0.U(32.W) 的序列
Seq.tabulate(8)(i => i.U)    // 生成序列 [0.U, 1.U, ..., 7.U]
```


### `for` 循环

Chisel 中的 `for` 是 Scala 的循环语句，它在**电路生成阶段（elaboration）**执行——循环体会被展开成多条并行的硬件语句，而不是生成一个"串行循环"电路。

```scala
// 批量连线：给 32 个寄存器的写端口连上对应数据
for (i <- 0 until 32) {
    rf(i) := writeData(i)
}
// 等价于手写 32 行：
// rf(0) := writeData(0)
// rf(1) := writeData(1)
// ...
// rf(31) := writeData(31)
```

```scala
// 条件展开：只对满足条件的索引生成硬件
for (i <- 0 until 32 if i != 10) {
    regs(i) := 0.U  // 跳过第 10 个寄存器
}
```

```scala
// yield：用 for 生成一个 Seq
val portList = for (i <- 0 until 8) yield {
    val port = IO(Output(UInt(32.W)))
    port := count + i.U
    port                 // 返回port，即最终序列中存的是port
}
// portList 是一个 Seq[UInt]，包含 8 个已连线的输出端口
```

!!! warning "`for` 展开的是电路结构，不是时序行为"
    这是从 Verilog 转 Chisel 的同学极易误解的地方：
    
    ```scala
    // 错误理解：以为 for 循环会产生"串行累加"的行为
    var sum = 0.U
    for (i <- 0 until 4) {
        sum = sum + data(i)   // 实际综合出来是一个 4 输入的加法器树！
    }
    
    // 正确理解：for 只是帮你批量写代码，展开后是纯组合逻辑
    val sum = data(0) + data(1) + data(2) + data(3) 
    ```
    
    `for` 循环生成的硬件**全部并行存在**，没有"先执行第一次循环、再执行第二次"的概念。如果你需要时序上的循环（比如多周期除法器中的迭代），应该用状态机 + 计数器，而不是 `for`。

### `reduce`

`reduce` 是 Scala 集合上的高阶函数，它将序列中的元素**两两结合**，最终归约为一个结果。在 Chisel 中，`reduce` 会综合出树形组合逻辑，是多输入归约的标准写法。

```scala
// 多输入加法：将 8 个数相加，综合为加法器树
val sum = data.reduce(_ + _)
// 等价于：data(0) + data(1) + data(2) + ... + data(7)

// 多输入按位与：检测是否所有位都为 1
val allOnes = bitsVec.reduce(_ & _)

// 多输入按位或：检测是否有任意位为 1
val anyOne = bitsVec.reduce(_ | _)

// 多输入拼接
val combined = fields.reduce(Cat(_, _))
```

`reduce` 的语法说明：`_ + _` 是一个匿名函数，两个下划线分别代表"已经归约的结果"和"当前元素"。如果你熟悉 Python，它等价于 `functools.reduce(lambda a, b: a + b, data)`。


!!! tip "`reduce` vs `for`——用哪个？"
    | 场景 | 用什么 |
    |------|--------|
    | 把 N 个信号归约成一个（加法、按位与/或、拼接） | `reduce`——简洁，自动综合为树 |
    | 对 N 个信号做**互不依赖**的独立操作（连线、模块实例化） | `for`——每个循环体生成独立的硬件 |
    
    CPU 中典型的 `reduce` 用法：多级仲裁器中的优先级树、多标志位汇总为单个中断信号。

### `package`

当你把 ALU、译码器、寄存器堆等模块写在不同的 `.scala` 文件中时，需要用 `package` 来组织它们，并在其他文件中用 `import` 引用。

```scala
// 文件：src/main/scala/cpu/Alu.scala
package cpu              // 声明这个文件属于 cpu 包

import chisel3._
import chisel3.util._

class Alu extends Module {
    val io = IO(new Bundle {
        val a   = Input(UInt(32.W))
        val b   = Input(UInt(32.W))
        val op  = Input(UInt(4.W))
        val out = Output(UInt(32.W))
    })
    // 内部逻辑（具体语法在后续章节中学习）
    io.out := io.a + io.b
}
```

```scala
// 文件：src/main/scala/cpu/AluOp.scala
package cpu              // 同一个包，放常量定义

import chisel3._

object AluOp {
    val ADD = 0.U(4.W)
    val SUB = 1.U(4.W)
    // ...
}
```

```scala
// 文件：src/main/scala/cpu/Top.scala
package cpu              // 同一个包

import chisel3._
// 同一个包内的类和 object 不需要 import，直接用即可

class Top extends Module {
    val alu = Module(new Alu)          // 同一个包，直接使用
    alu.io.op := AluOp.ADD             // 同一个包，直接用 object 常量
}
```

如果不同包之间需要引用，则要用 `import` 显式导入：

```scala
// 文件：src/main/scala/soc/Top.scala
package soc

import chisel3._
import cpu.Alu          // 导入其他包中的类
import cpu.AluOp        // 导入其他包中的 object

class SocTop extends Module {
    val alu = Module(new Alu)
    alu.io.op := AluOp.ADD
}
```

!!! tip "CPU 项目的推荐包结构"
    对于五级流水线 CPU，建议把所有模块放在同一个 `cpu` 包下，这样包内的类和常量互相可见，不需要写一堆 `import`。当你的 CPU 需要对接外部 SoC 总线时，再用不同包来隔离。
    

### `import`

```scala
import chisel3._                // Chisel 核心库（UInt、Module、Bundle 等）
import chisel3.util._           // 工具库（Decoupled、Counter、MuxLookup 等）
import cpu.AluOp                // 导入自定义包中的常量
import cpu.{Alu, Decoder}       // 一次导入同一个包中的多个类
```

以上 Scala 知识已经足够你阅读和编写 Chisel 代码，在后续讲义中将反复出现。

## 数据类型

在 Verilog 中，一个信号是 `wire` 还是 `reg` 决定了它是线还是寄存器；至于它是无符号数、有符号数还是布尔值，则靠你自己约定。Chisel 在**类型层面**把这些区分清楚，让编译器帮你检查错误。

### 三种基本类型

| Chisel 写法 | 含义 | Verilog 等价 |
|------------|------|-------------|
| `UInt(32.W)` | 32 位无符号数 | `[31:0]`（默认无符号） |
| `SInt(32.W)` | 32 位有符号数（补码） | `signed [31:0]` |
| `Bool()` | 单比特布尔值 | 单比特 `wire` |

```scala
val a = UInt(32.W)      // 无符号 32 位
val b = SInt(32.W)      // 有符号 32 位
val c = Bool()          // 布尔值（等价于 UInt(1.W)，但语义更明确）
```

!!! note "为什么 Chisel 要在类型层面区分有符号/无符号？"
    在 Verilog 中写 SLT 指令时，你需要在比较前手动加 `$signed()`，一旦漏掉，比较结果就会按无符号处理——这种 bug 很难排查。
    
    Chisel 把"有符号/无符号"写进**类型本身**：`UInt` 的 `<` 自动按无符号比较，`SInt` 的 `<` 自动按有符号比较。你不再需要手工插入 `$signed()`，编译器帮你记住这件事。

### 常量定义

在 Verilog 中，你用 `` `define `` 宏或 `localparam` 给常数起名字，比如 `localparam ALU_ADD = 4'b0001;`。Chisel 中推荐用 Scala 的 `object` 来组织常量——类型安全、可复用、不会像宏一样全局污染。

#### object
使用`object`和`val`关键字即可定义普通常量集合。注意`object`是单例对象，不可实例化，也不可有同名对象。
```scala
object AluOp {
    val ADD  = 0.U(4.W)
    val SUB  = 1.U(4.W)
    val AND  = 2.U(4.W)
    val OR   = 3.U(4.W)
    val XOR  = 4.U(4.W)
    val SLT  = 5.U(4.W)
    val SLL  = 6.U(4.W)
    val SRL  = 7.U(4.W)
    val SRA  = 8.U(4.W)
}

object Opcode {
    val OPC_R   = "b0110011".U(7.W)
    val OPC_I   = "b0010011".U(7.W)
    val OPC_LW  = "b0000011".U(7.W)
    val OPC_SW  = "b0100011".U(7.W)
    val OPC_B   = "b1100011".U(7.W)
    val OPC_JAL = "b1101111".U(7.W)
}

// 使用：通过 object名.字段名 引用，常量的类型是 UInt(4.W)
val myOp = AluOp.ADD                // 相当于 myOp = 0.U(4.W)
val isAdd = (aluOp === AluOp.ADD)   // 和普通 UInt 一样用 === 比较
```

!!! tip "`object` 的使用"
    `object` 定义的常量有**确定的类型**（如 `UInt(4.W)`），编译器能在你误用时精确报错。

    为了让CPU更易维护，**建议将使用到的全局变量写在单独的文件中**。

#### ChiselEnum

当信号只有有限的几个取值时（如状态机状态），用 `ChiselEnum` 比裸 `UInt` 更安全、可读性更好：

```scala
import chisel3.util._

object State extends ChiselEnum {
    val IDLE, RUN, DONE = Value
}

// 枚举信号声明（Wire 讲解详见下一节）
val state = Wire(State())

// 比较——枚举常量和普通常量一样，直接用 === 比较
val isIdle = (state === State.IDLE)
val isRun  = (state === State.RUN)
val isDone = (state === State.DONE)
```

!!! note "什么时候用 `ChiselEnum`，什么时候用 `object` 常量？"
    | 场景 | 推荐 | 原因 |
    |------|------|------|
    | ALU 操作码、funct3/funct7 编码 | `object` + `val` | 这些是 RISC-V 规范中已经固定的编码，不会变化 |
    | 状态机状态 | `ChiselEnum` | 取值只有有限的几个，枚举能防止写出非法值 |
    | 配置参数（位宽、深度） | `object` + `val` | 纯整数，不需要硬件类型 |

### 字面量（常数）

在 Verilog 中，你可以直接写 `32'd0`、`32'hFF`。但是Chisel 则需要用 `.U` / `.S` / `.B` 后缀，并**显式给出位宽**：

```scala
0.U(32.W)          // 32 位无符号 0       —— Verilog: 32'd0
"hFF".U(32.W)      // 32 位无符号 0xFF    —— Verilog: 32'hFF
"b1010".U(4.W)     // 4 位无符号 0b1010   —— Verilog: 4'b1010
-3.S(8.W)          // 8 位有符号 -3
true.B             // 布尔值 true         —— Verilog: 1'b1
false.B            // 布尔值 false        —— Verilog: 1'b0
```

!!! tip "位宽建议"
    注意 `0.U` 不带 `(32.W)` 也是合法的——Chisel 会自动推断位宽。但在复杂表达式中，自动推断可能导致意料之外的位宽截断或者使生成的verilog代码逻辑更加复杂。
    **建议始终显式声明位宽，特别是常数**。

### Bits

除了 `UInt` / `SInt`，Chisel 还提供了 `Bits` 类型：

```scala
val opcode = Bits(7.W)    // 7 位原始比特 —— 适合指令编码字段
val wen    = Bool()       // 单比特使能信号
```

| 类型 | 语义 | 适合场景 |
|------|------|---------|
| `UInt` | 无符号整数 | 地址、数据、计数器——需要做加减运算 |
| `SInt` | 有符号整数 | 有符号比较、算术右移 |
| `Bits` | 原始位向量 | opcode、funct3 等纯编码字段——只做提取和相等比较 |

!!! tip "什么时候用 Bits 而不是 UInt？"
    当你只做**位提取、拼接、相等判断**而不做加减时，用 `Bits` 更好——它明确表达了"这是一串没有数值含义的比特"。比如 `inst(6, 0)` 取 opcode，用 `Bits` 就很合适。

### 类型转换

Chisel 是强类型语言——`UInt` 和 `SInt` 之间不会隐式转换。做有符号/无符号运算或算术右移时，需要显式调用转换方法。

#### `asSInt` 与 `asUInt`

`asSInt` 和 `asUInt` **不改变底层比特**，只改变 Chisel 编译器看待这些比特的方式是有符号还是无符号：

```scala
val a = "b1111".U(4.W)        // UInt(4.W): 二进制 1111，无符号值 = 15
val b = a.asSInt              // SInt(4.W): 二进制 1111，有符号值 = -1（补码）

val c = -1.S(4.W)             // SInt(4.W): 有符号值 = -1
val d = c.asUInt              // UInt(4.W): 无符号值 = 15
```

**CPU 开发中最常见的两个使用场景：**

```scala
// 场景 1：SLT 指令 —— 有符号比较
// a、b 本身是 UInt，但 SLT 需要做有符号比较
val cmp = a.asSInt < b.asSInt    // asSInt 后做比较，自动按有符号规则

// 场景 2：SRA 指令 —— 算术右移
// UInt 的 >> 是逻辑右移（高位补 0）；要算术右移（高位补符号位），必须先转 SInt
val sraResult = (a.asSInt >> b(4, 0)).asUInt   // 转回 UInt 以匹配统一类型
```

!!! warning "忘记 `asSInt` 的 bug"
    在 Verilog 中，如果你忘记 `$signed()` 就做比较或右移，综合/仿真不一定报错，但结果就是错的。Chisel 强迫你写 `asSInt`——如果你不写，编译器就按无符号处理。**这类 bug 从"运行时排查"变成了"编译时就暴露"**。

#### `asTypeOf`

`asTypeOf` 把一段比特按照**目标类型的位宽和结构**重新解释，常用于 Bundle 清零和类型重解释：

```scala
// 清零整个 Bundle（asTypeOf 把 0.U 重新解释为 Bundle 的总位宽）
val bubble = 0.U.asTypeOf(new ID2EX)  // 所有字段全为零，等效于 NOP 气泡

// UInt 转 Bool（当 UInt 位宽为 1 时）
val flag_uint = 1.U(1.W)
val flag_bool = flag_uint.asTypeOf(Bool())   // 等价于 flag_uint(0)
```

`asTypeOf` 的核心思想：**底层比特不变，换个视角来看这些比特**。

清零 Bundle 的本质是——将`0.U`（1-bit 零）视作`ID2EX`Bundle，自动扩展为与 Bundle 总位宽匹配的全零向量。

!!! tip "`asTypeOf` 与位宽"
    源信号和目标类型的**总位宽必须相同**（`0.U` 是例外，Chisel 会推断位宽使其匹配目标）。如果位宽不匹配，编译时会报错——这恰好帮你发现了潜在的类型错误。

## 信号声明

在你开始写组合逻辑和时序逻辑之前，首先得知道如何**声明一个信号**。这是很多同学初学 Chisel 时最混乱的地方——`Wire`、`Reg`、`RegInit`、`IO` 看起来都像在"声明一个东西"，但各自生成的硬件完全不同。

### 预备知识

在深入 Chisel 之前，先回顾一下 Verilog 中 `wire` 和 `reg` 的本质区别。很多同学从单周期 CPU 开始接触 Verilog，可能形成了一个印象：`wire` 是组合逻辑，`reg` 是时序逻辑。但实际上：

- `wire` 确实就是一根物理连线（或组合逻辑网络的输出），必须用 `assign` 或模块实例的输出驱动。
- `reg` **并不一定**生成触发器。`reg` 只表示这个信号在 `always` 块中被赋值——如果 `always` 块的敏感列表是 `@(*)`，综合出来依然是组合逻辑（如多路选择器）；只有当敏感列表是 `@(posedge clk)` 时，`reg` 才真正变成触发器。

这种"语法关键字和实际硬件不完全对应"的情况，是 Verilog 历史演进的遗留问题。Chisel 从设计之初就纠正了这一点：**语法上怎么写，硬件上就怎么生成**，不存在"写的是 reg 但综合成组合逻辑"的歧义。

### Wire

`Wire` 是 Chisel 中最基础的信号声明方式。它的语义非常纯粹：**就是一根线**（以及驱动这根线的组合逻辑）。

**语法：**

```scala
val signalName = Wire(类型)
```

**它生成什么硬件：** 一根物理连线，等价于 Verilog 的 `wire`。如果你给 `Wire` 赋值一个表达式（如 `a + b`），Chisel 会在连线前面自动生成对应的组合逻辑（加法器）。

**什么时候用：**

- 组合逻辑的中间计算结果（比如 ALU 的输出、译码器的输出）
- 需要暂存一个组合表达式的值，以提升代码可读性
- 模块内部子模块之间的连线

**典型示例：**

```scala
// 声明一个 32 位的 Wire
val sum = Wire(UInt(32.W))
sum := a + b    // 用组合逻辑驱动这根线，等价于 Verilog: assign sum = a + b;

// 也可以一步完成声明和赋值（类型从初始值推断）
val diff = WireDefault(a - b)   // 推断为 UInt(32.W)，并连接到 a-b 的结果
```

!!! tip "WireDefault 的作用"
    `WireDefault(init)` 相当于 `Wire` + 默认值。如果你不显式给 `Wire` 赋值，它的输出是不确定的；`WireDefault` 则保证了一个确定的默认输出。在需要"默认走某条通路，条件满足时切换"的场景中（比如转发多路选择器），`WireDefault` 非常方便。

!!! tip "`DontCare`——明确表达"不关心""
    有时你不需要给 `Wire` 指定确定的默认值（比如译码出非法指令时 ALU 的运算结果无所谓），这时可以用 `DontCare`：
    ```scala
    val aluResult = WireDefault(DontCare)  // 告知综合工具：这个值随意，可以优化
    ```
    `DontCare` 让综合工具有更大的优化空间，同时明确告诉读代码的人"此处逻辑确实不在乎这个值"。

**常见错误：把 Wire 放进 when 块**

```scala
val x = Wire(UInt(32.W))
when(cond) {
    x := value    // 编译错误！Wire 不能放在 when 块内进行时序赋值
}
```

原因：`when` 块生成的是 `always @(posedge clk)` 逻辑，只能对寄存器赋值。Wire 是组合逻辑，不存在"在时钟沿上更新"的概念。如果你需要条件更新，目标必须是 `Reg`。

### Reg 与 RegInit

`Reg` 和 `RegInit` 是 Chisel 中声明**状态元件**（触发器/寄存器）的方式。

**语法：**

```scala
// RegInit：带复位值的寄存器（推荐）
val regName = RegInit(复位值)

// Reg：无复位值的寄存器（不推荐）
val regName = Reg(类型)
```

**它们生成什么硬件：** 一组 D 触发器，在时钟的上升沿更新输出。等价于 Verilog 中 `always @(posedge clk)` 块内用 `<=` 赋值的 `reg`。

RegInit 和 Reg 的区别：

| | RegInit | Reg |
|--|---------|-----|
| 复位后的值 | 由参数指定（如 `0.U`） | 不确定（X 态） |
| 生成的 Verilog | 带复位逻辑的寄存器 | 无复位逻辑的寄存器 |
| 仿真行为 | 时钟到来前有确定值 | 时钟到来前为 X（可能扩散到其他逻辑） |
| 推荐程度 | **推荐** | 不推荐，除非你非常清楚为什么要省略复位 |

```scala
// RegInit 示例：程序计数器，复位后从 0x80000000 开始
val pc = RegInit("h80000000".U(32.W))
pc := pc + 4.U    // 每个时钟周期 +4
// 生成的 Verilog 等价于：
// reg [31:0] pc;
// always @(posedge clk) begin
//     if (reset) pc <= 32'h80000000;
//     else       pc <= pc + 32'd4;
// end
```
```scala
// Reg 示例：无复位值的寄存器
val temp = Reg(UInt(32.W))
temp := io.in
// 生成的 Verilog 等价于：
// reg [31:0] temp;
// always @(posedge clk) temp <= io.in;
```

!!! warning "为什么不推荐 Reg？"
    没有复位值的寄存器在仿真中初始值为 X（未知态）。一旦这个 X 通过组合逻辑扩散到其他信号，仿真波形中可能出现大片红色 X，极大增加调试难度。实际 FPGA 中触发器虽然有确定的初始值，但具体是什么取决于芯片和上电过程——你无法控制。
    
    **在 CPU 设计中，PC、寄存器堆、控制寄存器等都需要确定的初始状态，请始终使用 RegInit。**

**RegInit 的初始值类型推断：**

```scala
val pc       = RegInit("h80000000".U(32.W))  // 类型自动推断为 UInt(32.W)
val flag     = RegInit(false.B)               // 类型自动推断为 Bool()
val count    = RegInit(0.U(32.W))             // 类型自动推断为 UInt(32.W)
val offset   = RegInit(0.S(32.W))             // 类型自动推断为 SInt(32.W)，注意用 .S
val negative = RegInit(-3.S(8.W))             // 类型自动推断为 SInt(8.W)，支持负数初值
```

你不需要写 `RegInit(new IF2ID)` 这样的类型参数，Chisel可以从初始值的类型推断。

### IO

`IO` 用于声明模块与外部通信的**端口**。它只能出现在 `extends Module` 的类内部，且必须包裹在一个特殊的 `Bundle` 中（端口 Bundle 的细节在后续 Bundle 章节展开）。

**语法：**

```scala
class MyModule extends Module {
    val io = IO(new Bundle {
        val in1  = Input(UInt(32.W))     // 输入端口
        val in2  = Input(Bool())
        val out1 = Output(UInt(32.W))    // 输出端口
        val out2 = Output(Bool())
    })
}
```

**`Input(T)` 和 `Output(T)` 的含义：**

- `Input(T)`：外部向本模块输入的信号。在模块内部，这个信号**只能读，不能写**（Chisel 编译器会检查）。
- `Output(T)`：本模块向外部输出的信号。在模块内部，这个信号**只能写，不能读**（需要读的话，先把它接到一个 `Wire` 上）。

```scala
class Alu extends Module {
    val io = IO(new Bundle {
        val a   = Input(UInt(32.W))
        val b   = Input(UInt(32.W))
        val op  = Input(UInt(4.W))
        val out = Output(UInt(32.W))
    })

    // 正确：读输入，写输出
    io.out := (io.a + io.b)

    // 错误：试图写输入端口
    io.a := 0.U    // Chisel 编译报错！
}
```

这等价于 Verilog：
```verilog
module Alu (
    input  [31:0] a, b,
    input  [3:0]  op,
    output [31:0] out
);
    assign out = a + b;
endmodule
```

Chisel 和 Verilog 的关键区别在于：

**Chisel 的整个端口集合（`io`）是一个 Bundle 对象，可以作为一个整体被传递和连接**。这意味着你可以把整个 `io` 赋给一个流水线寄存器，而不需要逐端口连线。这一点在流水线 CPU 开发中价值巨大（详见 Bundle 章节）。

### 选择合适的信号类型
```scala
// 示例：在不同场景中选择正确的声明方式

// 场景 1：模块端口
class MyCPU extends Module {
    val io = IO(new Bundle {
        val inst = Input(UInt(32.W))     // 模块端口，用 IO(Input)
        val pc   = Output(UInt(32.W))    // 模块端口，用 IO(Output)
    })
}

// 场景 2：跨周期状态
val pc = RegInit("h80000000".U(32.W))   // PC 需要保持状态，用 RegInit
pc := nextPC                              // 每个时钟周期更新

// 场景 3：组合逻辑中间结果
val aluResult = Wire(UInt(32.W))         // ALU 输出是组合逻辑，用 Wire
aluResult := a + b                       // 用组合表达式驱动

// 场景 4：简单表达式，可省略 Wire
val branchTarget = pc + imm    // Chisel 自动推断这是组合逻辑，无需显式 Wire
```

!!! warning "最常见的两个错误"
    1. **把 Wire 放进 when 块中赋值**：`when` 块生成的是时序逻辑，目标必须是 `Reg`。如果你需要组合逻辑的条件选择，请用 `Mux` 或 `MuxLookup`（详见组合逻辑一节）。
    2. **对 Reg 使用 `=` 而非 `:=`**：`reg = value` 是 Scala 的对象引用赋值，不会生成硬件更新逻辑。寄存器更新必须在 `when` 块内使用 `:=`，或在 `when` 块外直接 `reg := nextValue`（此时等价于每个周期无条件更新）。

## 组合逻辑

有了信号声明的基础，现在来看如何描述硬件的行为。

先说组合逻辑：它没有时钟参与，输出完全由当前输入决定，等价于 Verilog 中的 `assign` 或 `always @(*)`。

### 算术与比较运算

```scala
// 算术运算
val sum  = a + b        // 加法
val diff = a - b        // 减法
val prod = a * b        // 乘法（综合出的硬件较大，CPU 中慎用）
// 除法综合出的硬件非常大，CPU 中通常不用，或用移位替代

// 比较
// 注意等号数量！
val eq   = a === b      // 相等（三个等号！）
val neq  = a =/= b      // 不等
val lt   = a < b        // 小于（UInt 无符号，SInt 有符号）
val gte  = a >= b       // 大于等于
```

!!! warning "最易踩的坑：`===` vs `==`"
    Scala 自身的 `==` 比较的是两个 Scala 对象是不是同一个引用，**不会生成硬件比较器**。
    
    描述硬件相等必须用 Chisel 的 `===`，不等用 `=/=`。
    
    ```scala
    // 错误：a == b 不生成硬件，且比较结果恒为 false
    when(a == b) { ... }
    
    // 正确：a === b 生成硬件比较器
    when(a === b) { ... }
    ```
    
    如果你发现某个相等判断"不生效"，先数一下等号个数是否正确。

### 位运算

```scala
val and_out = a & b     // 按位与
val or_out  = a | b     // 按位或
val xor_out = a ^ b     // 按位异或
val not_out = ~a        // 按位取反
val shift_l = a << n    // 左移
val shift_r = a >> n    // 右移：UInt 逻辑右移，SInt 算术右移
```

### 位提取与拼接

从指令中提取 opcode、rs1、rs2、funct3、funct7 等字段，全依赖这些提取与拼接语法：

- 位提取
- 位拼接(Cat)
- 重复填充(Fill)

```scala
// 位提取
val opcode = inst(6, 0)     // 取 inst 的低 7 位 —— Verilog: inst[6:0]
val rd     = inst(11, 7)    // 取 inst 第 11~7 位
val bit5   = inst(5)        // 取单比特

// 拼接：Cat(a, b, c, ...)
val combined = Cat(high, low)        // Verilog: {high, low}
val ext_imm  = Cat(inst(31), inst(30, 25), inst(11, 8), inst(7))

// 重复填充：Fill(n, signal)
val sign_ext = Fill(16, a(15))       // Verilog: {16{a[15]}}，16 位符号扩展
val zero_ext = Cat(0.U(16.W), a)     // 16 位零扩展
```

### Mux

Verilog 中选择逻辑有三种写法：`?:` 三目运算符、`case` 语句、`if-else` 语句。

Chisel 用三种Mux一一对应。

#### Mux 二选一

```scala
val result = Mux(sel, a, b)
// Verilog: assign result = sel ? a : b;
```

这是最基础的选择器，嵌套后可以实现多路选择——CPU 中前递（Forwarding）的典型写法：

```scala
val aluA = Mux(forwardSel === Fwd_EX,  exResult,
           Mux(forwardSel === Fwd_MEM, memResult,
           regData))  
```

#### MuxLookup 多选一
上面的Mux如果面对较多的选择则写法比较繁琐，可以选择用MuxLookup实现多选一，语法更为简洁。
```scala
val result = MuxLookup(select, default)(Seq(
    key0 -> value0,
    key1 -> value1,
    key2 -> value2
))
// Verilog: always @(*) case(select) ... endcase
```
类似case语句的写法，select是要进行选择的信号，default是没有命中的默认值。


这在 CPU 开发中常用 ，特别适合写**ALU**和**译码器**：

```scala
// ALU 操作：一张表覆盖所有运算
val aluResult = MuxLookup(aluOp, 0.U(32.W))(Seq(
    ALU_ADD  -> (a + b),
    ALU_SUB  -> (a - b),
    ALU_AND  -> (a & b),
    ALU_OR   -> (a | b),
    ALU_SLT  -> Mux(a.asSInt < b.asSInt, 1.U, 0.U),
    ALU_SLL  -> (a << b(4, 0)),
    ALU_SRL  -> (a >> b(4, 0)),
    ALU_SRA  -> (a.asSInt >> b(4, 0)).asUInt // asSInt是将a的类型转为有符号
))
```

#### MuxCase 条件优先级链
与 `MuxLookup` 不同，`MuxCase` 的每个分支是一个**条件表达式**（Bool），按顺序检查，第一个满足的优先，即从前往后优先级依次降低。
```scala
val result = MuxCase(default, Seq(
    (cond1) -> value1,   // 优先级最高
    (cond2) -> value2,
    (cond3) -> value3    // 优先级最低
))
// Verilog: if (cond1) ... else if (cond2) ... else if (cond3) ... else default
```

CPU开发中适合**指令识别**（多条指令可能共享相同 opcode，需要 funct3/funct7 进一步区分）：

```scala
val instType = MuxCase(INST_ILLEGAL, Seq(
    (opcode === OPC_R  && funct3 === F3_ADD  
                        && funct7 === F7_NORMAL) -> INST_ADD,
    (opcode === OPC_R  && funct3 === F3_ADD  
                        && funct7 === F7_ALT)    -> INST_SUB,
    (opcode === OPC_I  && funct3 === F3_ADDI)    -> INST_ADDI,
    (opcode === OPC_LW)                          -> INST_LW,
    (opcode === OPC_JAL)                         -> INST_JAL
))
```

!!! tip "三种 Mux 的选择"
    | 你的需求 | 用什么 | 特点 |
    |---------|--------|------|
    | 二选一 | `Mux` | 最简单直接 |
    | 多选一，基于一个 select 信号的值查表 | `MuxLookup` | 类似 Verilog 的 `case`，所有分支等优先级 |
    | 多选一，每个分支有独立条件表达式，有优先级顺序 | `MuxCase` | 类似 `if-else if` 链，前面分支优先 |

#### Mux1H —— 独热码选择器

前面三种 Mux 的 select 信号都是**二进制编码**（如 `0.U`、`1.U`、`2.U`）。`Mux1H` 则接受**独热码**作为 select——当你的控制信号本身就是独热码时，`Mux1H` 综合出的电路比 `MuxLookup` 更省面积、时序更好。

```scala
// Mux1H(select, inputs*)：select 哪一位为 1，就选 inputs 中对应的那个
val result = Mux1H(Seq(
    isAdd  -> (a + b),       // select[0]=1 时选中
    isSub  -> (a - b),       // select[1]=1 时选中
    isAnd  -> (a & b),       // select[2]=1 时选中
    isOr   -> (a | b)        // select[3]=1 时选中
))
// Verilog 等价：assign result = isAdd ? (a+b) : isSub ? (a-b) : isAnd ? (a&b) : isOr ? (a|b) : 'x;
```

也可以将独热码向量和对应的值向量分开传入：

```scala
val sel = Wire(Vec(4, Bool()))           // 4 位独热码
val vals = Wire(Vec(4, UInt(32.W)))      // 4 个候选值
val result = Mux1H(sel, vals)            // sel(i)=1 时选 vals(i)
```

!!! tip "什么时候用 Mux1H？"
    译码器中，你经常会为每条指令生成一个独立的 `isAdd` / `isSub` / `isLw` 等使能信号——这些信号天然就是**互斥的独热码**。此时用 `Mux1H` 比 `MuxLookup` 更直接：既省去"把独热码转成二进制编码再查表"的中间步骤，综合器也更容易优化（Mux1H 在 FPGA 上通常映射为 LUT 链而非级联 Mux 树）。

    | 你的 select 信号是 | 用什么 |
    |-------------------|--------|
    | 二进制编码（如 `0.U`, `1.U`, `2.U`） | `MuxLookup` |
    | 独热码（如 `isAdd`, `isSub`, `isAnd`, `isOr`） | `Mux1H` |

## 时序逻辑

组合逻辑描述的是"数据怎么流动"，但数据本身需要**在时钟沿上更新**——这就是时序逻辑。

在 Verilog 中时序逻辑写在 `always @(posedge clk)` 里，用 `<=` 赋值；Chisel 中用 `Reg` + `when` + `:=` 实现。

### 寄存器声明
前面我们已经介绍了`Reg`和`RegInit`, 并推荐同学们尽可能不使用`Reg`而应该使用`RegInit`。

这一小节中再介绍一个新的寄存器声明方式：`RegNext`

`RegNext`已经包含了打一拍的语义，表示将某个信号打一拍后的信号。

```scala
// 最常用：带复位值的寄存器
val pc = RegInit("h80000000".U(32.W))    // 复位后 = 0x80000000
pc := nextPC                               // 每个周期更新

// 无复位值的寄存器（慎用——仿真时可能出 X 态）
val temp = Reg(UInt(32.W))

// RegNext：打一拍的简写
val delayed = RegNext(io.in)              // 等价于 Reg + RegInit(in, 0.U)
val delayed = RegNext(io.in, 0.U)         // 带复位值的打一拍
```

!!! tip "RegNext——流水线开发中最常用的原语"
    流水线的每一级本质上就是把上一级组合逻辑的结果"打一拍"。
    ```scala
    val id_pc = RegNext(if_pc)   // 一句话实现
    // verilog版本
    // reg [31:0] id_pc;
    // always @(posedge clk) id_pc <= if_pc;
    ```

### when / elsewhen / otherwise
在 Chisel 代码中看到了这几个关键字，就说明是时序逻辑，无需像Verilog中一样再写`always @(posedge clk)`。
```scala
when(cond1) {
    reg1 := value1       // 注意是 := 不是 =
    reg2 := value2
} .elsewhen(cond2) {
    reg1 := value3
} .otherwise {
    reg1 := value4
}
```

这等价于 Verilog：
```verilog
always @(posedge clk) begin
    if (cond1) begin
        reg1 <= value1;
        reg2 <= value2;
    end else if (cond2) begin
        reg1 <= value3;
    end else begin
        reg1 <= value4;
    end
end
```

!!! note "`when` 块的"保持"语义"
    如果你在 `when` 块的某个分支中没有对某个寄存器赋值，Chisel 会自动让该寄存器在对应条件下**保持原值**。但是综合后会在寄存器输入端加一个 Mux，选择新值还是旧值反馈。
    
    ```scala
    when(en) { reg := newValue }
    // en=0 时 reg 保持原值
    // 综合结果：reg := Mux(en, newValue, reg)
    ```
    
    如果你希望寄存器在某种条件下**清零**而不是保持，必须在那个分支中**显式赋值 0.U**。

### `switch` / `is`

Verilog 中还有一种常见模式——`case` 语句放在 `always @(posedge clk)` 里，这在状态机中非常普遍。

Chisel 用 `switch` / `is` 来实现这个模式：

```scala
switch(state) {
    is(IDLE) {
        when(start) { state := RUN }
    }
    is(RUN) {
        cnt := cnt + 1.U
        when(cnt === 10.U) { state := DONE }
    }
    is(DONE) {
        when(ack) { state := IDLE }
    }
}
```

等价于 Verilog：
```verilog
always @(posedge clk) begin
    case(state)
        IDLE: if (start) state <= RUN;
        RUN:  begin cnt <= cnt + 1; if (cnt == 10) state <= DONE; end
        DONE: if (ack)  state <= IDLE;
    endcase
end
```

**`switch`/`is` vs `when`/`elsewhen`：**

| | `when` / `elsewhen` | `switch` / `is` |
|--|---------------------|------------------|
| 对应 Verilog | `if-else if` 链 | `case` 语句 |
| 最适合 | 条件表达式互不相同 | 基于**同一个信号**的不同取值 |
| 优先级 | 有（上方的分支优先） | 无（所有分支互斥） |

!!! tip "CPU 中的典型场景"
    `switch`/`is` 最适合**多周期状态机**，而转发单元的冒险检测需要优先级选择则更适合 `when`/`elsewhen`。

### 区分 `:=` 和 `=`

这是 Chisel 初学者最容易混淆的地方。

**`=` 永远是组合连线；`:=` 的语义取决于赋值目标和所在位置**。

关键先理解 `:=` 在 `when` 块外对 `Reg` 的行为——它和 `Wire` 完全不同：

```scala
// when 块外的 := 用于 Wire —— 组合连线
val sum = Wire(UInt(32.W))
sum := a + b        // 等价于 Verilog: assign sum = a + b;

// when 块外的 := 用于 Reg —— 时序默认赋值！
val pc = RegInit("h80000000".U(32.W))
pc := pc + 4.U      // 等价于 Verilog: always @(posedge clk) pc <= pc + 4;
//                    每个时钟周期无条件更新！
```

"时序默认赋值"的意思是：

如果没有 `when` 块来覆盖这个行为，寄存器就按这个表达式无条件更新；如果后面有 `when` 块对同一个寄存器赋值，`when` 块的优先级更高：

```scala
val pc = RegInit("h80000000".U(32.W))
pc := pc + 4.U           // 默认：每个周期 +4

when(stall) {
    pc := pc              // 覆盖：stall 时保持不变（when 内的优先级更高）
}
// 等价于 Verilog:
// always @(posedge clk) begin
//     if (stall)  pc <= pc;
//     else        pc <= pc + 4;
// end
```

理解了这一点，下面用一张完整的表格来总结 `=` 和 `:=` 的区别：

| 写法 | 目标类型 | 生成什么硬件 | Verilog 等价 |
|------|---------|-------------|-------------|
| `a = b` | Wire 或 IO | 组合连线 | `assign a = b;` |
| `a := b`（when 外） | Wire 或 IO | 组合连线 | `assign a = b;` |
| `a := b`（when 外） | **Reg** | **时序默认赋值**（每周期无条件更新，可被 when 覆盖） | `always @(posedge clk) a <= b;` |
| `a := b`（when 内） | Reg | 时序条件赋值（条件满足时才更新） | `always @(posedge clk) if (...) a <= b;` |

!!! warning "关键记忆点"
    - `=` 永远是组合连线，目标只能是 Wire 或 IO，不能是 Reg。
    - `:=` 在 when 外：**看目标是什么**——Wire/IO 就是组合连线，**Reg 就是时序默认赋值**。
    - `:=` 在 when 内：**目标必须是 Reg**，是时序条件赋值，优先级高于 when 外的默认赋值。
    - `io.out := expr`：IO 的 Output 端口用 `:=` 驱动，等价于组合连线。


下面是`=`和`:=`的代码示例：
```scala
// 场景 1：Wire 的 := — 组合连线
val aluOut = Wire(UInt(32.W))
aluOut := a + b           // assign aluOut = a + b;

// 场景 2：Reg 默认赋值 — 每周期更新
val cnt = RegInit(0.U(32.W))
cnt := cnt + 1.U          // always @(posedge clk) cnt <= cnt + 1;

// 场景 3：Reg 在 when 内赋值 — 条件更新（优先级高于默认赋值）
when(reset) {
    cnt := 0.U            // reset 时清零，覆盖默认的 +1
}

// 场景 4：错误的用法
val x = Wire(UInt(32.W))
when(cond) {
    x := value            // 编译错误！Wire 不能放在 when 内
}
val y = RegInit(0.U(32.W))
y = y + 1.U               // 编译错误！Reg 不能用 = 赋值
```

### 常见时序模式
在Chisel中，可以快速实现三种常见的时序模式：
```scala
// 模式 1：带使能的寄存器
val reg = RegInit(0.U(32.W))
when(en) {
    reg := newValue        // en=1 时更新，en=0 时保持
}

// 模式 2：计数器
val cnt = RegInit(0.U(32.W))
cnt := cnt + 1.U           // 每个周期自增（不需要 when）

// 模式 3：条件更新
when(reset) {
    reg := 0.U
} .elsewhen(load) {
    reg := loadData
} .otherwise {
    reg := reg + 1.U
}
```

**模式 4：带使能寄存器——`RegEnable`**

`RegEnable` 是模式 1 的语法糖，一行替代 `RegInit` + `when(en)`：

```scala
val reg = RegEnable(nextValue, initValue, en)
// 等价于：
// val reg = RegInit(initValue)
// when(en) { reg := nextValue }
```

流水线 CPU 中，PC 在 stall 时需要保持不变——`RegEnable` 很自然地表达这个语义：

```scala
val pc = RegEnable(nextPC, "h80000000".U(32.W), !stall)
// stall=0 时正常更新为 nextPC，stall=1 时保持
```

对比手写 `when` 版本：
```scala
val pc = RegInit("h80000000".U(32.W))
when(!stall) {
    pc := nextPC
}
```

两种写法生成完全相同的硬件，`RegEnable` 胜在简洁——把"默认更新哪个值""初始值是什么""什么条件下更新"三个信息压缩到了一行。
