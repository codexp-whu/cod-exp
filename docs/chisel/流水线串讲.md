# 五级流水线 CPU 串讲

这一章按照 IF、ID、EX、MEM、WB 的顺序梳理五级流水线，并加入转发、暂停和冲刷控制。

这不是完整实验答案。译码表、存储器接口和调试端口仍要按课程框架补齐，但各级之间的时序关系应当保持一致。

## 本章采用的假设

为了先讲清经典五级流水线，本章假设：

- 单发射、顺序执行。
- IF、ID、EX、MEM、WB 各占一级。
- 指令和数据存储器的读数据在本拍返回。
- 分支和跳转在 EX 级确定。
- 暂不处理 Cache miss、异常、中断和总线等待。

若课程存储器使用同步读或 ready/valid 接口，需要在这个骨架上增加等待与对齐逻辑，不能只替换一个 `Mem` 类型。

## 先看五级在做什么

```text
IF          ID             EX             MEM           WB
取指   ->   译码/读寄存器  ->  ALU/分支   ->  访存   ->  写回
       IF/ID          ID/EX          EX/MEM        MEM/WB
```

流水线提高的是吞吐率：填满以后，理想情况可以每拍完成一条指令。单条指令仍要经过五级，实际加速还受到时钟周期、冒险和存储器等待影响，不能简单说成“五倍”。

本章使用的控制信号如下。各编码常量可以放在单独的 `object` 中定义：

```scala
class ControlSignals extends Bundle {
  val regWrite  = Bool()
  val memRead   = Bool()
  val memWrite  = Bool()
  val usesRs1   = Bool()
  val usesRs2   = Bool()
  val srcAIsPc  = Bool()
  val srcBIsImm = Bool()
  val isBranch  = Bool()
  val isJal     = Bool()
  val isJalr    = Bool()
  val aluOp     = UInt(4.W)
  val immType   = UInt(3.W)
  val memSize   = UInt(3.W)
  val wbSel     = UInt(2.W)
}
```

## 用 `valid` 表示这一拍有没有指令

每级流水线寄存器都带一个 `valid` 位：

```scala
class IF2ID extends Bundle {
  val valid = Bool()
  val pc    = UInt(32.W)
  val inst  = UInt(32.W)
}
```

ID/EX 还要携带源寄存器编号和读出的数据：

```scala
class ID2EX extends Bundle {
  val valid   = Bool()
  val pc      = UInt(32.W)
  val rs1     = UInt(5.W)
  val rs2     = UInt(5.W)
  val rd      = UInt(5.W)
  val rs1Data = UInt(32.W)
  val rs2Data = UInt(32.W)
  val imm     = UInt(32.W)
  val ctrl    = new ControlSignals
}
```

EX/MEM 保存执行结果和 store 数据：

```scala
class EX2MEM extends Bundle {
  val valid     = Bool()
  val aluResult = UInt(32.W)
  val storeData = UInt(32.W)
  val pcPlus4   = UInt(32.W)
  val rd        = UInt(5.W)
  val ctrl      = new ControlSignals
}
```

MEM/WB 只保留最终写回所需内容：

```scala
class MEM2WB extends Bundle {
  val valid = Bool()
  val rd    = UInt(5.W)
  val data  = UInt(32.W)
  val ctrl  = new ControlSignals
}
```

这里把同一个 `ControlSignals` 一路携带到底是为了讲解方便。实际项目可以只保留后续阶段还会使用的字段。

## 顶层先准备四组寄存器

```scala
val ifId  = RegInit(0.U.asTypeOf(new IF2ID))
val idEx  = RegInit(0.U.asTypeOf(new ID2EX))
val exMem = RegInit(0.U.asTypeOf(new EX2MEM))
val memWb = RegInit(0.U.asTypeOf(new MEM2WB))
```

每一级再准备一个组合的“下一值”：

```scala
val ifIdNext  = WireDefault(0.U.asTypeOf(new IF2ID))
val idExNext  = WireDefault(0.U.asTypeOf(new ID2EX))
val exMemNext = WireDefault(0.U.asTypeOf(new EX2MEM))
val memWbNext = WireDefault(0.U.asTypeOf(new MEM2WB))
```

把 `Next` 和寄存器分开，调试时很容易区分“本拍算出来的值”和“上一拍留下的值”。

## IF：取指

PC 指向当前要取的指令：

```scala
val pc = RegInit("h80000000".U(32.W))

io.imemAddr := pc
```

在本章的存储器假设下，`io.imemInst` 与当前 `pc` 对应，所以可以一起送进 IF/ID：

```scala
ifIdNext.valid := true.B
ifIdNext.pc    := pc
ifIdNext.inst  := io.imemInst
```

!!! warning "同步指令存储器需要调整时序"
    如果 `io.imemInst` 下一拍才返回，就必须同时保存发出请求时的 PC，并在响应回来时与指令配对。原稿把“上一拍的指令”和“本拍的 PC”一起写入 IF/ID，会造成错位。

## ID：译码与读寄存器

先从 IF/ID 中拆字段：

```scala
val idInst = ifId.inst
val idRs1  = idInst(19, 15)
val idRs2  = idInst(24, 20)
val idRd   = idInst(11, 7)
```

译码器输出控制信号，寄存器堆组合读取：

```scala
decoder.io.inst := idInst
regfile.io.rs1  := idRs1
regfile.io.rs2  := idRs2

val idCtrl = decoder.io.ctrl
val idImm  = ImmGen(idInst, idCtrl.immType)
```

把这一拍的结果装入 ID/EX 下一值：

```scala
idExNext.valid   := ifId.valid
idExNext.pc      := ifId.pc
idExNext.rs1     := idRs1
idExNext.rs2     := idRs2
idExNext.rd      := idRd
idExNext.rs1Data := regfile.io.rdata1
idExNext.rs2Data := regfile.io.rdata2
idExNext.imm     := idImm
idExNext.ctrl    := idCtrl
```

如果 `ifId.valid` 为假，后面的数据字段是什么并不重要；所有副作用都必须同时受 `valid` 控制。

## EX：先转发，再计算

### 判断哪些结果可以前递

EX/MEM 中的普通 ALU 结果已经可用，load 数据则还没从 MEM 返回：

```scala
val exCanForward = exMem.valid && exMem.ctrl.regWrite &&
  !exMem.ctrl.memRead && exMem.rd =/= 0.U

val wbCanForward = memWb.valid && memWb.ctrl.regWrite &&
  memWb.rd =/= 0.U
```

JAL/JALR 写回的是 `pc + 4`，所以 EX/MEM 的前递数据要根据写回来源选择：

```scala
val exForwardData = Mux(
  exMem.ctrl.wbSel === WbSel.PC4,
  exMem.pcPlus4,
  exMem.aluResult
)
```

### 选择 rs1 和 rs2 的最新值

```scala
val hitEx1 = exCanForward && exMem.rd === idEx.rs1
val hitWb1 = wbCanForward && memWb.rd === idEx.rs1

val src1 = MuxCase(idEx.rs1Data, Seq(
  hitEx1 -> exForwardData,
  hitWb1 -> memWb.data
))
```

rs2 同理：

```scala
val hitEx2 = exCanForward && exMem.rd === idEx.rs2
val hitWb2 = wbCanForward && memWb.rd === idEx.rs2

val src2 = MuxCase(idEx.rs2Data, Seq(
  hitEx2 -> exForwardData,
  hitWb2 -> memWb.data
))
```

EX/MEM 比 MEM/WB 更近，所以它排在 `MuxCase` 前面。连续两条指令都写同一个 rd 时，这个优先级尤其重要。

### ALU 输入与执行结果

```scala
val aluA = Mux(idEx.ctrl.srcAIsPc, idEx.pc, src1)
val aluB = Mux(idEx.ctrl.srcBIsImm, idEx.imm, src2)

alu.io.a  := aluA
alu.io.b  := aluB
alu.io.op := idEx.ctrl.aluOp
```

EX/MEM 下一值记录执行结果。store 数据也要使用转发后的 `src2`：

```scala
exMemNext.valid     := idEx.valid
exMemNext.aluResult := alu.io.out
exMemNext.storeData := src2
exMemNext.pcPlus4   := idEx.pc + 4.U
exMemNext.rd        := idEx.rd
exMemNext.ctrl      := idEx.ctrl
```

### 分支与跳转

分支比较也必须使用转发后的源操作数：

```scala
val branchTaken = idEx.valid && idEx.ctrl.isBranch &&
  (src1 === src2)

val branchTarget = idEx.pc + idEx.imm
```

JALR 的最低位按规范清零：

```scala
val jalrTarget = (src1 + idEx.imm) & "hfffffffe".U

val redirect = branchTaken || idEx.ctrl.isJal || idEx.ctrl.isJalr
val redirectTarget = Mux(idEx.ctrl.isJalr, jalrTarget, branchTarget)
```

这里只演示 BEQ。BNE、BLT、BGE 等分支应按 funct3 选择相应比较方式。

## MEM：访问数据存储器

```scala
io.dmemAddr  := exMem.aluResult
io.dmemWdata := alignedStoreData
io.dmemWmask := storeMask
io.dmemWen   := exMem.valid && exMem.ctrl.memWrite
```

`alignedStoreData` 和 `storeMask` 要根据地址低两位与访问宽度生成，不能把所有 store 都当作整字写入。具体写法见“CPU 开发场景速查”。

load 数据也要按地址低两位选出目标字节或半字，再做符号扩展。假设结果叫 `loadData`，写回数据可以在 MEM 级统一选择：

```scala
val wbDataNext = MuxLookup(exMem.ctrl.wbSel, exMem.aluResult)(Seq(
  WbSel.MEM -> loadData,
  WbSel.PC4 -> exMem.pcPlus4
))
```

```scala
memWbNext.valid := exMem.valid
memWbNext.rd    := exMem.rd
memWbNext.data  := wbDataNext
memWbNext.ctrl  := exMem.ctrl
```

若数据存储器是同步读，`loadData` 不会在本拍可用，MEM/WB 的控制信号也必须跟着延迟或等待响应。

## WB：写回

```scala
regfile.io.wen := memWb.valid && memWb.ctrl.regWrite &&
  memWb.rd =/= 0.U

regfile.io.rd    := memWb.rd
regfile.io.wdata := memWb.data
```

写使能同时检查 `valid`，这样气泡即使携带了旧数据，也不会产生副作用。

## Load-use 为什么要停一拍

考虑下面两条指令：

```asm
lw  x5, 0(x1)
add x6, x5, x2
```

当 `add` 到达 EX 时，`lw` 的数据才在 MEM 级产生。普通 EX/MEM 前递来不及，因此要让 `add` 在 ID 多等一拍，同时向 EX 插入一个气泡。

检测条件要同时考虑“寄存器编号相同”和“当前指令确实使用这个源”：

```scala
val hazardRs1 = idCtrl.usesRs1 && idRs1 === idEx.rd
val hazardRs2 = idCtrl.usesRs2 && idRs2 === idEx.rd

val loadUse = idEx.valid && idEx.ctrl.memRead &&
  idEx.rd =/= 0.U && ifId.valid && (hazardRs1 || hazardRs2)
```

暂停时：

- PC 保持，不能继续取下一条。
- IF/ID 保持，让依赖指令留在 ID。
- ID/EX 写入 `valid = false`，给 load 后面留出一拍。
- EX/MEM 和 MEM/WB 继续推进，让更老的指令完成。

## 分支冲刷

分支在 EX 级确定时，IF 和 ID 中最多已经有两条年轻指令来自错误路径。重定向时要让它们失效，同时让分支本身继续进入 EX/MEM。

因此，控制优先级通常写成：重定向优先，load-use 暂停其次，正常推进最后。

```scala
exMem := exMemNext
memWb := memWbNext

when(redirect) {
  pc := redirectTarget
  ifId.valid := false.B
  idEx.valid := false.B
}.elsewhen(loadUse) {
  pc := pc
  ifId := ifId
  idEx.valid := false.B
}.otherwise {
  pc   := pc + 4.U
  ifId := ifIdNext
  idEx := idExNext
}
```

这里没有把 EX/MEM 清掉，因为产生重定向的分支是正确路径上的老指令，它仍可能需要写回 `pc + 4`。

## 需要检查时序的三种情况

### 连续相关

```asm
addi x5, x0, 1
add  x5, x5, x5
sub  x6, x5, x1
```

第三条指令可能同时命中 EX/MEM 和 MEM/WB 的 x5，必须选择更近的 EX/MEM 值。

### Store 数据相关

```asm
add x5, x1, x2
sw  x5, 0(x3)
```

store 地址来自 rs1，写数据来自 rs2，两条通路都可能需要转发。

### 分支与暂停同拍出现

如果 EX 级的老分支要求跳转，而 ID 级的年轻指令恰好触发 load-use 检测，应先执行老分支的重定向。否则可能把 PC 锁在错误路径上。

## 调试顺序

1. 先用互不相关的 `addi` 验证五级能正常推进和写回。
2. 加入 EX/MEM 前递，再测试连续相关。
3. 加入 MEM/WB 前递，并测试两级同时命中的优先级。
4. 加入 load-use 暂停，逐拍检查 PC、IF/ID 和 ID/EX。
5. 加入 store 数据前递和字节写掩码。
6. 最后加入分支、JAL、JALR 和冲刷。

每次只增加一种行为，并保留对应测试。这样某个回归失败时，查错范围不会扩散到整颗 CPU。

## 每拍建议打印什么

```scala
printf(p"IF v=${ifId.valid} pc=0x${Hexadecimal(ifId.pc)} " +
  p"inst=0x${Hexadecimal(ifId.inst)}\n")
printf(p"EX v=${idEx.valid} pc=0x${Hexadecimal(idEx.pc)} rd=${idEx.rd}\n")
printf(p"WB v=${memWb.valid} rd=${memWb.rd} " +
  p"data=0x${Hexadecimal(memWb.data)}\n")
```

另外打印 `redirect`、`loadUse`、转发选择和存储器写使能。发现信号第一次偏离预期后，可以从该级及前一级开始检查。

## 收尾检查

- 所有外部副作用是否都受 `valid` 控制？
- EX/MEM 前递是否排除了尚未得到数据的 load？
- store 数据是否也经过转发？
- 冒险检测是否使用了 `usesRs1` / `usesRs2`？
- 重定向是否比年轻指令的暂停优先？
- 同步存储器的响应是否与 PC、rd 和控制信号对齐？
- 字节、半字访问是否处理了地址低位和符号扩展？

这些情况都可以用短程序单独测试。分别通过后，再运行规模较大的指令测试集，出现问题时更容易确定范围。
