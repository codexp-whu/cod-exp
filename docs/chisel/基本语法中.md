# 基本语法（中）：组合逻辑与时序逻辑

判断一段 Chisel 是组合逻辑还是时序逻辑，可以看数据是否经过 `Reg`：

- 没有 `Reg`，输出只依赖当前输入，就是组合逻辑。
- 经过 `Reg`，值会跨越时钟沿保存，就是时序逻辑。

`when`、`switch` 只是条件连接语法，本身不等于寄存器。

## 组合表达式

### 算术运算与位宽

```scala
val sum  = a + b
val diff = a - b
val prod = a * b
```

Chisel 的算术结果有明确的位宽规则。以 `UInt` 加法为例：

- `a + b` 与 `a +% b` 保留较宽操作数的位宽，最高位进位会被丢弃。
- `a +& b` 比较宽操作数多 1 位，可以保留进位。

```scala
val a = Wire(UInt(8.W))
val b = Wire(UInt(8.W))

val wrapped = a + b   // 8 位
val full    = a +& b  // 9 位
```

CPU 的 32 位加法通常希望自然回绕，使用 `+` 即可；计算校验和、地址边界或需要进位标志时，要考虑 `+&`。

!!! warning "确认加法结果的位宽"
    位宽不同的两个操作数通常可以参与运算，并不一定编译报错。设计时应检查结果宽度是否符合预期，并为 ALU 的溢出、最大值加一等情况编写测试。

### 比较运算

```scala
val eq  = a === b
val neq = a =/= b
val lt  = a < b
val ge  = a >= b
```

`UInt` 的大小比较按无符号数解释，`SInt` 按有符号数解释。RISC-V 的 `SLT` 和 `SLTU` 可以这样区分：

```scala
val slt  = a.asSInt < b.asSInt
val sltu = a < b
```

**硬件相等与不等使用 `===` 和 `=/=`**。

Scala 的 `==` 返回 Scala `Boolean`，不能代替 Chisel 的硬件比较结果 `Bool`。

```scala
when(a === b) {
  equalCount := equalCount + 1.U
}
```

### 位运算与逻辑运算

```scala
val andResult = a & b
val orResult  = a | b
val xorResult = a ^ b
val inverted  = ~a
```

多个 `Bool` 条件通常使用 `&&`、`||` 和 `!`：

```scala
val canWrite = wen && (rd =/= 0.U)
val mustStop = loadHazard || cacheBusy
```

### 移位

```scala
val sll = a << shamt
val srl = a >> shamt
val sra = (a.asSInt >> shamt).asUInt
```

对 RV32 来说，寄存器移位只使用低 5 位移位量：

```scala
val shamt = b(4, 0)
```

动态左移的结果位宽可能随移位量位宽扩张。若 ALU 输出必须保持 32 位，应由 32 位输出端口约束，并检查生成结果。

### 位提取、拼接与填充

```scala
val opcode = inst(6, 0)
val rs1    = inst(19, 15)
val sign   = inst(31)
```

`Cat` 从左到右按高位到低位拼接：

```scala
val immS = Cat(inst(31, 25), inst(11, 7))
val addr = Cat(wordAddr, 0.U(2.W))
```

`Fill` 用于重复某一段比特，常用于符号扩展：

```scala
val immI = Cat(Fill(20, inst(31)), inst(31, 20))
```

## 选择逻辑

### `Mux`

`Mux(cond, whenTrue, whenFalse)` 对应 Verilog 的三目运算符：

```scala
val nextPC = Mux(taken, target, pc + 4.U)
```

### `MuxLookup`

当选择依据是同一个编码信号时，可以用 `MuxLookup`：

```scala
val result = MuxLookup(aluOp, 0.U(32.W))(Seq(
  AluOp.ADD -> (a + b),
  AluOp.SUB -> (a - b),
  AluOp.AND -> (a & b)
))
```

第一个参数是选择信号，第二个参数是没有命中时的默认值。映射项的键和值都属于硬件表达式。

### `MuxCase`

`MuxCase` 接收一组独立条件，排在前面的条件优先：

```scala
val fwdData = MuxCase(rsData, Seq(
  hitEx  -> exData,
  hitMem -> memData
))
```

这适合转发选择等**有明确优先级**的场景。如果条件本来就是对同一个编码值进行比较，`MuxLookup` 通常更清楚。

### `Mux1H`

`Mux1H` 用一组 one-hot 条件选择数据：

```scala
val result = Mux1H(Seq(
  isAdd -> (a + b),
  isSub -> (a - b),
  isAnd -> (a & b)
))
```

它按位“掩码后再或起来”。因此：

- 没有条件为真时，结果通常为全零。
- 多个条件同时为真时，多个候选值会按位或，结果通常不是你想要的。



| 需求 | 建议写法 |
|------|----------|
| 二选一 | `Mux` |
| 同一个编码信号查表 | `MuxLookup` |
| 多个条件按顺序匹配 | `MuxCase` |
| 已有 one-hot 条件 | `Mux1H` |

## `when` 是条件连接

`when` / `elsewhen` / `otherwise` 可以连接 Wire、输出端口，也可以连接 Reg。生成什么硬件由目标决定。

### 用 `when` 描述组合逻辑

先给 Wire 一个默认值，再在条件成立时覆盖：

```scala
val selected = WireDefault(normalData)

when(forwardFromEx) {
  selected := exData
}.elsewhen(forwardFromMem) {
  selected := memData
}
```

这会生成带优先级的组合选择逻辑。默认值覆盖了条件都不成立的路径，因此不会出现未初始化连接。

下面的写法不完整：

```scala
val selected = Wire(UInt(32.W))
when(cond) {
  selected := data
}
```

`selected` 不是寄存器，`cond` 为假时也不能“保持原值”。Chisel 会在检查阶段指出它没有在所有路径上得到驱动。

### 用 `when` 控制寄存器更新

赋值目标是 Reg 时，条件不成立就保持原值：

```scala
val pc = RegInit(0.U(32.W))

when(!stall) {
  pc := nextPC
}
```

这里生成的是带使能的寄存器。保持原值不需要显式写 `pc := pc`。

### 连接顺序与优先级

同一个目标在同一作用域中被多次连接时，后写的连接优先。常见写法是先给默认连接，再写特殊情况：

```scala
pc := pc + 4.U

when(redirect) {
  pc := target
}
```

这相当于“通常加 4，重定向时跳到 target”。对 Wire 和 Reg 都可以使用这种默认值加覆盖的结构。

## `switch` / `is`

当多个分支都在检查同一个信号的不同取值时，`switch` 比一长串比较更容易读：

```scala
switch(state) {
  is(State.IDLE) { nextState := State.RUN }
  is(State.RUN)  { nextState := State.DONE }
  is(State.DONE) { nextState := State.IDLE }
}
```

`switch` 也不是专门的时序语句。上例中的 `nextState` 若是 Wire，就生成组合的下一状态逻辑；若直接连接状态 Reg，则控制寄存器更新。

状态机常用“状态寄存器 + 下一状态 Wire”的写法：

```scala
val state = RegInit(State.IDLE)
val nextState = WireDefault(state)

switch(state) {
  is(State.IDLE) { when(start) { nextState := State.RUN } }
  is(State.RUN)  { when(done)  { nextState := State.DONE } }
}

state := nextState
```

## `=` 与 `:=`

这两个符号处在不同层次：

| 写法 | 含义 | 是否生成硬件连接 |
|------|------|------------------|
| `val x = expr` | 定义 Scala 名字 `x` | `expr` 本身可能构造硬件 |
| `var x = expr` | 定义可重新绑定的 Scala 名字 | 重新绑定不等于硬件更新 |
| `sink := source` | 把硬件源连接到硬件目标 | 是 |

```scala
val sum = a + b
io.out := sum
```

第一行给硬件表达式起名，第二行建立从 `sum` 到输出端口的连接。不存在“`=` 是组合赋值、`:=` 是时序赋值”的规则。

## 常用寄存器写法

### `RegNext`

`RegNext(in)` 把输入延迟一拍，但不带复位值：

```scala
val delayed = RegNext(io.in)
```

需要复位值时使用第二个参数：

```scala
val delayed = RegNext(io.in, 0.U)
```

### `RegEnable`

`RegEnable` 只在使能为真时采样输入：

```scala
val pc = RegEnable(nextPC, 0.U(32.W), !stall)
```

等价的展开写法是：

```scala
val pc = RegInit(0.U(32.W))
when(!stall) {
  pc := nextPC
}
```

### 计数器

```scala
val count = RegInit(0.U(8.W))

when(enable) {
  count := count + 1.U
}
```

### 默认更新，特殊情况覆盖

```scala
val pc = RegInit(0.U(32.W))

when(redirect) {
  pc := target
}.elsewhen(!stall) {
  pc := pc + 4.U
}
```

如果暂停和重定向可能同拍出现，必须明确谁优先。上例先判断 `redirect`，因此重定向优先；既没有重定向又没有暂停时，PC 才加 4。暂停时没有连接，寄存器自然保持原值。

## 本节总结

- 看到 `when`，先看赋值目标是 Wire 还是 Reg。
- 组合 Wire 先给默认值，再按条件覆盖。
- `=` 是 Scala 定义或重新绑定，`:=` 是硬件连接。
- 加法、移位和类型转换都要检查位宽。
