    基本语法（上）: 基本数据类型¶

    从 Verilog 转到 Chisel 时，需要先分清“这句 Scala语句 什么时候执行”和“这根硬件信号什么时候变化”。这一章先说明这两个阶段，再介绍常用的数据类型与信号。

    先分清两个阶段¶

    一份 Chisel 源码会经历两个阶段。

    第一阶段是电路生成阶段。Mill 运行 Scala 程序，Scala 的 class、if、for 和函数在这时执行，最后构造出一张硬件电路图。

    第二阶段是硬件运行阶段。生成的 SystemVerilog 进入仿真器或 FPGA，组合逻辑随输入变化，寄存器在时钟沿更新。

    看到的内容 发生在什么时候 作用
    Scala Int、Boolean、if、for 生成电路时 决定要生成怎样的电路
    Chisel UInt、Bool、when、Reg 硬件运行时 表示真实的信号与状态

    看一个很小的例子：

    class Adder(val width: Int) extends Module {
  val io = IO(new Bundle {
    val a = Input(UInt(width.W))
    val b = Input(UInt(width.W))
    val y = Output(UInt(width.W))
  })

  io.y := io.a + io.b
}

    实例化 new Adder(32) 时，Scala 参数 width 的值是 32，它决定生成一个 32 位加法器。电路生成结束后，硬件里并不存在一个叫 width 的寄存器；io.a、io.b 和 io.y 才是运行时变化的信号。

    Scala 条件与硬件条件不是一回事

    if (debug) 的条件通常是 Scala Boolean，它决定某段硬件是否被生成 。when(io.enable) 的条件是 Chisel Bool，它会生成由 io.enable 控制的电路。不要拿 Scala 的 if 代替硬件多路选择器 。

    常用 Scala 语法¶

    这里介绍 CPU 实现中会反复使用的 Scala 语法，其余内容可在遇到时再查阅。

    val、var 与 :=¶

    val 表示这个 Scala 名字不能重新绑定，var 表示可以重新绑定：

    val xlen = 32
var fileCount = 0
fileCount = fileCount + 1

    声明硬件时几乎总是使用 val:

    val pc = RegInit(0.U(32.W))
pc := pc + 4.U

    这里的 pc 始终指向同一个硬件寄存器，所以它是 val。val 限制的是 Scala 名字，寄存器保存的比特仍会在时钟沿变化。

    = 和 := 也处在不同层次：

    写法 含义
    val nextPC = pc + 4.U 给一个硬件表达式起 Scala 名字
    pc := nextPC 把硬件表达式连接到寄存器输入
    x = y 重新绑定 Scala var，不是硬件赋值

    不要用 var 模拟寄存器

    Scala 的重新绑定只发生在生成阶段。硬件要跨周期保存数据，必须使用 Reg 或 RegInit。

    class、new 与 object¶

    class 用来定义可重复创建的结构。Bundle 通过 new 创建，模块实例还需要用 Module(...) 包住：

    class FetchPacket extends Bundle {
  val pc = UInt(32.W)
  val inst = UInt(32.W)
}

val packet = Wire(new FetchPacket)
val alu = Module(new Alu)

    object 是 Scala 的单例对象，适合放全局配置和固定编码：

    object CoreConfig {
  val XLEN = 32
  val RESET_PC = BigInt("80000000", 16)
}

    这里的 XLEN 和 RESET_PC 都是生成阶段使用的 Scala 常量。它们不会单独生成硬件。

    Seq¶

    Seq 是 Scala 序列，类似只读的列表。它本身不是硬件，但里面可以装 Chisel 表达式或模块实例。

    val zeros = Seq.fill(32)(0.U(32.W))
val indices = Seq.tabulate(4)(i => i.U)
val adders = Seq.fill(2)(Module(new Adder(32)))

    后面遇到 VecInit(Seq(...))、MuxLookup(...)(Seq(...)) 时，外层 Seq 负责在生成阶段收集若干项，Chisel 再根据这些项生成电路。

    for 循环¶

    Chisel 中的 for 是 Scala 循环，会在生成阶段展开。下面的代码生成四份并行加法逻辑：

    for (i <- 0 until 4) {
  io.out(i) := io.in(i) + 1.U
}

    它的含义 接近手写四行连接，不是第 0 个周期算 out(0)、第 1 个周期再算 out(1)。

    区分和软件编程中的if

    Chisel中的for表达的是并行的含义，用于描述多个相同结构的硬件。

    如果需要一个随周期迭代的除法器，应使用状态机、计数器和寄存器。Scala for 只复制或组织硬件，不会产生多周期行为。

    yield 可以把每次循环产生的结果收集成 Seq：

    val incremented = for (i <- 0 until 4) yield {
  io.in(i) + 1.U
}

    这里的 incremented 是一个包含四个硬件表达式的 Scala 序列。

    reduce¶

    reduce 把一个序列逐项合并成一个结果。放入 Chisel 运算后，它会生成对应的组合逻辑。

    val sum = data.reduce(_ + _)
val anyHit = hitVec.reduce(_ || _)
val allReady = readyVec.reduce(_ && _)

    _ + _ 是匿名函数的简写，可以读成“把前面的结果和当前元素相加”。例如 data.reduce(_ + _) 最终会把 data 中的所有元素连成加法网络。

    reduce 表达的是“把所有元素合并”，但不承诺生成平衡树。输入较多或时序要求较高时，应检查生成 RTL 和综合报告。

    package 与 import¶

    CPU 代码拆成多个文件后，通常用 package 放进同一个命名空间。例如 mycpu/src/cpu/Alu.scala：

    package cpu

import chisel3._
import chisel3.util._

class Alu extends Module {
  // 端口与逻辑
}

    同属 cpu 包的文件可以直接使用 Alu。跨包引用时再写：

    import cpu.Alu
import cpu.{Decoder, RegisterFile}

    我们的课程实验规模的五级流水线 CPU 不必把包分得很细。先让核心模块统一放在 cpu 包下，通常已经够清楚。

    Scala 类型与 Chisel 类型¶

    下面两组类型名字相似，但用途不同：

    Scala 数据 Chisel 数据 区别
    Int、BigInt UInt、SInt 前者在生成阶段计算，后者表示硬件比特
    Boolean Bool 前者控制 Scala，后者可以接进电路
    Seq[T] Vec[T] 前者由 Scala 下标访问，后者可由硬件下标选择

    例如：

    val width: Int = 32
val resetPC: BigInt = BigInt("80000000", 16)

val data = Wire(UInt(width.W))
val valid = Wire(Bool())

    width 和 resetPC 在生成电路时就已经确定；data 和 valid 才是仿真波形里能看到的硬件信号。

    三种常用硬件数据类型¶

    Chisel 写法 含义 Verilog 中接近的写法
    UInt(32.W) 32 位无符号类型 logic [31:0]
    SInt(32.W) 32 位有符号补码类型 logic signed [31:0]
    Bool() 单比特布尔类型 logic

    这些写法只描述信号的类型。把它给 Wire、Reg 或 IO 后，才会得到有归属的硬件信号：

    val aluOut = Wire(UInt(32.W))
val pc = RegInit(0.U(32.W))

    也可以让一个硬件表达式直接绑定到 val，不必为了每个中间结果都额外写 Wire：

    val nextPC = pc + 4.U
val isZero = aluOut === 0.U

    nextPC 和 isZero 仍然代表硬件表达式，只是没有单独声明一个可被多次连接的 Wire。

    硬件字面量¶

    Scala 数字后加 .U、.S 或 .B，才会变成 Chisel 硬件常量：

    0.U(32.W)
"hff".U(32.W)
"b1010".U(4.W)
-3.S(8.W)
true.B
false.B

    0.U 的位宽可以由连接位置推断，但复位值、接口常量、掩码和地址通常应明确位宽。下一章会继续说明算术表达式的结果位宽。

    一定要明确位宽

    在Chisel中定义字面量一定要明确位宽，否则会出现位宽阶段等难以排查的错误。

    固定编码与枚举¶

    用 object 保存固定编码¶

    RISC-V 操作码和 ALU 控制码已经由设计规定，适合集中放在 object 中：

    object AluOp {
  val ADD = 0.U(4.W)
  val SUB = 1.U(4.W)
  val AND = 2.U(4.W)
  val OR  = 3.U(4.W)
  val XOR = 4.U(4.W)
}

    使用时写 AluOp.ADD。比起到处散落 0.U、1.U，看到名字就知道这几个比特表示什么。

    ChiselEnum¶

    状态机只有有限的几个状态，优先使用类型更明确的 ChiselEnum：

    import chisel3.util.ChiselEnum

object State extends ChiselEnum {
  val IDLE, RUN, DONE = Value
}

val state = RegInit(State.IDLE)
when(state === State.IDLE) {
  state := State.RUN
}

    枚举值拥有自己的类型，误把普通 UInt 直接接给状态信号时，编译器更容易帮你发现问题。

    Enum(n)¶

    旧代码和一些较短的例子中也常见 Enum(n)。它生成若干普通 UInt 常量：

    import chisel3.util.Enum

val idle :: run :: done :: Nil = Enum(3)
val state = RegInit(idle)

when(state === idle) {
  state := run
}

    :: 是 Scala 的列表拆分写法。上面三个值依次对应 0.U、1.U、2.U。它比较轻量，但类型检查不如 ChiselEnum 严格。

    Tip

    在实验中状态机建议优先用 ChiselEnum；阅读已有项目时，两种写法都要认识。

    类型转换¶

    asSInt 与 asUInt¶

    这两个操作 不改变底层比特 ，只改变这些比特按有符号还是无符号解释：

    val bits = "b1111".U(4.W)
val signed = bits.asSInt

    bits 按 UInt 看是 15，signed 按四位补码看是 -1。CPU 中常见的使用场景是 SLT 和 SRA：

    val slt = a.asSInt < b.asSInt
val sra = (a.asSInt >> b(4, 0)).asUInt

    忘记转换通常不会报语法错，而是悄悄生成另一种合法电路。因此有符号比较、负数和最高位为 1 的输入必须单独测试。

    Warning

    有关有符号数和无符号数的部分一定要认真对待，否则会出现计算结果错误的情况！

    asTypeOf¶

    asTypeOf 按目标类型的结构重新解释一组比特，流水线 Bundle 清零时很常见：

    val bubble = 0.U.asTypeOf(new ID2EX)
    能够把目标类型的结构快速清零。

    Wire¶

    Wire 表示由组合逻辑驱动的信号。它不会保存上一拍的值。

    val result = Wire(UInt(32.W))
result := io.a + io.b

    当一个组合结果有默认路径和特殊路径时，可以先给默认连接，再覆盖：

    val nextPC = WireDefault(pc + 4.U)

when(branchTaken) {
  nextPC := branchTarget
}

    这会生成多路选择逻辑。条件不成立时走 pc + 4，条件成立时走 branchTarget。

    谨慎使用 DontCare

    DontCare 表示某些比特无所谓，综合时可能被优化。它也会让仿真更难读，甚至掩盖非法控制路径。CPU 的控制信号建议先给明确默认值。

    明确复位

    无论是当前介绍的Wire 还是后续介绍的 Reg寄存器，都建议使用带默认值的版本，避免 Vivado 仿真时出现 X未定态！

    Reg 与 RegInit¶

    Reg 和 RegInit 会生成寄存器。输入在时钟沿被采样，输出在两个时钟沿之间保持。

    val pc = RegInit("h80000000".U(32.W))
pc := pc + 4.U

    RegInit 指定复位值，Reg 只指定类型：

    val valid = RegInit(false.B)
val data = Reg(UInt(32.W))

    没有复位值的 data 在复位后内容不应被依赖。流水线里常见的做法是复位每一级的 valid，数据字段可以不复位；只要 valid 为假，就不能让这些数据产生写寄存器或写内存等副作用。

    PC、状态机、流水线 valid 和会控制外部副作用的状态，通常应明确复位。

    对于控制通路必须复位，对于数据通路非必要不复位，以免增大面积影响时序。

    IO：模块端口¶

    IO 声明模块与外部连接的端口。常见写法是把端口放进一个 Bundle：

    class Alu extends Module {
  val io = IO(new Bundle {
    val a = Input(UInt(32.W))
    val b = Input(UInt(32.W))
    val out = Output(UInt(32.W))
  })

  io.out := io.a + io.b
}

    从模块内部看，Input 只能读取，Output 由当前模块负责驱动。Chisel 会检查端口方向，试图给输入端口连接一个内部结果会报错。

    io 是常用的端口变量名，不是语言强制名称。沿用这个命名便于阅读不同模块的接口。

    本章要点¶

    • Scala 的 if、for、Int 在生成阶段工作；Chisel 的 when、UInt、Reg 描述硬件。
    • val 固定的是 Scala 名字，寄存器内容仍然可以每拍变化。
    • UInt(32.W) 是硬件类型模板；交给 Wire、Reg 或 IO 后才成为有归属的信号。
    • Wire 没有记忆，组合路径要完整驱动；Reg 能跨周期保存状态。
    • = 用来定义或重新绑定 Scala 名字，:= 才是硬件连接。

    下一章会在这些信号上搭组合逻辑和时序逻辑，并重点说明 when、默认连接、连接优先级和算术位宽。
