    环境搭建

    Tip

    在开始学习语法之前，我们先花一节的时间把开发环境搭好，并亲手跑通第一个 Chisel 模块——从写代码，到生成 Verilog，再到看见结果。这一节的目标不是让你看懂每一行代码（语法后面几节会细讲），而是让你的电脑先能"跑起来"，这样后面学语法时你可以随时改一改、跑一跑，学得更快。

    如果你此刻只想先了解语法、环境稍后再装，可以先跳到下一节，但强烈建议在正式写 CPU 之前回来把环境跑通。

    Chisel 是怎么变成电路的¶

    先建立一张"全景图"，理解你敲下的 Chisel 代码到底经历了什么，后面的每一步操作你才知道自己在干什么。

    回忆你写 Verilog 的流程：写 .v 文件 → 丢给 Vivado/Verilator → 综合仿真。Chisel 只是在最前面多了两步转换：

    你写的 Scala/Chisel 代码
        │  ① sbt 编译并运行你的 Scala 程序
        ▼
   Chisel 电路描述（内存中的电路对象）
        │  ② Chisel 生成 FIRRTL（一种电路中间表示）
        ▼
      FIRRTL
        │  ③ firtool 把 FIRRTL 编译成 Verilog
        ▼
   Verilog / SystemVerilog（.sv 文件）
        │  ④ 和你以前一样：丢给 Vivado / Verilator
        ▼
   综合、仿真、上板

    关键认知：Chisel 程序是一个"电路生成器"

    这是 Verilog 转 Chisel 的同学最需要扭转的观念。

    你写的 Chisel 代码本身是一段会被运行的 Scala 程序。运行它，程序会"搭建"出一个电路对象，再把这个电路对象翻译成 Verilog。所以你能用 if、for、函数、类这些编程手段去生成电路——这正是 Chisel 强大的根源。

    换句话说：Verilog 是"描述"电路，Chisel 是用程序"生成"电路。 这句话现在可能有点抽象，等你写到参数化流水线时会有切身体会。

    好消息是：上面 ①②③ 这几步转换，你只需要一条命令就能全部触发，平时根本不用手动操心 FIRRTL 长什么样。

    安装工具链¶

    Chisel 是 Scala 的库，Scala 又跑在 Java 虚拟机（JVM）上，所以你需要装三样东西。三者都装好后，你就再也不用单独和它们打交道了，日常只用 sbt 一个命令。

    工具 作用 推荐版本
    JDK（Java 开发工具包） 提供 JVM，Scala 运行的地基 JDK 17 或 JDK 21（LTS 版本）
    构建工具（sbt 或 Mill，二选一） Scala 的"构建工具"，相当于 C 的 make、Python 的 pip 最新版即可
    firtool 把 FIRRTL 编译成 Verilog（通常由构建工具自动下载，一般无需手动装） 跟随 Chisel 版本

    构建工具：sbt 还是 Mill？

    Scala 世界有两个主流构建工具，功能上完全可以互相替代，你的 Chisel 项目用哪个都能写 CPU：

    • sbt：Scala 官方老牌工具，资料最多，本讲义正文默认用它。
    • Mill：更年轻、启动更快、配置更简洁的工具。国内知名的开源 RISC-V 处理器（香山 XiangShan、果壳 NutShell）都用 Mill，如果你打算参考它们的代码，会经常见到 Mill。

    下面我们先以 sbt 走一遍完整流程；本节末尾有专门的 "用 Mill 构建" 一节，把同样的事用 Mill 再讲一遍，并给出两者的命令对照表。跟着课程模板走——模板用哪个你就学哪个，两者思路是相通的。

    各平台安装方式¶

    最省心的方式是用 Coursier（Scala 官方一键安装器），它会帮你把 JDK、sbt、scala 全部装好并配好环境变量：

    在 Coursier 官网 下载 cs-x86_64-pc-win32.exe，重命名为 cs.exe，然后在 PowerShell 中运行：

    .\cs.exe setup

    它会自动安装 JDK、sbt 等，并把它们加进 PATH。装完重启一下终端让环境变量生效。

    brew install coursier/formulas/coursier && cs setup

    （若没有 Homebrew，先装 Homebrew，或从 Coursier 官网下载对应的安装脚本。）

    curl -fL "https://github.com/coursier/coursier/releases/latest/download/cs-x86_64-pc-linux.gz" | gzip -d > cs
chmod +x cs && ./cs setup

    验证安装¶

    打开一个新的终端，依次运行：

    java -version     # 应显示 17 或 21
sbt --version     # 应显示 sbt 的版本号（第一次运行会下载一些依赖，稍等片刻）

    只要这两条命令都能正常输出版本号，你的地基就打好了。

    第一次运行 sbt 会很慢

    sbt 第一次启动会从网络下载 Scala 编译器和一大堆依赖包（几百 MB），可能要等几分钟甚至更久，这是正常现象。请务必保证网络通畅（国内同学建议配置国内镜像源，见文末附录）。下载过一次后就会缓存到本地，以后就快了。

    建立你的第一个项目¶

    一个最小的 Chisel 项目长这样：

    my-cpu/
├── build.sbt                       # 项目配置：依赖哪些库、用哪个 Scala 版本
├── project/
│   └── build.properties            # 指定 sbt 版本
└── src/
    ├── main/
    │   └── scala/                   # 你的 Chisel 源码放这里
    │       └── Adder.scala
    └── test/
        └── scala/                   # 你的测试代码放这里
            └── AdderSpec.scala

    别自己一个个建文件夹

    绝大多数课程会直接提供一个配好的项目模板（骨架仓库），你只需要 git clone 下来，把代码写进 src/main/scala/ 即可。如果助教发了模板，请优先使用模板，下面手动建项目的内容仅供你理解每个文件的作用。

    build.sbt——项目的"配料表"¶

    build.sbt 告诉 sbt：这个项目用哪个版本的 Scala、依赖哪些库。对我们来说，最重要的就是引入 Chisel。把下面内容存为项目根目录下的 build.sbt：

    // build.sbt
ThisBuild / scalaVersion := "2.13.16"       // Chisel 6 需要 Scala 2.13
ThisBuild / version      := "0.1.0"

lazy val root = (project in file("."))
  .settings(
    name := "my-cpu",
    libraryDependencies ++= Seq(
      // Chisel 本体
      "org.chipsalliance" %% "chisel"    % "6.7.0",
      // 测试框架（下一节讲仿真时用，放在 test 作用域）
      "edu.berkeley.cs"   %% "chiseltest" % "6.0.0" % Test,
    ),
    // Chisel 依赖一个编译器插件才能正常工作，这一行必不可少
    addCompilerPlugin("org.chipsalliance" % "chisel-plugin" % "6.7.0" cross CrossVersion.full),
    scalacOptions ++= Seq(
      "-language:reflectiveCalls",
      "-Ymacro-annotations",     // 支持 Bundle 里用到的一些高级特性
    ),
  )

    project/build.properties 指定 sbt 自身的版本：

    sbt.version=1.10.7

    这些版本号会随时间更新

    Chisel、sbt、Scala 的版本号会不断迭代。上面给的是本讲义编写时的稳定组合。如果课程模板里的版本号和这里不同，以课程模板为准——版本号不必和讲义完全一致，只要能编译通过即可。

    Hello, Chisel：一个加法器¶

    现在写下你的第一个 Chisel 模块。把下面代码存为 src/main/scala/Adder.scala：

    // src/main/scala/Adder.scala
import chisel3._                 // 引入 Chisel 核心库
import circt.stage.ChiselStage   // 引入生成 Verilog 的工具

// 一个 8 位加法器模块
class Adder extends Module {
  val io = IO(new Bundle {
    val a   = Input(UInt(8.W))
    val b   = Input(UInt(8.W))
    val sum = Output(UInt(8.W))
  })
  io.sum := io.a + io.b     // 把 a + b 的结果连到输出端口
}

// 一个"主程序"，负责把 Adder 翻译成 Verilog 并打印出来
object AdderMain extends App {
  println(ChiselStage.emitSystemVerilog(new Adder))
}

    先别纠结每一行——语法后面会细讲。你现在只需要感知到几件事：

    • class Adder extends Module：定义一个模块，等价于 Verilog 的 module Adder ... endmodule。
    • io = IO(new Bundle {...})：这个模块的输入输出端口。
    • io.sum := io.a + io.b：把加法结果连到输出。:= 是 Chisel 的连线符号（后面会专门讲它和 = 的区别）。
    • object AdderMain extends App：一个可运行的入口程序，emitSystemVerilog 就是触发前面全景图里 ①②③ 那三步转换的"总开关"。

    运行它，看见 Verilog¶

    在项目根目录打开终端，运行：

    sbt "runMain AdderMain"

    第一次会编译一会儿，随后你会在终端里看到生成的 SystemVerilog，大致长这样：

    module Adder(
  input        clock,
  input        reset,
  input  [7:0] io_a,
  input  [7:0] io_b,
  output [7:0] io_sum
);
  assign io_sum = io_a + io_b;
endmodule

    恭喜——你已经完整跑通了"Chisel 代码 → Verilog"的全流程！ 看，你写的 io.sum := io.a + io.b 变成了熟悉的 assign io_sum = io_a + io_b;。

    为什么凭空多出了 clock 和 reset？

    你在 Chisel 里没写时钟和复位，但生成的 Verilog 里却有 clock 和 reset 两个端口。这是因为凡是 extends Module 的模块，Chisel 都会自动帮你接上一个隐式的时钟和复位——你以后写寄存器（Reg）时，它们会自动挂到这个时钟上，你再也不用像 Verilog 那样在每个 always @(posedge clk) 里手写 clk 了。

    对于这个纯组合逻辑的加法器，clock/reset 用不上，但接口里仍然会保留它们。这是 Chisel 的正常行为，无需担心。

    把 Verilog 写到文件里¶

    emitSystemVerilog 只是打印到屏幕。真正开发时，你会想把 Verilog 落到磁盘上，好丢给 Vivado。改用 emitSystemVerilogFile：

    object AdderMain extends App {
  ChiselStage.emitSystemVerilogFile(
    new Adder,
    firtoolOpts = Array("-disable-all-randomization", "-strip-debug-info"),
    args = Array("--target-dir", "generated"),   // 输出到 generated/ 目录
  )
}

    再次 sbt "runMain AdderMain"，你会在 generated/Adder.sv 找到生成的文件。这个 .sv 文件就可以像你以前的 Verilog 一样，加入 Vivado 工程综合、上板。

    工作流小结

    从今往后，你的日常开发循环就是这三步：

    1. 在 src/main/scala/ 里写/改 Chisel 代码
    2. sbt test 跑仿真验证逻辑对不对（下一节详解）
    3. 逻辑没问题后，sbt "runMain XxxMain" 生成 Verilog，交给 Vivado 综合上板

    绝大部分时间你都泡在第 1、2 步，只有最后要上板时才碰第 3 步。

    用 sbt 的正确姿势¶

    sbt 每次启动都要加载 JVM，比较慢。更舒服的用法是进入 sbt 交互式命令行，之后所有命令都在里面敲，省去反复启动的开销：

    sbt            # 进入 sbt 交互式 shell（提示符变成 sbt:my-cpu>）

    进去以后：

    sbt:my-cpu> compile              # 只编译，检查语法错误
sbt:my-cpu> runMain AdderMain    # 运行主程序生成 Verilog
sbt:my-cpu> test                 # 跑所有测试（下一节讲）
sbt:my-cpu> ~test                # 加 ~：进入"监视模式"，你一存文件就自动重跑测试
sbt:my-cpu> exit                 # 退出

    ~ 监视模式：写 CPU 的神器

    ~test 前面加个波浪号，sbt 会盯着你的源文件，每次你 Ctrl+S 保存，它就自动重新编译并跑测试。写 CPU 时开着它，改一行看一次结果，反馈飞快，强烈推荐。

    用 Mill 构建（sbt 之外的另一选择）¶

    前面整套流程用的是 sbt。如果你的课程模板用的是 Mill，或者你想参考香山、果壳这类国内开源处理器的写法，这一节把同样的事用 Mill 再走一遍。核心概念（生成 Verilog、跑测试）完全一样，只是配置文件和命令换了个样子。

    Mill 好在哪

    Mill 相比 sbt 的直观优势：启动快（不用每次都等 JVM 慢慢热身）、配置更像普通 Scala 代码（增量、可组合）、输出目录 out/ 结构清晰。缺点是资料相对少一些、老项目仍以 sbt 为主。对写 CPU 而言，两者都够用，看模板、看喜好即可。

    安装 Mill¶

    最省事的还是用 Coursier（前面装 sbt 时已经装过 Coursier 了）：

    cs install mill

    装好后验证：

    mill --version

    更常见的方式：项目自带 mill 引导脚本

    很多 Mill 项目会在仓库根目录放一个叫 mill 的引导脚本（Windows 上还有 mill.bat），并用一个 .mill-version 文件锁定 Mill 版本。这样你连 Mill 都不用单独装——直接在项目里运行 ./mill ...（Windows 用 .\mill.bat ...），脚本会自动下载对应版本的 Mill。如果课程模板里有这个 mill 脚本，优先用它，版本最省心。

    Mill 的项目结构与配置¶

    Mill 项目和 sbt 项目长得差不多，只是配置文件从 build.sbt 换成了 build.mill（老一点的项目里叫 build.sc，语法基本一致）：

    my-cpu/
├── build.mill           # Mill 的配置文件（相当于 sbt 的 build.sbt）
├── .mill-version        # 锁定 Mill 版本（可选）
└── src/                 # 源码；测试放在下面的 test/ 里
    ├── Adder.scala
    └── test/
        └── AdderSpec.scala

    Mill 的源码目录和 sbt 不一样

    这是从 sbt 切到 Mill 时最容易踩的坑：Mill 默认的源码目录是模块目录下的 src/，测试在 test/src/，不像 sbt 那样是 src/main/scala 和 src/test/scala。具体以你的 build.mill 里各模块的定义为准，不确定时看模板的目录结构照着放。

    一个最小的 build.mill，实现和前面 sbt 版完全相同的功能：

    // build.mill
package build
import mill._, scalalib._

object mycpu extends ScalaModule {
  def scalaVersion = "2.13.16"

  // 相当于 sbt 的 libraryDependencies
  def ivyDeps = Agg(
    ivy"org.chipsalliance::chisel:6.7.0",
  )
  // Chisel 的编译器插件（相当于 sbt 的 addCompilerPlugin）
  def scalacPluginIvyDeps = Agg(
    ivy"org.chipsalliance:::chisel-plugin:6.7.0",
  )
  def scalacOptions = Seq("-Ymacro-annotations")

  // 测试子模块（相当于 sbt 的 test 作用域）
  object test extends ScalaTests with TestModule.ScalaTest {
    def ivyDeps = Agg(
      ivy"edu.berkeley.cs::chiseltest:6.0.0",
    )
  }
}

    :: 和 ::: 的区别——别写错

    Mill 的依赖写法里，冒号数量有讲究，对应 sbt 里的 %% 和 cross CrossVersion.full：

    • ivy"组织::库名:版本"（两个冒号）：库要按 Scala 大版本交叉编译，等价于 sbt 的 %%。Chisel 本体、chiseltest 用它。
    • ivy"组织:::库名:版本"（三个冒号）：按 Scala 完整版本交叉，等价于 sbt 的 cross CrossVersion.full。编译器插件 chisel-plugin 必须用三个冒号，写成两个会报找不到依赖。

    sbt ↔ Mill 命令对照¶

    你在前面 sbt 部分学的操作，换成 Mill 是这样：

    你想做的事 sbt Mill
    只编译、查语法错误 compile mill mycpu.compile
    运行主程序生成 Verilog runMain AdderMain mill mycpu.runMain AdderMain
    跑所有测试 test mill mycpu.test
    保存即自动重跑（监视模式） ~test mill -w mycpu.test
    进交互式、少等 JVM 进 sbt shell 加 --bsp 或用 ./mill 常驻，多数时候单命令已经够快

    mycpu 就是 build.mill 里 object mycpu 的名字——Mill 的命令格式是 mill 模块名.任务名。

    本讲义后续命令怎么翻译

    后面几节（尤其"仿真与测试"）里出现的 sbt test、sbt "runMain Xxx"，如果你用 Mill，一律按上表换成 mill 模块名.test、mill 模块名.runMain Xxx 即可，其余 Chisel/测试代码一个字都不用改——构建工具只管"怎么编译运行"，不影响你写的电路本身。

    常见报错自查¶

    初次搭环境难免踩坑，这里列几个最常见的：

    现象 可能原因 解决
    sbt: command not found / mill: command not found 构建工具没装好或没进 PATH 重装 Coursier，重启终端；Mill 项目试试仓库自带的 ./mill 脚本
    卡在 Resolving ... / downloading 很久 在下载依赖，网络慢 耐心等；国内配镜像源（见附录）
    not found: value chisel3 / object chisel3 is not a member 配置文件里没正确引入 Chisel，或没加编译器插件 sbt 查 libraryDependencies + addCompilerPlugin；Mill 查 ivyDeps + scalacPluginIvyDeps（插件记得用三个冒号）
    java.lang.UnsupportedClassVersionError JDK 版本太低 装 JDK 17 或 21
    生成 Verilog 时报 firtool not found firtool 没下载成功 检查网络；或按 Chisel 文档手动安装 firtool

    编译错误 ≠ 环境问题

    环境跑通之后，你写 Chisel 时仍会遇到大量编译错误——比如位宽不匹配、类型不对、=== 写成 ==。这些不是环境坏了，而是 Chisel 编译器在帮你抓 bug。这恰恰是 Chisel 相对 Verilog 的一大优势：很多在 Verilog 里要仿真才暴露的错误，Chisel 在编译期就拦住了。看到红色报错别慌，仔细读它指向的行号和信息。

    附录：国内镜像加速（可选）¶

    国内同学如果下载依赖极慢，可以给 sbt 配置国内镜像。新建（或编辑）~/.sbt/repositories 文件（Windows 在 C:\Users\你的用户名\.sbt\repositories），填入：

    [repositories]
  local
  huaweicloud-maven: https://repo.huaweicloud.com/repository/maven/
  maven-central: https://repo1.maven.org/maven2/
  sbt-plugin-repo: https://repo.scala-sbt.org/scalasbt/sbt-plugin-releases, [organization]/[module]/(scala_[scalaVersion]/)(sbt_[sbtVersion]/)[revision]/[type]s/[artifact](-[classifier]).[ext]

    配好后依赖下载会快很多。

    用 Mill 的同学

    上面那个 ~/.sbt/repositories 是 sbt 专用的。Mill 底层走的是 Coursier，镜像要配在 Coursier 这边——新建 ~/.config/coursier/mirror.properties（Windows 在 C:\Users\你的用户名\AppData\Roaming\Coursier\config\mirror.properties）：

    central.from=https://repo1.maven.org/maven2
central.to=https://repo.huaweicloud.com/repository/maven

    这样 Mill/Coursier 拉依赖也会走国内镜像。

    环境搭好、第一个模块也跑通了，接下来我们正式进入 Chisel 的语法。学习过程中，随时可以回到你的项目里改一改、sbt "runMain XxxMain"（或 mill mycpu.runMain XxxMain）看看生成的 Verilog——动手实验永远是学硬件描述语言最快的方式。
