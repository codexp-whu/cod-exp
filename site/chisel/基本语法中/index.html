    基本语法中

    Tip

    在这一节中，我们将要介绍如何在Chisel中描述组合逻辑和时序逻辑的硬件行为。

    组合逻辑¶

    有了信号声明的基础，现在来看如何用Chisel描述硬件的行为。

    先谈更为简单的组合逻辑。它没有时钟参与，输出完全由当前输入决定，等价于 Verilog 中的 assign 或 always @(*)。

    算术与比较运算¶

    // 算术运算
val sum  = a + b        // 加法
val diff = a - b        // 减法
val prod = a * b        // 乘法（综合出的硬件较大，CPU 中慎用）
// 除法综合出的硬件非常大，CPU 中通常不用，或用移位替代

// 比较
// 注意等号数量！
val eq   = a === b      // 相等（三个等号！）
val neq  = a =/= b      // 不等
val lt   = a < b        // 小于（UInt 无符号，SInt 有符号）
val gte  = a >= b       // 大于等于

    最易踩的坑：=== vs ==

    Scala 自身的 == 比较的是两个 Scala 对象是不是同一个引用，不会生成硬件比较器。

    描述硬件相等必须用 Chisel 的 ===，不等用 =/=。

    // 错误：a == b 不生成硬件，且比较结果恒为 false
when(a == b) { ... }

// 正确：a === b 生成硬件比较器
when(a === b) { ... }

    如果你发现某个相等判断"不生效"，先数一下等号个数是否正确。

    位运算¶

    val and_out = a & b     // 按位与
val or_out  = a | b     // 按位或
val xor_out = a ^ b     // 按位异或
val not_out = ~a        // 按位取反
val shift_l = a << n    // 左移
val shift_r = a >> n    // 右移：UInt 逻辑右移，SInt 算术右移

    位提取与拼接¶

    从指令中提取 opcode、rs1、rs2、funct3、funct7 等字段，全依赖这些提取与拼接语法：

    • 位提取
    • 位拼接(Cat)
    • 重复填充(Fill)
    // 位提取
val opcode = inst(6, 0)     // 取 inst 的低 7 位 —— Verilog: inst[6:0]
val rd     = inst(11, 7)    // 取 inst 第 11~7 位
val bit5   = inst(5)        // 取单比特

// 拼接：Cat(a, b, c, ...)
val combined = Cat(high, low)        // Verilog: {high, low}
val ext_imm  = Cat(inst(31), inst(30, 25), inst(11, 8), inst(7))

// 重复填充：Fill(n, signal)
val sign_ext = Fill(16, a(15))       // Verilog: {16{a[15]}}，16 位符号扩展
val zero_ext = Cat(0.U(16.W), a)     // 16 位零扩展

    Mux¶

    Verilog 中选择逻辑有三种写法：?: 三目运算符、case 语句、if-else 语句。

    Chisel 用三种Mux一一对应。

    Mux 二选一¶

    val result = Mux(sel, a, b)
// Verilog: assign result = sel ? a : b;

    这是最基础的选择器，嵌套后可以实现多路选择——CPU 中前递（Forwarding）的典型写法：

    val aluA = Mux(forwardSel === Fwd_EX,  exResult,
           Mux(forwardSel === Fwd_MEM, memResult,
           regData))

    MuxLookup 多选一¶

    上面的Mux如果面对较多的选择则写法比较繁琐，可以选择用MuxLookup实现多选一，语法更为简洁。 

    val result = MuxLookup(select, default)(Seq(
    key0 -> value0,
    key1 -> value1,
    key2 -> value2
))
// Verilog: always @(*) case(select) ... endcase
    类似case语句的写法，select是要进行选择的信号，default是没有命中的默认值。

    这在 CPU 开发中常用 ，特别适合写ALU和译码器：

    // ALU 操作：一张表覆盖所有运算
val aluResult = MuxLookup(aluOp, 0.U(32.W))(Seq(
    ALU_ADD  -> (a + b),
    ALU_SUB  -> (a - b),
    ALU_AND  -> (a & b),
    ALU_OR   -> (a | b),
    ALU_SLT  -> Mux(a.asSInt < b.asSInt, 1.U, 0.U),
    ALU_SLL  -> (a << b(4, 0)),
    ALU_SRL  -> (a >> b(4, 0)),
    ALU_SRA  -> (a.asSInt >> b(4, 0)).asUInt // asSInt是将a的类型转为有符号
))

    MuxCase 条件优先级链¶

    与 MuxLookup 不同，MuxCase 的每个分支是一个条件表达式（Bool），按顺序检查，第一个满足的优先，即从前往后优先级依次降低。 

    val result = MuxCase(default, Seq(
    (cond1) -> value1,   // 优先级最高
    (cond2) -> value2,
    (cond3) -> value3    // 优先级最低
))
// Verilog: if (cond1) ... else if (cond2) ... else if (cond3) ... else default

    CPU开发中适合指令识别（多条指令可能共享相同 opcode，需要 funct3/funct7 进一步区分）：

    val instType = MuxCase(INST_ILLEGAL, Seq(
    (opcode === OPC_R  && funct3 === F3_ADD  
                        && funct7 === F7_NORMAL) -> INST_ADD,
    (opcode === OPC_R  && funct3 === F3_ADD  
                        && funct7 === F7_ALT)    -> INST_SUB,
    (opcode === OPC_I  && funct3 === F3_ADDI)    -> INST_ADDI,
    (opcode === OPC_LW)                          -> INST_LW,
    (opcode === OPC_JAL)                         -> INST_JAL
))

    三种 Mux 的选择

    你的需求 用什么 特点
    二选一 Mux 最简单直接
    多选一，基于一个 select 信号的值查表 MuxLookup 类似 Verilog 的 case，所有分支等优先级
    多选一，每个分支有独立条件表达式，有优先级顺序 MuxCase 类似 if-else if 链，前面分支优先

    Mux1H 独热码选择器¶

    前面三种 Mux 的 select 信号都是二进制编码（如 0.U、1.U、2.U 表示"选第 0 / 1 / 2 个"）。

    Mux1H 则用独热码做 select，每一位对应一个候选值，哪一位为 1 就选那个候选值。

    译码器产生独热码¶

    回顾译码器的工作方式。当你用 MuxCase 识别指令类型时，每条指令都会生成一个独立的 Bool 信号：

    // 译码器中对每条指令的判断——以下信号互斥，天然是独热码
val isAdd  = (opcode === OPC_R) && (funct3 === F3_ADD) && (funct7 === F7_NORMAL)
val isSub  = (opcode === OPC_R) && (funct3 === F3_ADD) && (funct7 === F7_ALT)
val isAnd  = (opcode === OPC_R) && (funct3 === F3_AND) && (funct7 === F7_NORMAL)
val isOr   = (opcode === OPC_R) && (funct3 === F3_OR)  && (funct7 === F7_NORMAL)
// 对于任意一条合法指令，这四个信号中最多只有一个为 true

    按常规做法，你会把这些独热码信号使用 MuxLookup查表选择。

    先把它们转回二进制编码（"isAdd→0, isSub→1, isAnd→2, isOr→3"），再查表选择。

    这种做法麻烦很多，信号本来就是独热码，绕一圈转成二进制再解码回来。

    使用Mux1H则可以直接使用独热码进行选择。

    Mux1H 语法¶
    // Mux1H：直接用独热码 isAdd/isSub/isAnd/isOr 选择对应的运算结果
val aluResult = Mux1H(Seq(
    isAdd  -> (a + b),       // isAdd=1  时选中 a+b
    isSub  -> (a - b),       // isSub=1  时选中 a-b
    isAnd  -> (a & b),       // isAnd=1  时选中 a&b
    isOr   -> (a | b)        // isOr=1  时选中 a|b
))

    综合后的电路：isAdd ? (a+b) : isSub ? (a-b) : isAnd ? (a&b) : isOr ? (a|b) : DontCare。

    与 MuxCase 不同，Mux1H 明确告诉综合器"这些条件互斥"，综合器可以放心用更简洁的 LUT 链而非级联优先级 Mux。

    也可以采用另一种写法：

    val sel  = VecInit(isAdd, isSub, isAnd, isOr)    // 4 位独热码向量
val vals = VecInit(a + b, a - b, a & b, a | b)    // 4 个候选值
val result = Mux1H(sel, vals)                      // sel(i)=1 时选 vals(i)
    与 MuxLookup 的对比¶

    以 ALU 为例，两种写法都能工作：

    MuxLookup 写法 Mux1H 写法
    select 信号 先把独热码转为二进制 ALU 操作码编号 直接用译码产生的独热码
    写法 MuxLookup(aluOp, 0.U)(Seq(ALU_ADD -> (a+b), ...)) Mux1H(Seq(isAdd -> (a+b), ...))
    生成硬件 二进制解码器 + Mux 树 LUT 链（更简洁）

    如果你的译码器已经输出了 isAdd / isSub / isAnd / isOr 这类独热码信号，用 Mux1H 最简洁，你不需要再额外定义一个 ALU 操作码常量表来给它们编号。

    选择指南

    你的 select 信号是 用什么
    二进制编码（如 0.U, 1.U, 2.U） MuxLookup
    独热码（译码直接产出的 isAdd / isSub / isLw 等） Mux1H

    时序逻辑¶

    组合逻辑描述的是"数据怎么流动"，但数据本身需要在时钟沿上更新，这就是时序逻辑。

    在 Verilog 中时序逻辑写在 always @(posedge clk) 里，用 <= 赋值；Chisel 中用 Reg + when + := 实现。

    寄存器声明¶

    在基本语法上中我们已经介绍了Reg和RegInit, 并推荐同学们尽可能不使用Reg而应该使用RegInit。

    这一小节中再介绍一个新的寄存器声明方式：RegNext

    RegNext已经包含了打一拍的语义，表示将某个信号打一拍后的信号。

    // 最常用：带复位值的寄存器
val pc = RegInit("h80000000".U(32.W))      // 复位后 = 0x80000000
pc := nextPC                               // 每个周期更新

// 无复位值的寄存器（慎用，仿真时可能出 X 态）
val temp = Reg(UInt(32.W))

// RegNext：打一拍的简写
val delayed1 = RegNext(io.in)               // 等价于 Reg + RegInit(in, 0.U)
val delayed2 = RegNext(io.in, 0.U)          // 带复位值的打一拍

    RegNext——流水线开发中最常用的原语

    流水线的每一级本质上就是把上一级组合逻辑的结果"打一拍"。 

    val id_pc = RegNext(if_pc)   // 一句话实现
// verilog版本
// reg [31:0] id_pc;
// always @(posedge clk) id_pc <= if_pc;

    when / elsewhen / otherwise¶

    在 Chisel 代码中看到了这几个关键字，就说明是时序逻辑，无需像Verilog中一样再写always @(posedge clk)。 

    when(cond1) {
    reg1 := value1       // 注意是 := 不是 =
    reg2 := value2
} .elsewhen(cond2) {
    reg1 := value3
} .otherwise {
    reg1 := value4
}

    这等价于 Verilog： 

    always @(posedge clk) begin
    if (cond1) begin
        reg1 <= value1;
        reg2 <= value2;
    end else if (cond2) begin
        reg1 <= value3;
    end else begin
        reg1 <= value4;
    end
end

    when 块的"保持"语义

    如果你在 when 块的某个分支中没有对某个寄存器赋值，Chisel 会自动让该寄存器在对应条件下保持原值。但是综合后会在寄存器输入端加一个 Mux，选择新值还是旧值反馈。

    when(en) { reg := newValue }
// en=0 时 reg 保持原值
// 综合结果：reg := Mux(en, newValue, reg)

    如果你希望寄存器在某种条件下清零而不是保持，必须在那个分支中显式赋值 0.U。

    switch / is¶

    Verilog 中还有一种常见模式：case 语句放在 always @(posedge clk) 里，这在状态机中非常普遍。

    Chisel 用 switch / is 来实现这个模式：

    switch(state) {
    is(IDLE) {
        when(start) { state := RUN }
    }
    is(RUN) {
        cnt := cnt + 1.U
        when(cnt === 10.U) { state := DONE }
    }
    is(DONE) {
        when(ack) { state := IDLE }
    }
}

    等价于 Verilog： 

    always @(posedge clk) begin
    case(state)
        IDLE: if (start) state <= RUN;
        RUN:  begin cnt <= cnt + 1; if (cnt == 10) state <= DONE; end
        DONE: if (ack)  state <= IDLE;
    endcase
end

    switch/is vs when/elsewhen：

    when / elsewhen switch / is
    对应 Verilog if-else if 链 case 语句
    最适合 条件表达式互不相同 基于同一个信号的不同取值
    优先级 有（上方的分支优先） 无（所有分支互斥）

    CPU 中的典型场景

    switch/is 最适合多周期状态机，而转发单元的冒险检测需要优先级选择则更适合 when/elsewhen。

    区分 := 和 =¶

    这是 Chisel 初学者最容易混淆的地方。

    = 永远是组合连线；:= 的语义取决于赋值目标和所在位置。

    关键先理解 := 在 when 块外对 Reg 的行为，它和 Wire 完全不同：

    // when 块外的 := 用于 Wire —— 组合连线
val sum = Wire(UInt(32.W))
sum := a + b        // 等价于 Verilog: assign sum = a + b;

// when 块外的 := 用于 Reg —— 时序默认赋值！
val pc = RegInit("h80000000".U(32.W))
pc := pc + 4.U      // 等价于 Verilog: always @(posedge clk) pc <= pc + 4;
//                    每个时钟周期无条件更新！

    "时序默认赋值"的意思是：

    如果没有 when 块来覆盖这个行为，寄存器就按这个表达式无条件更新；如果后面有 when 块对同一个寄存器赋值，when 块的优先级更高：

    val pc = RegInit("h80000000".U(32.W))
pc := pc + 4.U           // 默认：每个周期 +4

when(stall) {
    pc := pc              // 覆盖：stall 时保持不变（when 内的优先级更高）
}
// 等价于 Verilog:
// always @(posedge clk) begin
//     if (stall)  pc <= pc;
//     else        pc <= pc + 4;
// end

    理解了这一点，下面用一张完整的表格来总结 = 和 := 的区别：

    写法 目标类型 生成什么硬件 Verilog 等价
    a = b Wire 或 IO 组合连线 assign a = b;
    a := b（when 外） Wire 或 IO 组合连线 assign a = b;
    a := b（when 外） Reg 时序默认赋值（每周期无条件更新，可被 when 覆盖） always @(posedge clk) a <= b;
    a := b（when 内） Reg 时序条件赋值（条件满足时才更新） always @(posedge clk) if (...) a <= b;

    关键记忆点

    • = 永远是组合连线，目标只能是 Wire 或 IO，不能是 Reg。
    • := 在 when 外：看目标是什么——Wire/IO 就是组合连线，Reg 就是时序默认赋值。
    • := 在 when 内：目标必须是 Reg，是时序条件赋值，优先级高于 when 外的默认赋值。
    • io.out := expr：IO 的 Output 端口用 := 驱动，等价于组合连线。

    下面是=和:=的代码示例： 

    // 场景 1：Wire 的 := — 组合连线
val aluOut = Wire(UInt(32.W))
aluOut := a + b           // assign aluOut = a + b;

// 场景 2：Reg 默认赋值 — 每周期更新
val cnt = RegInit(0.U(32.W))
cnt := cnt + 1.U          // always @(posedge clk) cnt <= cnt + 1;

// 场景 3：Reg 在 when 内赋值 — 条件更新（优先级高于默认赋值）
when(reset) {
    cnt := 0.U            // reset 时清零，覆盖默认的 +1
}

// 场景 4：错误的用法
val x = Wire(UInt(32.W))
when(cond) {
    x := value            // 编译错误！Wire 不能放在 when 内
}
val y = RegInit(0.U(32.W))
y = y + 1.U               // 编译错误！Reg 不能用 = 赋值

    常见时序模式¶

    在Chisel中，可以快速实现三种常见的时序模式： 

    // 模式 1：带使能的寄存器
val reg = RegInit(0.U(32.W))
when(en) {
    reg := newValue        // en=1 时更新，en=0 时保持
}

// 模式 2：计数器
val cnt = RegInit(0.U(32.W))
cnt := cnt + 1.U           // 每个周期自增（不需要 when）

// 模式 3：条件更新
when(reset) {
    reg := 0.U
} .elsewhen(load) {
    reg := loadData
} .otherwise {
    reg := reg + 1.U
}

    RegEnable¶

    带使能寄存器 RegEnable 是模式 1 的语法糖，一行替代 RegInit + when(en)：

    val reg = RegEnable(nextValue, initValue, en)
// 等价于：
// val reg = RegInit(initValue)
// when(en) { reg := nextValue }

    流水线 CPU 中，PC 在 stall 时需要保持不变。RegEnable 很自然地表达这个语义：

    val pc = RegEnable(nextPC, "h80000000".U(32.W), !stall)
// stall=0 时正常更新为 nextPC，stall=1 时保持

    对比手写 when 版本： 

    val pc = RegInit("h80000000".U(32.W))
when(!stall) {
    pc := nextPC
}

    两种写法生成完全相同的硬件，RegEnable 更为简洁。
