    基本语法下

    Tip

    这一讲将要介绍Chisel中许多能够实现敏捷开发的语法，更加抽象，但也能够极大地提升开发效率。

    Bundle¶

    回忆你写 Verilog 单周期 CPU 时的经历：

    IF 级的 pc 和 inst 要传到 ID 级，你声明了两根 wire；ID 级的十几个控制信号要传到 EX 级，你声明了十几根 wire，然后在顶层模块中逐根连线…… 十分痛苦，如果遇到代码错误则更加糟心，可能需要耗费数小时来进行debug。

    Bundle 就是为了解决这个问题而生的。

    Bundle 是什么¶

    Bundle 本质上就是一个信号的集合体——你可以把需要一起传递的信号打包成一个"包裹"，以后只需要操作这个包裹，而不需要逐根操作每一根信号。

    并且可以在CPU多个模块内复用同一个Bundle，极大地减少了重复代码。

    下面是一个IF阶段传递Bundle到ID阶段的示例： 

    // 定义：将 IF——ID 需要传递的信号打包
class IF2ID extends Bundle {
    val pc   = UInt(32.W)
    val inst = UInt(32.W)
}

// 使用
val if2id_wire = Wire(new IF2ID)                    // 组合连线
val if2id_reg  = RegInit(0.U.asTypeOf(new IF2ID))   // 流水线寄存器

// 填充单个字段
if2id_wire.pc   := pc
if2id_wire.inst := inst

// 整包传递，一行解决
if2id_reg := if2id_wire    // 一句话替代逐字段赋值，无需每个信号分别连接

    asTypeOf¶

    前面已经介绍过asTypeOf，它可以将Bundle中的所有字段清零，流水线CPU开发中插入NOP气泡将会用到。

    // 将 Bundle 中所有字段清零（插入 NOP 气泡）
val bubble = 0.U.asTypeOf(new ID2EX)  // 所有控制信号 = 0，等效于 NOP
id2ex_reg := bubble

    这比 Verilog 中逐信号清零安全得多——不会遗漏任何一个控制位。

    asTypeOf优先级

    如果asTypeOf语句后续还有对Bundle内字段赋值的语句，则会对相应字段进行赋值，并不会保持清零状态。

    Bundle 的嵌套¶

    当一个 Bundle 包含几十个信号时，把所有字段平铺在一个类里会变得难以维护。更严重的是，有些信号组（比如译码产生的控制信号组）会在多个不同的 Bundle 中反复出现——ID2EX 里有一份，EX2MEM 里有一份，MEM2WB 里又有一份。如果在每个 Bundle 中都逐一声明这些字段，一旦需要新增一个控制信号，你需要在多处 Bundle 中分别添加——这与 Chisel 消除重复代码的初衷背道而驰。

    Bundle 的嵌套正是为了解决这个问题：你可以将一个 Bundle 作为另一个 Bundle 的字段，形成层次化的信号结构。

    基本语法¶

    // 定义可复用的子 Bundle
class ControlSignals extends Bundle {
    val regWrite = Bool()
    val memRead  = Bool()
    val memWrite = Bool()
    val aluOp    = UInt(4.W)
    val memExt   = UInt(3.W)
}

class DataPathSignals extends Bundle {
    val pc      = UInt(32.W)
    val rs1Data = UInt(32.W)
    val rs2Data = UInt(32.W)
    val imm     = UInt(32.W)
    val rd      = UInt(5.W)
}

// 嵌套使用：将子 Bundle 作为字段
class ID2EX extends Bundle {
    val ctrl = new ControlSignals    // 嵌套子 Bundle——控制信号组
    val data = new DataPathSignals   // 嵌套子 Bundle——数据通路信号组
    val rs1  = UInt(5.W)             // 普通字段仍然可以共存
    val rs2  = UInt(5.W)
}

    访问嵌套字段¶

    嵌套 Bundle 的字段访问和普通 Bundle 一样，用 . 逐级访问：

    // 填充嵌套字段
id2ex_wire.ctrl.regWrite := true.B       // 两级访问：ctrl 内部 —— regWrite
id2ex_wire.ctrl.aluOp    := ALU_ADD
id2ex_wire.data.pc       := if2id_reg.pc
id2ex_wire.data.imm      := immResult

// 整包传递——嵌套 Bundle 同样支持！
id2ex_reg := id2ex_wire     // 所有嵌套字段一次性更新

// 清零同样适用
val bubble = 0.U.asTypeOf(new ID2EX)    // 嵌套字段也会被全部清零

    嵌套在 CPU 开发中的核心优势¶

    优势一：子 Bundle 跨模块复用，消除重复定义。

    译码器输出的控制信号组，在 ID2EX、EX2MEM、MEM2WB 中都要携带。传统做法是在每个 Bundle 中重复声明，嵌套则只需定义一次 ControlSignals，各处引用：

    // 译码器模块——直接用 ControlSignals 作为输出端口
class Decoder extends Module {
    val io = IO(new Bundle {
        val inst = Input(UInt(32.W))
        val ctrl = Output(new ControlSignals)   // 一个端口输出整组控制信号
    })
    io.ctrl.regWrite := ...  // 译码逻辑
    io.ctrl.aluOp    := ...
}

// 各流水线寄存器 Bundle——复用同一个 ControlSignals
class EX2MEM extends Bundle {
    val ctrl      = new ControlSignals   // 复用
    val aluResult = UInt(32.W)
    // ...
}

    优势二：新增控制信号，一处修改全局生效。

    假设你需要为 CSR（状态控制寄存器） 指令新增一个 csrWrite 控制信号。使用嵌套 Bundle 时，你只需在 ControlSignals 中添加一行：

    class ControlSignals extends Bundle {
    val regWrite = Bool()
    val memRead  = Bool()
    val memWrite = Bool()
    val csrWrite = Bool()          // 新增这一行，而非在 N 个 Bundle 中各加一行
    val aluOp    = UInt(4.W)
    val memExt   = UInt(3.W)
}

    所有引用了 ControlSignals 的地方——译码器输出、ID2EX、EX2MEM、MEM2WB——全部自动携带 csrWrite 字段，无需逐个修改。编译器会检查每个使用点是否遗漏了赋值，杜绝"某级流水线忘记传递新信号"的隐患。

    优势三：整组传递，连线从几十行缩减为一行。

    // 译码器输出直接赋给流水线寄存器——整组控制信号一次传递
id2ex_wire.ctrl := decoder.io.ctrl    // 一行替代 N 行逐字段赋值

// 即使后续在 ControlSignals 中新增字段，这一行也不需要修改

    什么时候应该嵌套

    如果你发现同一个字段（比如 regWrite、aluOp）出现在三个以上的 Bundle 中，或者一个 Bundle 的字段超过 15 个且可以按功能分组，就可以采用Bundle嵌套， 让单个Bundle的字段更少，逻辑更清晰。

    控制信号组、数据通路信号组是 CPU 中最典型的两个可嵌套子 Bundle。

    Bundle 的优势¶

    在五级流水线 CPU 中，每级之间有 10~30+ 条信号需要传递。假设你新增一个控制信号，两种工作量的对比：

    Verilog Chisel + Bundle
    修改位置 声明 wire、连线、寄存器赋值 × 4 级 Bundle 定义中加 1 行
    遗漏风险 高——每一处都可能忘记 零——编译器帮你检查所有字段

    使用Bundle可以极大地解放繁琐的连线工作，提升开发效率并利于后期修改维护。

    在流水线CPU的开发过程中，应该善用Bundle，相信它能给你带来软件开发般的畅快体验。

    Vec¶

    如果说 Bundle 是"按名字"访问的信号集合，Vec 就是"按下标"访问的信号集合。

    VecInit¶

    VecInit与C/C++中的数组相似，可以使用下标访问内部的信号。 

    // 译码 ROM：存一张常数表
val immSizeTable = VecInit(Seq(
    IMM_I.U, IMM_S.U, IMM_B.U, IMM_U.U, IMM_J.U
))
val immSize = immSizeTable(immType)  // 根据 immType 下标查表
// 综合出来是一个 Mux 树

    寄存器堆¶

    使用RegInit(VecInit(...))语法可以快速实现一个寄存器堆。 

    // 32 个 32 位寄存器，全部初始化为 0
val rf = RegInit(VecInit(Seq.fill(32)(0.U(32.W))))

// 读：组合逻辑，rf(rs1) 自动综合为 Mux 树
val rdata1 = Mux(rs1 === 0.U, 0.U, rf(rs1))   // x0 硬连线为 0
val rdata2 = Mux(rs2 === 0.U, 0.U, rf(rs2))

// 写：时序逻辑
when(wen && rd =/= 0.U) {
    rf(rd) := wdata
}

    对比 Verilog：Chisel 中 rf(rs1) 这简简单单的一行，自动综合为一个 32 选 1 的多路选择器——你不需要手写 always @(*) case(rs1) ... endcase。

    VecInit vs Vec¶

    写法 生成什么 用途
    VecInit(Seq(...)) 组合 Mux 树 常数查找表、译码 ROM
    RegInit(VecInit(Seq(...))) 寄存器阵列 寄存器堆
    Wire(Vec(n, T)) 一组 Wire 级间信号组（不如 Bundle 常用）

    log2Ceil 与 log2Floor¶

    在 Verilog 中，寄存器堆有 32 个寄存器 → 地址位宽写死为 [4:0]。但如果寄存器数量是参数化的（比如 Config.REG_COUNT），你不想手算 log2(32) = 5。log2Ceil 和 log2Floor 在编译期帮你完成这个计算。

    import chisel3.util.log2Ceil
import chisel3.util.log2Floor

val addrWidth = log2Ceil(32)    // 5 —— 表示 0~31 至少需要 5 bit
val addrWidth = log2Ceil(31)    // 还是 5 —— 31 也需要 5 bit（ceil 向上取整）

log2Floor(32)                   // 5
log2Floor(31)                   // 4 —— floor 向下取整

    CPU 开发中的典型用法：

    object Config {
    val REG_COUNT = 32
}

val rf = RegInit(VecInit(Seq.fill(Config.REG_COUNT)(0.U(32.W))))

// 寄存器地址位宽自动根据 REG_COUNT 计算——改为 64 个寄存器时位宽自动变为 6
val rs1 = Input(UInt(log2Ceil(Config.REG_COUNT).W))   // 等价于 UInt(5.W)
    函数 含义 REG_COUNT=32 结果 REG_COUNT=31 结果
    log2Ceil(n) 表示 0~n-1 范围最少需要多少 bit 5 5
    log2Floor(n) n 的 log2 向下取整 5 4

    Tip

    log2Ceil 和 log2Floor 是 Scala 函数（不是硬件！），在电路生成阶段执行，结果是编译期常量。它们的输入必须是 Scala Int，不能是 Chisel 硬件类型。

    Module¶

    有了数据类型、信号声明、组合/时序逻辑、Bundle 和 Vec，接下来你就可以开始组装CPU的各个模块了。Chisel 的模块概念与 Verilog 的 module 完全对应。

    模块的定义与端口¶

    io是模块的固定命名，对应Verilog中的输入输出信号集合。不仅可以在模块定义处具体定义Bundle，也可以复用已有Bundle。 

    class Alu extends Module {
    val io = IO(new Bundle {       // io 是固定命名，IO(...) 包裹端口 Bundle
        val a    = Input(UInt(32.W))
        val b    = Input(UInt(32.W))
        val op   = Input(UInt(4.W))
        val out  = Output(UInt(32.W))
        val zero = Output(Bool())
    })

    // 内部逻辑通过 io.xxx 访问端口
    io.out  := MuxLookup(io.op, 0.U(32.W))(Seq(...))
    io.zero := io.out === 0.U
}

    Verilog 对比： 

    module Alu (
    input  [31:0] a, b,
    input  [3:0]  op,
    output [31:0] out,
    output        zero
);
    assign out = ...;
    assign zero = (out == 0);
endmodule

    关键区别：Chisel 的端口 Bundle 可以整体传递（传进子模块、存进流水线寄存器）；Verilog 的端口不行。

    模块的实例化¶

    // 实例化——和 Verilog 一样直接 new
val alu    = Module(new Alu)       // Module(...) 包裹
val decoder = Module(new Decoder)

// 连线
alu.io.a   := rs1Data
alu.io.b   := rs2Data
alu.io.op  := aluOp
val result = alu.io.out            // 读取输出

    批量实例化：Seq.fill / Seq.tabulate

    当你需要实例化多个同类型模块时（比如多个相同的ALU），Scala 的 Seq 可以帮你省去逐一声明的麻烦：

    // 实例化 4 个完全相同的加法器
val adders = Seq.fill(4)(Module(new Adder))

// 连线时按索引访问
for (i <- 0 until 4) {
    adders(i).io.a := inputs(i).a
    adders(i).io.b := inputs(i).b
}

// Seq.tabulate：在创建时就拿到索引
val adders = Seq.tabulate(4)(i => Module(new Adder))

    Seq.fill vs Seq.tabulate

    Seq.fill(n)(expr) 重复 expr n 次；Seq.tabulate(n)(i => expr) 在表达式中可以使用索引 i。

    Mem 与 SyncReadMem¶

    Chisel 提供了两种存储器抽象，区别在于读时序，将会直接影响你的流水线设计。

    Mem¶

    Mem 的读是组合逻辑，等价于 Verilog 中用 reg [31:0] mem [0:4095] + assign rdata = mem[addr] 的写法。

    对于刚接触 Chisel 的同学来说，Mem 的行为与你在单周期 CPU 中用 Verilog 写的存储器最接近。

    val mem = Mem(4096, UInt(32.W))           // 4096 × 32-bit

// 读：组合逻辑——地址给出去，当周期数据就回来
val rdata = mem.read(addr)                
// 等价于 Verilog: assign rdata = mem[addr];

// 写：同步写（下一拍才真正写入）
when(io.wen) {
    mem.write(io.addr, io.wdata)
}

    SyncReadMem¶

    SyncReadMem 是同步读（映射到 FPGA 的 Block RAM）：读地址给出去之后，数据在下一个时钟周期才出现在输出端。

    这是硬件 SRAM 的真实行为,因为Block RAM 的输出端自带一级寄存器。

    val imem = SyncReadMem(4096, UInt(32.W))    // 4096 × 32-bit
val inst = imem.read(addr >> 2)              // 同步读：数据下一拍才出来

    SyncReadMem 与 Verilog reg [31:0] mem [0:4095] 的区别

    很多同学在单周期 CPU 中习惯的 Verilog 写法是组合读（assign rdata = mem[addr]）。如果直接把同样的思路套到 SyncReadMem 上，你会发现数据"晚了一拍"。所以时序不同，CPU的设计也有区别。

    如何选择？¶

    Mem SyncReadMem
    读时序 组合读（当周期得到数据） 同步读（下一拍得到数据）
    综合结果 分布式 RAM 或寄存器阵列 FPGA Block RAM（BRAM）
    适用场景 规模较小的存储（寄存器堆、小查找表） 规模较大的存储（指令/数据存储器）
    与 Verilog 对比 等价于 reg [...] mem [...]; assign rdata = mem[addr]; 等价于 Block RAM IP 核，输出自带寄存器

    流水线 CPU 中的选择建议

    在五级流水线中，IMem 和 DMem 通常用 SyncReadMem（面积更优、时序更好），流水线的自然节奏已经覆盖了那一拍同步读延迟。寄存器堆本身规模小、需要组合读（译码阶段当周期拿到寄存器值），用 VecInit + RegInit 实现。

    读写冲突¶

    同一个周期对同一地址既读又写（前一条指令写，后一条指令读），Mem 和 SyncReadMem 的默认行为都是读旧值（read-first / read-before-write）。

    加载初始内容¶

    Mem 和 SyncReadMem 声明的存储器初始值全为零。CPU 需要把程序加载到 IMem 中，用 loadMemoryFromFile：

    val imem = SyncReadMem(4096, UInt(32.W))
loadMemoryFromFile(imem, "program.hex")   // 仿真时从 hex 文件加载程序

    loadMemoryFromFile 只在仿真时有效

    这个函数仅在仿真环境中可用，综合时会被忽略。实际 FPGA 上板时，你需要用 Vivado 的 IP 核（Block Memory Generator）通过 COE 文件或其他方式初始化 BRAM。

    调试手段¶

    写 CPU 你需要知道怎么在仿真中观察电路的行为。Chisel 提供了 printf 和 assert，让你在仿真时就能定位问题，而不必对着波形图瞎猜。

    printf：仿真中的"串口打印"¶

    // 打印 PC 和指令（每条指令取指时触发）
printf(cf"pc = $pc, inst = ${io.inst}\n")     // cf 字符串插值，自动处理类型格式

// 在 when 块中条件打印
when(io.regWrite && io.rd =/= 0.U) {
    printf(cf"write reg[${io.rd}] = ${io.wdata}\n")
}

    printf 只在仿真时有效，综合时自动忽略——所以你可以放心地在任何地方加打印，不会影响最终电路的资源消耗和时序。

    cf 插值器

    cf"..." 是 Chisel 提供的字符串插值器，$variable 会自动根据变量类型选择合适的格式（%d for UInt/SInt, %x for Bits）。使用 cf 而非手动 printf("%d", ...) 可以减少格式字符串错误。

    assert：仿真中的硬件断点¶

    // 断言 PC 必须 4 字节对齐
assert(pc(1, 0) === 0.U, "PC must be 4-byte aligned!")

// 断言寄存器堆写使能时 rd 不为 0（RISC-V 规范要求 x0 硬连线为 0）
when(io.regWrite) {
    assert(io.rd =/= 0.U, "Cannot write to x0!")
}

    assert 同样只在仿真时生效。当条件为 false 时，仿真器打印错误信息并停止——相当于帮你设了一个"一旦违反规范就立即报警"的硬件断点。

    调试流水线 CPU 的推荐做法

    1. 在每级流水线寄存器的输入处加 printf，打印该级的关键信号（pc、inst、控制信号）
    2. 在写回阶段加 printf，确认寄存器堆写入的值和地址正确
    3. 在转发条件、stall/flush 条件处加 assert，确保冒险检测逻辑没有误判
    4. 仿真跑出错误后，首先看打印日志中哪一级的信号开始不对劲

    至此，你已经学完了 Chisel 的常用语法。从数据类型到组合/时序逻辑，从 Bundle/Vec 到 Module/Mem，再到调试手段——这些知识已经足够支撑你写出一颗完整的五级流水线 CPU。

    接下来，CPU 开发场景 将把这些零散的语法点串联起来，按 PC、取指、译码、ALU、访存、流水线寄存器、转发、冒险控制的顺序，手把手带你搭建流水线 CPU 的骨架。建议将那一节作为速查手册，边写边翻。
